# Скачивание файлов

[Документация](README.md) · [Интернет](web.md) · [Разрешения](permissions.md)

В Build попросите агента найти и сохранить файл либо укажите публичную HTTP(S)-ссылку. Встроенный инструмент ядра `web_download` скачивает файл напрямую, без команды оболочки. JavaScript со страницы и скачанный файл не выполняются.

Скачивание сохраняет исходные байты сервера. Имя `.txt` не превращает HTML в текст статьи. Инструмент не записывает пересказ агента и не принимает `data:` или локальные URL; обычный `write_file` записывает созданный текст внутри проекта. Для экспорта собственного текста прямо на рабочий стол отдельного инструмента пока нет.

```text
Найди официальный логотип Python. Помощнику поручи поиск,
а сам сохрани PNG на мой рабочий стол и проверь файл.
```

## Куда сохраняется файл

Для рабочего стола и загрузок агент указывает `directory: "desktop"` или `"downloads"` и имя файла. Путь определяет ChiselCode по настройкам ОС: Windows учитывает перенаправление известных папок, включая OneDrive; macOS использует пользовательские системные каталоги; Linux читает XDG `user-dirs.dirs`, включая локализованные пути. При отсутствии настройки XDG используются стандартные `~/Desktop` и `~/Downloads`. Отключённый или недоступный системный каталог даёт ошибку, а не подменяется папкой проекта.

Внутри проекта можно указать `path`; действуют прежние ограничения проекта и игнорируемых путей. Родительские каталоги создаются только после разрешения записи. Результат содержит фактический абсолютный путь, размер в байтах, MIME-тип ответа и SHA-256 сохранённого файла. Двоичные данные в контекст модели не поступают.

## Разрешения и перезапись

Для скачивания требуются одновременно разрешённый Web Fetch и разрешение на запись. Allow для чтения публичных страниц сам по себе не разрешает сохранить файл. В Plan и у readonly-помощника запись недоступна. Coding-помощник может скачать файл внутрь собственной рабочей копии; сохранение на рабочий стол выполняет основной агент.

Существующий файл по умолчанию не меняется. Агент должен выбрать другое имя либо явно запросить `overwrite: true`. При перезаписи ядро проверяет, что назначение не изменилось после подготовки: конкурирующая запись останавливает операцию и сохраняет чужие изменения.

Пока идёт сеть, данные поступают в закрытый временный каталог ядра, без изменения файлов проекта. Затем ядро берёт блокировку назначения, переносит данные в файл рядом с ним и проверяет размер и SHA-256 перед атомарной публикацией. Это работает и при разных дисках хранилища и назначения. Временные файлы удаляются при отказе и отмене. Обычные shell-команды сохраняют прежние блокировки файлов и Git; скачать файл не означает обойти работающий процесс, который занимает назначение.

## Ход операции и ошибки

Чат показывает полученные байты и процент, когда сервер сообщает общий размер. Ctrl+C отменяет запрос и незавершённое сохранение. По умолчанию скачивание ограничено 128 МиБ и двумя минутами на все соединения, повторы и сохранение. Вызов может дополнительно уменьшить `maxBytes`; глобальные настройки — `web.limits.maxDownloadBytes` и `downloadTimeoutMs`.

Для HTTP 429 и временных сетевых/серверных ошибок допускаются максимум три попытки в общей временной границе. `Retry-After` соблюдается; если сервер требует ждать дольше оставшегося времени, агент получает причину и должен выбрать другой источник. Обрыв начинает следующую попытку с чистого временного файла. Постоянный отказ, ошибка записи, превышение размера и небезопасный адрес не запускают бесконечные повторы.

Каждый redirect проходит прежние проверки DNS, публичных адресов, TLS и доменных запретов. Локальные адреса, metadata, credentials в URL и нестандартные порты не разрешаются скачиванием. Cookies, login и произвольные HTTP-заголовки инструмент не принимает. При атомарном создании без перезаписи нужна файловая система с поддержкой hard links; неподдерживаемая файловая система вернёт ошибку без замены назначения.

Возможность доступна начиная с CLI [0.6.31](https://github.com/TheAsrada/ChiselCode/releases/tag/v0.6.31); в 0.6.30 её нет.
