[Материалы для участников](../README.md#планы) · [Действующие клавиши](../../keybindings.md) · [Порядок проверок](../testing.md)

Статус: план от 2 ноября 2026 года. Изменения интерфейса и сочетаний ещё не реализованы.

Исследованы исходники [TheAsrada/ChiselCode, main, f08acd9](https://github.com/TheAsrada/ChiselCode/tree/f08acd9a414c3d9a6f9e301f88af68f82ea1adb0), версия 0.6.47, обработчики ввода, компоненты окон, пользовательская справка и существующие тестовые сценарии. Это анализ кода, без запуска OpenTUI и без измерений частоты использования сочетаний. «Лишние» ниже означает дублирующие обычную навигацию или отдельное именованное действие; это проектное решение, а не вывод из телеметрии.

## Цель и границы

Меню должно объяснять доступные действия названиями, состоянием и видимым фокусом. Для работы с ним достаточно стрелок, Tab/Shift+Tab, Enter/Space и Esc; длинные списки и текст сохраняют Home/End и PgUp/PgDn. Специальные сочетания не должны быть единственным способом обновить каталог, открыть инструкции, сменить подраздел или управлять задачей.

Согласно [AGENTS.md](../../../AGENTS.md), сохранить горячие клавиши на главной, не возвращать `/help`, работать в `main`, писать интерфейс и документацию по-русски. Главная и чат сохраняют существующие переходы и подсказки: Shift+Tab, F4, Ctrl+S, Ctrl+,, Ctrl+T, Ctrl+B, F6/F7/F8/F9, управление вкладками, историей ввода, diff и буфером. Их фактические ограничения по фокусу и открытому окну также сохраняются. В этой задаче не сокращать глобальный набор и не возвращать удалённую служебную ленту или кнопки под вводом.

Область работы — встроенные меню, Settings и окна CLI. Не менять slash-команды, публичный SDK, пользовательские сочетания расширений, runtime операций, разрешения, форматы данных или версии зависимостей. ChiselCodeDesktop вне задачи. Новый план [меню LSP](lsp-menu.md) ещё не реализован: согласовать навигацию с ним, но не включать его runtime/config-переделку в эту работу.

Для реализации использовать skill [opentui](https://github.com/msmps/opentui-skill), references React, keyboard, keymap, layout и testing. При подготовке этого плана прочитаны React, keyboard, keymap и testing. В проекте закреплены `@opentui/core` / `@opentui/react` 0.5.12. Отдельного `@opentui/keymap` в зависимостях нет; его установка и переписывание всей маршрутизации для этой задачи не требуются. API из справки сверять с установленными типами.

Основные причины — локальные соглашения каждого окна, разный смысл Tab и Ctrl+R, дублирование сочетаний в нескольких строках, скрытие действий при уменьшении окна. Само наличие одинакового сочетания в разных изолированных окнах не доказывает конфликт; реальные конфликты проверять сценарием ввода, а не поиском по строкам.

## Целевое поведение

### Общая навигация

1. Tab/Shift+Tab обходят видимые доступные области в порядке чтения: подразделы, поиск, список/содержимое, действия. Пустые и недоступные элементы пропускаются. Фокус и выбранная строка имеют разные видимые состояния.
2. В полосе подразделов ←/→ меняют выбранный подраздел; в списке ↑/↓ выбирают строку; в действиях стрелки выбирают кнопку. Enter выполняет выбранное действие. Space работает для кнопок и переключателей, но в поле остаётся пробелом. Enter в поиске может открыть выбранный результат, как сейчас, если это явно показано.
3. Esc сначала отменяет редактирование или выходит из вложенного просмотра, затем возвращает на предыдущий уровень. Закрытие формы с изменениями сохраняет выбор «Остаться / Сохранить / Отбросить». Не вводить единый принудительный close поверх действующей отмены операций.
4. Ctrl+F оставить для поиска в Settings; `/` оставить как обычный вход в поиск поддерживающих его списков, только вне редактируемого поля. Поиск также доступен через Tab. Ctrl+S оставить единственным специальным сочетанием сохранения форм. Не добавлять новые F-клавиши и буквенные мнемоники взамен удалённых.
5. Поля сохраняют native редактирование, выделение, undo/redo, ввод русских букв и bracketed paste. Удалённое сочетание не должно вызывать прежнее действие или проваливаться к чату; возможное стандартное действие редактора определяется самим полем.
6. F6/F7 в открытых соответствующих представлениях могут по-прежнему скрывать их как парные существующему глобальному переходу. Ctrl+C сохраняет текущую контекстную семантику: остановка основной работы из чата, локальная отмена там, где она предусмотрена, и защита от групповой остановки в просмотрах.

### Решение по локальным сочетаниям

Удалять обработчик и его подсказки в одном изменении, только после реализации и проверки маршрута в правой колонке. Таблица — целевое решение, а не описание действующей версии.

| Где | Что убрать | Чем пользоваться после изменения |
| --- | --- | --- |
| Settings и встроенные формы | F2 как дубль Ctrl+S; локальный Ctrl+T, M; Ctrl+R в подключениях | «Сохранить» и Ctrl+S текущей формы; «Внешний вид» в списке разделов, переключатель «Анимации», «Проверить подключение» |
| Выбор модели | Ctrl+N, Ctrl+R | «Ввести ID», «Обновить каталог», «Настройки» в обходе действий; «Модели / Профили» в доступной полосе |
| Навыки, standalone и Settings | Ctrl+O/N/E/R, Alt+1/2 | «Инструкции», «Создать», «Изменить», «Обновить каталог»; «Библиотека / Закрепление» через полосу подразделов. Ограничения встроенных и agent-only навыков сохраняются |
| История | F3, Ctrl+P, Ctrl+R, Ctrl+D | «Просмотр», «Переименовать», «Удалить…», «Продолжить» в действиях выбранной строки; все доступны на малой высоте |
| MCP | Ctrl+R; F2 во встроенном варианте | «Проверить подключение» и «Остановить проверку», сохранение проверенного результата через действие или Ctrl+S; обычная отмена сохраняется |
| Рабочие копии | N, R | «Создать копию», «Обновить список», «Обновить diff»; недоступные изменения объясняют ограничение Plan/busy |
| Помощники | J/K, S, C | Стрелки; «Остановить» и «Контекст» через обычный обход действий |
| Фоновые задачи | J/K, S/F/A, D/H/B | Стрелки; «Фильтр», «Остановить», «Остановить все…», «Удалить историю…», «Восстановить очистку», «В фон» в основном или дополнительном списке действий |
| Разделы боковой панели | 1/2/3, [ / ], Ctrl+←/→ | Tab на полосу «Меню / Контекст / Агенты», ←/→, затем Tab в содержимое. Ctrl+B и F7 сохраняются |
| Выбор разрешений | Локальный F4 как альтернативу стрелкам | ↑/↓ и Enter в окне выбора; F4 на главной и в свободном composer продолжает переключать режим |

Существующие подтверждения Y/Н, N/Т/Esc, сетевое A/Ф и остановка помощника в запросе разрешения остаются: это отдельный сценарий подтверждения. Удаление истории и массовая остановка сохраняют собственное подтверждение; Enter, открывший запрос, не может тут же его подтвердить. Отдельное сочетание не заменять автоматическим выполнением по выделению строки.

### Подсказки и размеры

Названия действий — «Инструкции», «Создать», «Переименовать», без `Ctrl+O`, `^R` и подобных префиксов. Внизу одна контекстная строка, например «↑↓ выбор · Tab действия · Enter открыть · Esc назад». В поле редактирования показывать его действие, при несохранённой форме — доступное сохранение; Ctrl+S указывать один раз, без F2. Ошибки и состояние операции важнее справки.

Для ширины и высоты использовать существующие layout helpers и `terminalLine`, но сначала выбирать короткое содержание по приоритету, затем обрезать. Не пытаться поместить прежнюю длинную строку за счёт нечитаемых сокращений. Главная сохраняет свои полезные подсказки.

На 120×40 и 80×24 доступны обычные списки и действия. На 60×15 и 32×10 второстепенные операции можно убрать в именованный список «Действия…», доступный с клавиатуры; порядок основных действий остаётся узнаваемым. При ещё меньшем viewport показывать доступный компактный экран/список, а не оставлять операции только на специальных клавишах. Resize сохраняет запрос, выбор по стабильному ID, черновик и действительный фокус. Если сфокусированное действие исчезло, фокус переходит к доступному соседу и ничего не запускает.

## Порядок реализации

### 1. Зафиксировать доступность и общий контракт фокуса

- Повторно сверить исходники с таблицей, включая подписи/сообщения, `useUiKeyboard`, native key bindings и формы, открываемые из разных точек. Для каждого удаляемого сочетания записать действие, условие доступности и маршрут без мыши на обычном и компактном экране.
- Уточнить контракт между `OpenTuiDialog`, родительскими обработчиками и `EmbeddedSettingsPanel`: Settings владеет внешними областями и сохранением; вложенная панель сообщает внутренние доступные цели. Tab входит в содержимое, обходит его внутренние цели и выходит в следующую область; Shift+Tab проходит обратный путь. Не создавать два независимых обработчика одного Tab.
- При необходимости расширить внутренний контракт [settings-panel.ts](../../../src/ui/settings-panel.ts) и сделать небольшой общий механизм обхода действий рядом с `DialogAction`. Список целей, обработка клавиатуры, disabled и визуальное выделение должны использовать одну модель действий. Не внедрять новый глобальный keymap и не переносить бизнес-операции в UI-helper.
- Зафиксировать критерии: одна клавиша — одно действие исходного владельца; изменение выделения, hover и фокуса не сохраняет форму и не вызывает модель.

### 2. Модели, навыки и история — сначала устранить зависимость от сочетаний

- В моделях добавить доступ к профилям, ручному ID, обновлению и настройкам через общий обход. Ручной ID работает при ошибке или незавершённой загрузке каталога; обновление сохраняет выбранный ID и не принимает поздний ответ другого профиля.
- В навыках сделать одинаковый набор действий в отдельном окне и внутри Settings. Инструкции прокручиваются с клавиатуры; создание/изменение только готовят черновик, не отправляют запрос и не меняют закрепление. На узком экране действия не исчезают вместе с правой колонкой.
- В истории сохранить продолжение, readonly просмотр полного разговора, переименование и подтверждаемое удаление без F3/Ctrl-сочетаний. Не менять проверки root/архива, выбор исходного проекта и сохранность черновика.
- После проверки каждого окна удалить перечисленные обработчики и их подписи; обновить соответствующие пользовательские страницы в этом же этапе.

### 3. Settings и остальные меню

- Убрать F2 во всей цепочке оболочки и вложенных форм, сохранив Ctrl+S только для текущей формы. Проверить ветки `simpleFooter`, tiny/compact и dirty-close: кнопка сохранения должна работать там же, где сочетание. Не сохранять незавершённые соседние формы автоматически.
- Перенести локальные обновления и проверки в именованные действия; отмена MCP-проверки остаётся доступной кнопкой и существующим способом отмены. Сохранение не обходит проверку подключения, trust, permissions или revision.
- Упорядочить действия рабочих копий, помощников и фоновых задач по таблице. «Остановить все…» захватывает прежний набор задач перед подтверждением; смена списка/выделения не перенаправляет действие. Сохранить различие скрытия окна, остановки процесса и удаления истории.
- Добавить фокус полосы разделов боковой панели до удаления цифровых и скобочных альтернатив. Согласовать переходы с деревом помощников, меню, контекстом и собственными действиями; стрелки в дереве продолжают сворачивать ветви.
- Окна сервисов, проектов, расширений, обновления, сообщения команды и побочного ответа проверить на соответствие общим правилам и коротким подсказкам. Не удалять их штатные Enter/Esc/Tab и не менять обработчики SDK расширений. В окне разрешений убрать только локальный дубль F4.

### 4. Очистка подсказок, справка и проверка законченного сценария

- Удалить остаточные упоминания снятых сочетаний из актуального UI, ошибок, placeholder и пользовательских инструкций. Не переписывать исторические CHANGELOG, отчёты прошлых выпусков и результаты проверок под новый интерфейс.
- Провести общий сценарий: главная → меню → модели → навыки → Settings → история → рабочие копии → помощники/фон → назад к исходному черновику. Все переходы выполнить без мыши и удаляемых сочетаний; отдельно проверить мышь и resize.
- Сохранить настоящие кадры OpenTUI и показать владельцу сравнение до/после для моделей, навыков, истории и Settings. Кадры сгенерированного макета не заменяют рендеринг. Если добавляются PNG, получать их из native capture, а не рисовать интерфейс заново.

## Проверки и критерии приёмки

Для текущей правки только плана достаточно `bun run docs:check`, проверки текста, путей к исходникам и маршрута от README. Тесты UI, сборка и native validation здесь не подтверждались и не нужны для публикации плана.

При реализации сначала запускать затронутые файлы из существующих групп; не выполнять всю таблицу после каждого шага:

| Область | Существующие проверки для расширения |
| --- | --- |
| Модели, навыки, история | `tests/unit/opentui-models.test.tsx`, `opentui-skills.test.tsx`, `opentui-sessions.test.tsx`; после изменения production-маршрута истории — `tests/integration/session-resume.test.ts` |
| Settings и встроенные панели | `tests/unit/settings-shell.test.tsx`, `opentui-settings.test.tsx`, `opentui-mcp.test.tsx`; `tests/integration/settings-tools-runtime.test.ts` для standalone/embedded, отмены, форм и черновика |
| Фокус панели, глобальные клавиши, подтверждения | `tests/unit/opentui-sidebar.test.tsx`, `opentui-navigation.test.tsx`, `opentui-permissions.test.tsx`, `opentui-tab-approvals.test.tsx`; `tests/integration/tui-agent-navigation.test.ts` |
| Рабочие копии, помощники, фон | `tests/unit/opentui-worktrees.test.tsx`, `opentui-subagents.test.tsx`, `opentui-background.test.tsx`; при затрагивании production-маршрута — соответствующий существующий integration-fixture |
| Границы расширений и ввода | `tests/unit/opentui-ui-bindings.test.tsx`, `opentui-extension-interaction.test.tsx`, `opentui-clipboard.test.tsx`, `opentui-terminal-compatibility.test.tsx` по фактическому влиянию |

Нужны поведенческие assertions, а не только отсутствие строк с `Ctrl+…`:

- Каждое действие из таблицы выполняется без мыши и специального сочетания; disabled/скрытое действие не получает фокус. На 120×40, 80×24, 60×15, 32×10 можно открыть, выбрать действие и вернуться; resize между режимами не теряет выбор/черновик.
- Буквы, цифры, скобки, пробелы, русская раскладка и многострочная вставка попадают в нужное поле. Снятые сочетания не вызывают старую операцию и не открывают глобальное окно позади текущего. Shift+Tab внутри окна двигает фокус, не меняя Plan/Build.
- Enter/Space выполняет ровно одно действие; удержание клавиши, поздний callback, смена вкладки, новое подтверждение или resize не перенаправляют действие на новую строку/владельца. Проверять фактическую операцию и конечное состояние.
- Ctrl+S в чате по-прежнему открывает навыки; в форме сохраняет только её. Ctrl+C, F4 на главной, F6/F7/F8/F9, вкладки, копирование и вставка сохраняют ранее допустимые контексты. Сетевые и файловые разрешения остаются обязательными.
- Снятие сочетаний не удаляет проверки отмены, atomic storage/revision, архивов, root, конфликтов рабочих копий, ownership процессов и cleanup. Меняется путь к действию, а не его гарантии.

Асинхронные UI-сценарии ожидают готовый ввод, видимый элемент или конечный статус с ограниченным deadline, без фиксированной паузы как доказательства готовности. Переиспользовать native test renderer/fixtures проекта; API новых примеров skill не считать доступным в 0.5.12 без проверки типов.

После законченного изменения исходников: `bun run test:fast`, `bun run typecheck`, `bun run lint`, `bun run build`, `bun run docs:check` и соответствующие точечные UI/integration tests по [порядку проверок](../testing.md). Не добавлять дорогие TUI-fixtures в быстрый профиль и не дублировать полный сценарий в installed/compiled smoke. Native validation требуется перед релизом или при изменении native runtime; для ошибки конкретной ОС запускать затронутые файлы на ней и честно отмечать непроверенные платформы.

Задача реализации завершена, когда локальные обработчики из таблицы удалены, каждое прежнее действие имеет проверенный путь через меню на обычном и компактном экране, глобальные клавиши сохранены, подсказки соответствуют фокусу, а справка и настоящие кадры описывают тот же source.
