Статус: план реализации от 29 октября 2026 года; описанные изменения ещё не реализованы. Дополняет общий план запуска. Выбор проекта, защита ChiselCode Home, worktree и миграция истории остаются в [основном документе](project-startup.md).

## 1. Два контракта контекста

| Контракт | Поля | Источник |
| --- | --- | --- |
| `RuntimeIdentity` | Название и VERSION, тип клиента, модель/provider/profile текущего запроса, захваченные Plan/Build и approval mode, cwd | Запущенный процесс и captured configuration реально отправляемого запроса. |
| `UiSnapshot` | `observedAt`, видимость своей беседы, route и target фокуса, выбор модели для следующего запроса | Application-owned port OpenTUI, привязанный к владельцу запроса. В headless — `available: false`. |

Identity запроса неизменяем в течение его исполнения. Изменение модели в UI влияет на следующую задачу; если выбор отличается, эти два значения называются отдельно. `update.log`, индекс сессий и другой executable не используются для определения фактов работающего процесса.

Снимок UI сообщает состояние на момент наблюдения. При переходе в другую вкладку передаёт только `ownerVisible: false`, без её ID, проекта, текста и черновика. Фокус может быть неизвестен; активное окно ОС и глобальные события клавиатуры не наблюдаются. OpenTUI явно обозначается как терминальный интерфейс, без DOM.

Привязка проекта использует WorkspaceRef после реализации общего допуска. До этого передаётся фактический cwd существующего runtime, без нового утверждения, что проект уже прошёл WorkspaceAdmission.

## 2. Встраивание в существующий runtime

1. Собирать identity в общем application/runtime seam из VERSION и captured model/modes; использовать один builder для CLI, OpenTUI и помощников. Помощник получает собственную фактическую конфигурацию. [Системный промпт](../../../src/core/prompt.ts) отображает компактные schema-поля с понятными источниками, без чтения файлов приложения.
2. Собирать UI snapshot один раз на попытку и передавать через существующий ephemeral request context в [AgentRuntime](../../../src/runtime/agent-runtime.ts). Один объект участвует в подсчёте токенов и отправке; новый retry получает новый снимок. Он не становится постоянным фактом в Session, summary или checkpoint.
3. Application-owned port возвращает только ограниченные данные своего владельца. Credentials, секретные endpoints, содержимое других бесед и произвольная сериализация UI-state не передаются. Расширения и model tool input не подменяют identity; пользовательские строки экранируются как данные.
4. Добавить короткое правило агенту: для вопросов о собственной среде использовать переданные сведения, указывать время UI-наблюдения и честно отмечать неизвестное. Новый универсальный инструмент доступа к внутренним файлам приложения не нужен.

## 3. Переносы в Markdown

В [inline renderer](../../../src/ui/opentui-message.tsx) HTML-token сейчас выводится как raw text, поэтому внутри таблицы виден `<br>`. Исправление делается на уровне представления токенов: только точные формы `<br>`, `<br/>`, `<br />` без атрибутов, без учёта регистра, преобразуются в перенос. Остальной HTML сохраняет прежнее текстовое поведение.

Кодовые блоки, inline code и экранированный `&lt;br&gt;` сохраняются буквально. Глобальная замена в исходном ответе не используется. Сохранённая история и исходный текст ответа не переписываются. Существующие table renderer и узкий fallback должны учитывать многострочную высоту, streaming, resize и выделение.

Для UI-части применяется [скилл OpenTUI](https://github.com/msmps/opentui-skill), профильные React/components/testing references и установленные типы. Обновление OpenTUI или добавление HTML/DOM-движка для этой задачи не требуется.

## 4. Порядок и проверки готовности

| Шаг | Критерий готовности |
| --- | --- |
| Identity | Перехваченный запрос содержит фактические VERSION/model/provider/profile/modes; смена следующей модели и запуск помощника не подменяют их. |
| UI snapshot | Headless, неизвестный фокус, смена вкладки и retry дают корректные данные владельца; token counting, auto/emergency compaction и resume сохраняют нужный срок жизни снимка. |
| Markdown | Настоящий renderer показывает переносы в таблицах и inline-тексте; code/escaped HTML остаются буквальными. Проверены 40×12, 80×24, 120×40, streaming, resize и копирование выделения. |
| Интеграция | Тест №8 прогоняется на живых выбранных моделях с учётом вызовов инструментов: ответ о версии/модели берётся из контекста, неизвестное не выдумывается. Отдельно завершается допуск проектов по общему плану. |

Controlled-provider тест проверяет фактический payload и отсутствие фонового чтения логов ядром; он не доказывает поведение живой модели. Для ручного прогона фиксируются версия CLI, модель/профиль, file-tool calls, токены и время ответа. Прежние девять чтений и 58,4 с — наблюдённый исходный случай, а не универсальная норма или обещание ускорения.

Дополнить существующие prompt/context/runtime tests и `opentui-message.test.tsx`, включая разные варианты `<br>` и незавершённый streaming token. UI-файл уже входит в platform subset Windows/macOS: повторный CI-step не добавляется. При реализации показать кадры настоящего OpenTUI, обновить затронутые руководства и `Unreleased`, выполнить проверки по фактическому изменению.
