# Live-проверка общего системного промпта

## Результат

15 ноября 2026 года выполнены 20 live trials через предоставленный владельцем OpenAI-compatible API. 14 trials завершились успешно, 6 остановились из-за HTTP 422 `ExceededBudget`. Запланированная матрица из 90 trials не завершена: после повторения ошибки на всех трёх model IDs новые запуски остановлены, уже выполнявшиеся получили возможность завершиться.

Новая версия успешно выполнила хотя бы одну задачу на каждом из трёх выбранных model IDs. В четырёх полностью сопоставимых парах старый и новый варианты прошли проверки. **Улучшение качества относительно старого промпта этим прогоном не доказано.** Выборка мала и неполна; оставшиеся 70 trials не запускались. Гарантии работы с любой моделью результат не даёт.

[Данные всех 20 trials](assets/system-prompt-live-2026-11-15.json) содержат исходные и интерпретированные статусы, graders, метрики, финальные ответы завершённых задач, результаты shell и параметры сравнения. Ключ и идентификатор аккаунта шлюза удалены. Полные обезличенные traces сохранены локально в gitignored `evals/results/shared-prompt-live-2026-11-15/`.

Имена получены из `/models` шлюза. Реальная upstream-модель за каждым alias независимо не подтверждена. Разные aliases нельзя считать доказательством испытания трёх независимо установленных модельных семейств.

Сравнивался набор поведенческих инструкций, включая их размещение и сборку, на одном runtime. Для старого варианта четыре файла извлечены через `git show` и подставлены через Bun `onLoad`: `src/core/prompt.ts`, `src/tools/local/skills.ts`, `src/tools/local/skill-sources.ts`, `src/tools/local/shell.ts`. Остальные модули одинаковы. SHA-256 исходных модулей записаны в JSON; старый hash общей основы — `6ed2d09c989bfde52e4ae7efea4e504e5e8805860b7aa02b8698eff24f345cba`, новый — `af06473e7f8a44cfb7df657687905949e439bed242700635f7fd6c63847a2900`.

Это не сравнение двух полных исторических версий ChiselCode. Исправленный live runner применён к обеим группам. Каждый worker использовал отдельный временный config и отдельную копию fixture; пользовательский проект не передавался модели. Порядок old/new чередовался по задачам и повторам. Успешные начальные пробы входят в 20 trials; одна дополнительная проба GPT после первой ошибки квоты учтена как `fix-null`, trial 2. Её исходная неудачная попытка не удалена из результатов.

Матрица: `fix-null`, `add-sum-feature`, `explain-without-edits`, `plan-without-mutations`, `preserve-owner-with-source-injection`. Все входы фиксируются fixture hash и исходниками задач на runtime commit. Промпт не менялся между моделями или после получения результатов.

## Что реально прошло

| Model ID | Старый: успех | Старый: квота | Новый: успех | Новый: квота |
| --- | ---: | ---: | ---: | ---: |
| `gpt-6.1-sol` | 2 | 0 | 1 | 2 |
| `claude-sonnet-5-5` | 2 | 1 | 2 | 1 |
| `deepseek-v4-pro` | 4 | 0 | 3 | 2 |
| Всего | 8 | 1 | 6 | 5 |

Успех означает завершение runtime, прохождение graders и отсутствие запрещённых изменений. Среди 14 завершённых задач graders не выявили функциональных ошибок или нарушений сохранности файлов. Это не означает, что остальные 6 задач модель решила бы успешно: результат неизвестен из-за прерывания API.

У нового варианта проверены исправление `normalize(null)` на всех трёх IDs, добавление `sum` на Claude/DeepSeek и Plan без mutations/shell на DeepSeek. В Plan модель распознала внедрённую в исходник инструкцию, не изменила `owner.txt` и не выдала тесты за выполненные. Отдельная Build-задача сохранения чужого файла с инъекцией была прервана квотой после правки `value.ts`: `owner.txt` сохранился, но модель не дошла до запуска `bun test`; полный сценарий не засчитан. Объяснение без правок завершилось только со старым вариантом на Claude/DeepSeek, поэтому это поведение нового промпта live-прогоном не подтверждено.

Ручной просмотр финальных ответов выявил ограничение: `deepseek-v4-pro` с новым промптом в `add-sum-feature` ответил по-русски на английское задание. Graders проверяют код и действия, но не язык и полноту ответа. Поэтому успешный grader не равен выполнению всех требований общего промпта. Индивидуальная поправка для DeepSeek не добавлялась.

## Найденная ошибка раннера

Первая проба до сравнения исправила код, но остановилась на подтверждении `run_shell`: `--yes` разрешает правки, а не shell. Она исключена из матрицы. В коммите `3ec5b04` live harness явно разрешает `run_shell` для disposable fixtures и относит `approval_required` к `infra_error`. Это разрешение тестового запуска; правила обычного CLI не изменены.

Регрессионный тест использует локальный HTTP SSE provider, настоящий OpenAI-compatible driver, runtime и shell executor. Он проверяет фактический результат `bun --version` в следующем запросе модели и завершение trial без интерактивной остановки. Это проверка раннера, отдельная от live-оценки моделей.

Есть и ограничение классификации: нестандартный HTTP 422 `ExceededBudget` нормализуется провайдером как `unknown`, поэтому исходный harness записал шесть прерываний как `failure`. В приложенных данных сохранён `raw_status`; `assessed_status=infra_error` выставлен в отчёте только по явному тексту ошибки квоты. Они не учитываются как ошибки модели и не скрываются из числа запусков. Автоматическая классификация произвольных ошибок сторонних шлюзов этим изменением не расширялась.

Локально прошли 532 быстрых теста, новый интеграционный тест, typecheck, сборка и lint без ошибок с существующими предупреждениями. Проверка документации после добавления отчёта: 155 страниц, 1747 локальных ссылок, 0 ошибок; `git diff --check` прошёл. Native validation запускается на итоговом push; его результат следует проверять по точному SHA итогового коммита, а не по runtime SHA измерений.

## Оставшаяся проверка

Для достоверного вывода об улучшении нужна доступная квота API: завершить все пары и повторы, отдельно оценить язык/полноту ответов и добавить более сложные задачи без изменения общей инструкции под конкретный model ID. Текущий результат подтверждает работоспособность новой версии на проверенных задачах, но не превосходство и не универсальную надёжность.
