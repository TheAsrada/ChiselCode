# Побочные вопросы: отчёт о реализации

Этап P1.4. Ниже сохранены сведения и результаты проверок реализации выпуска 0.6.19.

База реализации: main `55feb46b29370b2f01c6c863c50b5f2ee23b5b62`, версия 0.6.18. Работа продолжила опубликованные LSP и автоматическую настройку серверов. Изменения выполнены непосредственно в main; новые ветки, worktrees для разработки и PR не создавались. Выпуск v0.6.19 добавлен по отдельному поручению владельца.

## Поведение

`builtin.btw` регистрирует `/btw <вопрос>` через существующий API команд расширений. Основные операции остаются в своей очереди, `side_query` получает отдельную операцию и ограниченный контекст с портом модели без `tools`. Обычная команда расширения также может использовать ленивый порт модели; команды без обращения к модели по-прежнему не требуют API-ключа.

Контекст, профиль, модель и адрес API фиксируются при отправке. Core читает живую Session через узкий мост, включая уже принятый запрос до первого ответа модели; незавершённые блоки протокола не передаются. Позднее создание сессии закрытого разговора не заменяет нового владельца. Во время сетевого запроса не удерживается блокировка проекта, не создаются привязка MCP или второй AgentRuntime.

Плавающее окно принадлежит исходному разговору: Esc/«Скрыть» скрывают представление, F6/«Открыть» возвращают его; без F-клавиши доступны Tab → запись → Enter. «Остановить ответ» отменяет только побочный запрос. Ctrl+C сохраняет отмену основной задачи и её очереди. Черновик, положение курсора, выделение и прокрутка принадлежат представлению побочного ответа. Подтверждение основной операции временно получает единственное право на ввод, пока побочный запрос продолжает работу. Ответ не добавляется в основные сообщения, сжатие истории или заполнение контекста.

## Ограничения и сохранение

Лимиты: вопрос — 8 КиБ UTF-8, снимок истории — 64 КиБ, весь ввод — 16 000 оценочных токенов, ответ — 2048 токенов и 64 КиБ, общий срок — 120 секунд. Допускается один активный запрос на разговор и четыре на приложение. Известные пределы модели дополнительно уменьшают бюджет. Неизвестные пределы, цены и расход остаются неизвестными.

Повторы SDK и резервный вызов для совместимости отключены. Core выполняет не более трёх HTTP-попыток ответа, только после явного 429/5xx до текста; после текстового фрагмента или неизвестного исхода автоматического повтора нет. Native `count_tokens` использует существующий ограниченный транспорт без повторов SDK. Истечение времени, ручная отмена, отказ модели, пустой ответ, отсутствующее или повторное финальное сообщение, предложенный инструмент и обрезка имеют отдельные статусы. Секреты, разделённые между фрагментами потока, проходят санитайзер с ограниченной задержкой вывода до наблюдателей, UI и сохранения.

Session сохраняет `schemaVersion: 3`: необязательные типизированные `sideQueries/mainSpend/sideQuerySpend` проходят существующие миграцию и валидацию. Основное сохранение под блокировкой индекса объединяет свежие побочные поля; побочная запись меняет только свою операцию и учёт расходов. Старый полный снимок основной задачи не стирает ответ или расход. Учёт присваивается по `operationId` и пересчитывается из основного итога и реестра побочных расходов, а не прибавляется повторно. Возобновление помечает незавершённые побочные записи как `interrupted` без открытия окна или повторного запроса.

Сохраняются последние 50 завершённых текстовых записей и все активные записи. Компактные сведения о расходах старых операций остаются для общего итога и однократного учёта позднего usage. Полный снимок разговора не дублируется в побочной записи. Ошибка сохранения явно сообщает, что ответ пока доступен только в текущем окне.

Доверенный программно подключённый JavaScript работает в процессе приложения; это не песочница. Callback, игнорирующий отмену, нельзя принудительно остановить через readonly API; core блокирует поздний текст и освобождает владельца по истечении срока, а SDK получает abort. Поздний наблюдаемый расход обновляет только исходную операцию. Подагенты, фоновые задания, UI-слоты и внешний SDK этим этапом не реализованы.

Регрессии LSP используют внешний typescript-language-server 6.0.1 / TypeScript 6.0.3 и Pyright 1.1.414, Node 24.19.0. TypeScript из зависимостей разработки ChiselCode не подставляется вместо сервера. Установленный пакет не включает автозагрузку тестовых расширений или скрытые флаги.

Интеграция настоящего TUI удерживает основной HTTP-запрос на управляемом барьере. Побочный запрос выдаёт текст до освобождения основной операции, продолжает работу и сохраняется во время подтверждения write_file. Подтверждение получает приоритет над окном, отказ возвращает побочное представление, основной агент продолжает инструменты. Проверены единственное создание Session, два независимых потока, пустой набор инструментов побочного запроса, общий расход без удвоения, скрытие/открытие без сети, отдельный черновик, изменение размера и возобновление. CLI использует оба настоящих SDK-драйвера и локальный endpoint; платная модель не требуется.

Кадры получены `captureCharFrame()` и `captureSpans()` установленного OpenTUI 0.5.12; PNG растеризует те же терминальные ячейки и RGBA. Исходные TXT/JSON сохранены рядом; макеты в браузере и генерация изображений не использовались. ## Воспроизведение кадров и UI-проверок

```sh
CHISEL_CAPTURE_DIR=/absolute/captures bun tests/fixtures/tui-side-query.ts
CHISEL_CAPTURE_DIR=/absolute/captures bun test tests/unit/opentui-side-query.test.tsx
```

Эти переменные используются только тестами. Проверка упаковки запускает встроенное окно /btw из установленного пакета и compiled-сборки. Обычные проверки CLI используют тот же диспетчер команд, без тестового загрузчика в приложении. Матрица CI сохраняет Windows/macOS/Linux и регрессии настоящих закреплённых серверов LSP.

Переиспользованы OpenTuiDialog/DialogAction/Palette, native textarea, FormattedMessage и TerminalScrollbox. Явный перехват владельца клавиатуры до глобальных обработчиков дополнен параметрами фокуса. API OpenTUI 0.5.12 `KeyHandler.emitWithPriority`, `preventDefault/stopPropagation` и `prependListener` проверены напрямую; отладочные цвета и отдельная дизайн-система не переносились. Проверки без внешней модели охватывают реальные HTTP-попытки с отключёнными повторами SDK, собственных провайдеров без ключа, ошибки протокола/авторизации и частичные ответы, пределы, поздний расход, разделённые секреты, одновременное объединение сохранений и хранение прерванных ответов.
