У больших результатов сохранены ссылки `tool-result://…`. Сами файлы artifacts не приложены: целостность их исходных bytes нельзя проверить по одним JSON. Запрос большего `maxChars` использует полный извлечённый документ из кеша, пока он доступен и действующая policy разрешает адрес.

## Воспроизведение и исправления

Живая проверка выполнена на Linux x64, Bun 1.4.3, 21 октября 2026 года через штатный DNS/IP-pinned HTTP client с сохранением proxy и TLS. Reuters снова вернул 401. AP в этой среде ответил 200 и отдал читаемый текст; прежний 403 не воспроизвёлся. Это наблюдения конкретного запроса, не обещание постоянной доступности сайтов.

### Отказ внешнего сервера

Раньше результат содержал только `WEB_HTTP_ERROR: Web request returned HTTP 401.`. Теперь сообщение содержит домен, HTTP status и русское объяснение: авторизация, автоматический доступ или ограничения сайта могут зависеть от его сервера. `details.hostname` дополняет прежние `status`, `retryable` и Retry-After. HTTP 404 и 429 объясняются отдельно; raw error body не попадает в результат.

Guidance различает поиск и открытие страниц, советует перейти к доступному авторитетному источнику после эквивалентных отказов, читать нужные artifact ranges и увеличивать `maxChars`, когда требуется текст за пределом извлечения. Это рекомендации модели, не гарантия её поведения. Транспорт не делает скрытого replay 401/403/451 и не закрывает весь домен после отказа одного пути. Разрешения, SSRF, TLS, redirects и отмена сохраняются.

### Статическая оболочка страницы

На `https://www.nyse.com/index` воспроизведён HTTP 200 с 265879 bytes HTML, из которых extractor получил 126 символов: заголовок «Connect with NYSE» и две ссылки. Динамические котировки не были прочитаны, но результат не содержал пояснения.

Теперь HTML со scripts и только заголовками/ссылками в выбранном теле получает optional `source.warnings: ["limited_static_content"]` и понятное предупреждение. Полезные ссылки сохраняются; cache и история сохраняют metadata. Проверка основана на DOM после удаления служебного содержимого и не отклоняет короткий содержательный текст. `truncated: false` продолжает означать отсутствие обрезки по extraction limit. Это консервативная диагностика; она не распознаёт все JS-приложения, login pages или paywalls и не исполняет браузер.

### UTF-8 в коротком превью

В переданном разговоре у превью Интерфакса виден `�` на границе обрезки. Общий `normalizeResult` делал `Buffer.subarray(...).toString("utf8")` без проверки границы символа. Этот сценарий воспроизведён независимо для кириллицы, трёхбайтового символа и emoji.

Нормализация использует общий `utils/text.utf8Prefix`, а краткая причина ошибки — `clipText`. Прежний экспорт helper из `models/context` сохранён. Budget остаётся прежним; полный artifact, метка недоверенного источника и исходная ошибка сохраняются. Исправление применяется и к другим инструментам с длинным выводом.

## Проверки

До исправления три новые регрессионные проверки завершились с ошибкой: ограниченный статический HTML, диагностика HTTP и UTF-8 preview. После исправления:

| Набор | Фактический результат на Linux |
| --- | --- |
| Быстрый профиль | 432 pass, 0 fail, 3231 assertions, 44 файла, 1,52 с. |
| Content/result/security + HTTP/runtime | 111 pass, 0 fail, 806 assertions, 5 файлов, 2,99 с. |
| Runtime v2 + Auto/Exa/Parallel/download | 62 pass, 0 fail, 664 assertions, 5 файлов, 12,12 с. |

Точечные проверки включают сохранение warning и ошибки в session, cache hit без второго HTTP, увеличение извлечения из кеша, публичный путь после 401 на том же host, отсутствие автоматического повтора и утечки error body, полный UTF-8 artifact и trust label. Существующие тесты проверяют redirects, DNS rebinding/SSRF, Ask/Deny, cancellation, decompression limits, credentials, скачивание и replay. Новый тест нормализации включён в быстрый профиль: он использует только небольшие изолированные временные файлы.

Typecheck, lint и CLI/SDK build прошли. Lint завершился без ошибок, с 400 warnings и 57 infos. Локально упакованный и установленный npm-пакет исправленных исходников прочитал `example.com` без warning; compiled CLI прочитал NYSE с `limited_static_content`. Обычный собранный CLI сохранил контролируемый отказ Reuters: `WEB_HTTP_ERROR`, status 401, hostname и `retryable: false`.

[Quick CI](https://github.com/TheAsrada/ChiselCode/actions/runs/39714221791) успешна на точном source `45785fd`: быстрый профиль, typecheck, lint, CLI/SDK build и запуск CLI. Полный Native validation не запускался: изменения не затрагивают механизм native transport, IO/cleanup или платформенные ветки. Проверки опубликованных установщиков нового выпуска не заявляются.

Локальные пакеты, проверенные при реализации, сохраняли номер исходников 0.6.38 и не были публикацией установщиков. В Native CI для 0.6.39 прошли smoke на Windows и macOS; они не были частью первоначального набора проверок исправления. Логика открытия соединений, DNS/TLS, чтения потоков и остановки процессов не менялась. Настоящая модель с обновлённым guidance и полные пользовательские сценарии подготовки PDF не проверялись.

В шести изменённых Markdown проверены 82 локальные ссылки, anchors и пути изображений, ошибок нет. Отчёт доступен из оглавления материалов участников, пользовательской справки Web и решения проблем.
