## Решение в существующей архитектуре

Нормализация находится в общем ToolExecutor, перед прежними parser/prepare/permissions; UI и provider drivers не исполняют исправленные вызовы самостоятельно. Изменяются только однозначные представления известных полей. Не поддерживаются исправление UUID/имён, подстановка обязательных значений, переписывание shell, удаление неизвестных параметров или исполнение незавершённого provider stream. Составные и ссылочные схемы остаются за исходным валидатором. Политики Plan, permissions, путь и ownership, revisions и отмена сохраняются.

Проверка повторов теперь работает до lookup/parser; `AgentRuntime` оставляет модели возможность исправить вызов после предупреждения. Два подряд целиком заблокированных batches завершают запрос после checkpoint. Другой результат сбрасывает счётчик; отсутствие общего лимита шагов помощника не означает бесконечный повтор уже заблокированных вызовов. Исходный fingerprint и кэш по call ID сохраняют запрет повторного эффекта.

Завершение проверяется по текущему assistant message. Streaming-текст остаётся временной проекцией; успешный полный ответ определяет итог, в том числе при middleware и адаптере без text deltas.

## Сравнение с OpenCode

Отдельный предел `TOOL_FAILURE_LIMIT` останавливает восемь последовательных batches только с ошибками. Он не зависит от совпадения fingerprint: смена несуществующего GitHub-инструмента на worktree/shell не создаёт бесконечный цикл. Проверки обычного и дочернего запроса сохраняют файл, созданный до отказов; дополнительный сценарий подтверждает сброс счётчика после успешного чтения. Ошибка проекта остаётся ошибкой, уже выполненное действие не повторяется.

Изучен snapshot OpenCode `3ba597f7769e19cc3b5f67e3d6667e7b6318f6a3`:

- [ToolInputRepairPlugin](https://github.com/anomalyco/opencode/blob/3ba597f7769e19cc3b5f67e3d6667e7b6318f6a3/packages/core/src/plugin/tool-input-repair.ts) приводит представление по схеме перед validation. В ChiselCode выбран более узкий набор без алиасов имён, удаления неизвестных полей, распаковки строковых объектов и scalar → array.
- [ToolRuntime](https://github.com/anomalyco/opencode/blob/3ba597f7769e19cc3b5f67e3d6667e7b6318f6a3/packages/ai/src/tool-runtime.ts) возвращает неуспешный вызов модели как tool result. ChiselCode сохраняет свою durable invocation, scheduler и разрешения.
- [SessionRunnerLLM](https://github.com/anomalyco/opencode/blob/3ba597f7769e19cc3b5f67e3d6667e7b6318f6a3/packages/core/src/session/runner/llm.ts) разделяет шаг и попытки, ограничивает восстановление и отдельно обрабатывает незавершённые вызовы. Его Effect/БД/потоковое исполнение не переносятся в ChiselCode; сохраняется проверка полного terminal response до исполнения инструментов.
