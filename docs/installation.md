# Установка и обновление

[Документация](README.md) · [Главная](../README.md)

## Готовые установщики

Скачивайте пакеты из [GitHub Releases](https://github.com/TheAsrada/ChiselCode/releases/latest). Сверяйте скачанные файлы с `SHA256SUMS` из того же выпуска, начиная с 0.6.52. Подставляйте номер выпуска вместо `<версия>`.

Текущий выпуск — [CLI 0.6.53](https://github.com/TheAsrada/ChiselCode/releases/tag/v0.6.53). [Результаты проверок и SHA-256](contributors/reports/release-0.6.53.md#публикация-и-проверка-файлов).

| Система | Файл | Куда устанавливается программа |
| --- | --- | --- |
| Windows x64 | `ChiselCode-Setup-<версия>.exe` | `%LOCALAPPDATA%\ChiselCode` |
| macOS Apple Silicon | `ChiselCode-Setup-<версия>-macos-arm64.pkg` | `/usr/local/bin/chisel` |
| macOS Intel | `ChiselCode-Setup-<версия>-macos-x64.pkg` | `/usr/local/bin/chisel` |
| Debian/Ubuntu x64 | `ChiselCode-Setup-<версия>-linux-amd64.deb` | `/usr/bin/chisel` |
| Fedora x64 | `ChiselCode-Setup-<версия>-linux-x86_64.rpm` | `/usr/bin/chisel` |
| Arch Linux x64 | `ChiselCode-Setup-<версия>-linux-x86_64.pkg.tar.zst` | `/usr/bin/chisel` |

### Windows

С CLI 0.6.44 новые ярлыки и запуск с завершающей страницы NSIS передают `--launcher` и открывают главную без проекта. Старый ярлык со служебным cwd также открывает выбор папки. После обновления восстанавливаются только прежний проверенный проект и его session ID; перезапуск без проекта возвращает главную.

Запустите EXE. Установка не требует прав администратора, добавляет `chisel` в пользовательский PATH и создаёт ярлык в меню «Пуск». Ярлык рабочего стола — дополнительный компонент. После установки откройте **новый** PowerShell и выполните `chisel`.

Для неподписанного EXE Windows может показать SmartScreen. Проверьте источник файла и название релиза перед запуском.

### macOS

Выберите пакет под свой процессор и откройте его системным установщиком. Если система блокирует неподписанный пакет, проверьте источник и используйте системные настройки разрешения запуска. После установки выполните `chisel` в терминале.

### Linux x64 с glibc

Из каталога со скачанным файлом выполните команду для своего дистрибутива, заменив `VERSION` на номер выпуска.

| Дистрибутив | Установка или обновление | Удаление |
| --- | --- | --- |
| Debian / Ubuntu | `sudo apt install ./ChiselCode-Setup-VERSION-linux-amd64.deb` | `sudo apt remove chiselcode` |
| Fedora | `sudo dnf install ./ChiselCode-Setup-VERSION-linux-x86_64.rpm` | `sudo dnf remove chiselcode` |
| Arch Linux | `sudo pacman -U ./ChiselCode-Setup-VERSION-linux-x86_64.pkg.tar.zst` | `sudo pacman -R chiselcode` |

После установки выполните `chisel --version`. Для ручной установки распакуйте `ChiselCode-<версия>-linux-x64.tar.gz` в отдельный каталог и запускайте `chisel` оттуда. Храните папку `skills` рядом с бинарником. Для других архитектур и систем с musl доступна [сборка из исходников](development.md).

### Установка через curl

На Linux x64 с glibc скрипт использует `curl`, Bash и стандартные GNU-утилиты. Скачайте скрипт последнего стабильного выпуска и запустите его.

```bash
curl -fsSLo install.sh https://github.com/TheAsrada/ChiselCode/releases/latest/download/install.sh
bash install.sh
export PATH="$HOME/.local/bin:$PATH"
chisel --version
```

При необходимости добавьте строку с `export PATH` в настройки своей оболочки. Скрипт загружает архив своей версии, проверяет SHA-256 и запускает проверку версии перед переключением `~/.local/bin/chisel`. Для обновления повторите те же команды. Выпуски лежат в `${XDG_DATA_HOME:-$HOME/.local/share}/chiselcode-cli/releases`. Чтобы удалить эту установку, удалите её ссылку `~/.local/bin/chisel` и каталог `chiselcode-cli`.

### npm и Bun

Установите опубликованный в GitHub архив `chiselcode-<версия>.tgz`. Он содержит CLI и SDK расширений. Для запуска CLI в обоих случаях нужен Bun в PATH.

```bash
archive=https://github.com/TheAsrada/ChiselCode/releases/download/v0.6.53/chiselcode-0.6.53.tgz
npm install -g "$archive"
# или
bun add -g "$archive"
chisel --version
```

Для обновления установите архив новой версии тем же менеджером. Для SDK без глобального CLI установите архив как зависимость проекта. [Использование SDK](extensions/quickstart.md).

### Рецепты Homebrew и AUR

Файлы `chiselcode.rb` и `chiselcode-<версия>-aur.tar.gz` доступны в GitHub Release. Оба рецепта используют переносимый Linux x64 архив конкретного тега и закреплённый SHA-256. Формулу можно добавить в собственный Homebrew tap. Для Arch распакуйте рецепт, проверьте `PKGBUILD` и запустите `makepkg -si` в его каталоге от обычного пользователя. `chiselcode-bin` занимает тот же путь, что и готовый пакет pacman. Для перехода между ними удалите прежний системный пакет перед установкой нового.

## Внешние инструменты

Bun не нужен для запуска скомпилированной программы из установщика. Для ускоренного поиска рекомендуется **ripgrep (`rg`)**. Если его нет, `grep` использует встроенный поиск. Для Git-инструментов нужен **Git** в PATH. Установщики проекта не включают эти дополнительные программы.

```bash
chisel --version
rg --version
git --version
```

## Обновление

| Способ | Поведение |
| --- | --- |
| `chisel update` | Проверить последнюю версию и показать ссылку на установщик |
| `chisel update --json` | Получить результат проверки в JSON, без установки |
| `/update` в чате | Открыть окно обновления: проверить версию, скачать файл выбранного канала или показать действия менеджера |
| Установка из исходников | Обновить исходники по руководству разработки |

При запуске ChiselCode проверяет новые версии в фоне; готовое обновление отмечается на главной. Уведомление или `/update` открывает окно с установленной и новой версиями. Кнопка «Скачать» начинает загрузку с реальным процентом и объёмом; Esc или «Отмена» прерывают её и удаляют неполный файл. Перед установкой проверяются размер и SHA-256 из метаданных GitHub Release. Если файлы релиза ещё собираются, можно повторить проверку позже.

После подготовки обновления на Windows выберите «Перезапустить»: текущий процесс завершится, установщик тихо заменит файлы и вернёт приложение в выбранный проект и сохранённую сессию. «Позже» позволяет продолжить работу и вернуться к подготовленному обновлению без повторной загрузки. Перезапуск недоступен, пока выполняется запрос или очередь. На macOS и Linux окно показывает команду для скачанного файла или инструкцию по каналу. После установки перезапустите ChiselCode. Пользовательские навыки, сессии и настройки хранятся отдельно от заменяемых файлов.

Начиная с 0.6.35 выход для обновления пропускает ожидание Enter после сохранения данных. Установщик дожидается выхода ChiselCode; если файл занят другим окном или заблокирован антивирусом, прежний EXE сохраняется. Причина записывается в `update.log` рядом с программой и видна при следующем запуске в `/update`. Закройте остальные окна ChiselCode и повторите установку. [Если зависает уже установленный старый клиент](troubleshooting.md#зависает-перезапуск-после-update).

## Удаление

- Windows: используйте установленный деинсталлятор приложения.
- Linux: используйте команду удаления из раздела своего способа установки. Для переносимого архива удалите каталог распаковки.
- macOS: `sudo rm /usr/local/bin/chisel` удаляет исполняемый файл. Пакет также устанавливает встроенные навыки в `/usr/local/bin/skills/bundled`; удаляйте их только после проверки, что они относятся к ChiselCode.

Пользовательские сессии, конфигурация и ключи могут остаться после удаления программы. Их расположение описано в [конфигурации](configuration.md); удаление этих данных необратимо.

Далее: [первый запуск](getting-started.md).

## Встроенный навык создания расширений

Начиная с 0.6.33 `/extension-creator` поставляется вместе с `/skill-creator` и `/code-review`: установщики и npm-пакет включают `skills/bundled/*/SKILL.md`. Библиотека обновляет встроенные инструкции, сохраняя `skills/user`. [Создание и включение UI-расширения](ui-mods.md) не требует отдельного SDK рядом с пакетом.
