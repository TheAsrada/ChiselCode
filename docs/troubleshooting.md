# Решение проблем

[Документация](README.md) · [Главная](../README.md)

Сначала выполните `chisel --version` и `chisel doctor`. Если приложение запускается, проверьте модель и подключение в `/settings`, а папку проекта — внизу главной.

| Симптом | Что проверить |
| --- | --- |
| `chisel` не найден | Откройте новый терминал после установки; проверьте PATH и путь из [установки](installation.md) |
| Окно закрывается при двойном клике | Запускайте `chisel` из PowerShell/терминала, чтобы увидеть сообщение |
| Не найден API-ключ | Завершите `chisel setup`; проверьте выбранный сервис |
| 401 / неверный ключ | Пересоздайте или замените ключ; переменная окружения может перекрывать сохранённый |
| 404 / HTML вместо API | Проверьте тип совместимого API и базовый URL: [провайдеры](providers.md) |
| Модель не найдена | Сверьте ID с консолью сервиса или `/model` |
| Локальная модель не отвечает | Запустите сервер, проверьте порт, адрес и загруженную модель |
| `rg` не найден | Поиск продолжает работать через встроенный механизм. Для ускорения установите ripgrep и проверьте `rg --version` |
| Git-инструмент не работает | Проверьте `git --version` и наличие репозитория в выбранной папке |
| Изменение не выполнено | Проверьте отказ в подтверждении, правила `.chiselrc` и `approval_required` в одноразовом режиме |
| Файл за пределами проекта / ignored path | Проверьте `/cwd`, симлинки и `ignorePatterns`; не отключайте проверки ради ошибочного пути |
| Сессия не найдена | Выберите исходную папку проекта; для префикса ID нужно однозначное совпадение |
| Нельзя выделить текст мышью | Попробуйте Shift при выделении в терминале или режим `CHISEL_NO_ALT_SCREEN=1` с нативной историей |
| Не вставляется текст | В 0.6.13+ работают Ctrl+V, Ctrl+Shift+V, Shift+Insert и правый щелчок по полю. Если терминал сам обрабатывает сочетание, он передаёт обычную вставку. В SSH используйте меню вставки терминала или его Ctrl+Shift+V; ChiselCode не читает буфер удалённой машины |
| Не копируется выделение | Выделите текст чата мышью либо используйте Ctrl+Shift+C / Ctrl+Insert. Ctrl+C останавливает запрос. Если терминал не поддерживает OSC52, удерживайте Shift при выделении и копируйте средствами терминала |
| Неудобная прокрутка | Нажмите End для возврата к вводу; попробуйте `CHISEL_ALT_SCREEN=0` |
| Квадраты с вопросительным знаком вместо значков | Выберите в терминале моноширинный шрифт с поддержкой Unicode и языка сообщений. Начиная с 0.6.34 используется только графическое оформление OpenTUI; переключатель ASCII удалён |
| Обновление не устанавливается автоматически | Автоустановка рассчитана на установленную Windows-версию; на остальных платформах следуйте инструкции для своего канала |
| Ошибка проверки обновления | Проверьте доступ к GitHub; скачайте пакет вручную из Releases |

## Проверка подключения

`doctor` проверяет локальные настройки. Для сетевой проверки откройте `/settings` → «Проверить». Даже доступный список моделей не гарантирует, что выбранная модель поддерживает все нужные операции: попробуйте короткий запрос.

## Долгое ожидание ответа модели

«Ожидаю ответ модели» после завершения команды означает, что клиент ждёт следующего ответа от API. Если поток не начался или перестал передавать содержательные события на 60 секунд, CLI выдаёт `timeout`. Посмотрите результаты выполненных инструментов в разговоре перед повтором задачи. При отказе шлюза по квоте проверьте лимит выбранного аккаунта. При повторяющемся тайм-ауте укажите в отчёте провайдера, модель и этап ожидания.

## Ctrl+C не останавливает запрос

Вернитесь в чат и нажмите Ctrl+C без Shift. В окнах просмотра помощников, фоновых задач и статусов сочетание не отменяет основную работу; используйте именованное действие «Остановить» для выбранной задачи или закройте окно через Esc. В чате остановка относится к текущей вкладке и её очереди; остальные вкладки продолжают работу. Для выхода из приложения отправьте `/exit`.

В Linux-терминалах с протоколом Kitty русская раскладка могла передавать `с` и базовый код `c`, который прежний обработчик не учитывал. Исправление вошло в [CLI 0.6.52](https://github.com/TheAsrada/ChiselCode/releases/tag/v0.6.52). Если установленный выпуск ещё не содержит исправления, переключитесь на английскую раскладку и повторите Ctrl+C. Это также помогает, если терминал не сообщает базовый код клавиши.

Если сочетание по-прежнему не работает, проверьте его назначение в настройках терминала. В отчёте укажите `chisel --version`, терминал, раскладку, наличие SSH/tmux и этап работы: ожидание модели, команда или подтверждение. Ctrl+Shift+C предназначен для копирования и не останавливает запрос.

## Тайм-аут подготовки LSP

При первом анализе для ряда языков ChiselCode скачивает закреплённый backend или SDK. Если подготовка прервалась по тайм-ауту, проверьте соединение и повторите диагностику. Подготовленные и проверенные файлы используются повторно. Если процесс уже был запущен и завершился с ошибкой, откройте «Анализ кода · LSP» по F9, проверьте состояние сервера и выберите перезапуск. [Настройки и состав каталога](configuration.md#анализ-кода-lsp).

## Ошибка `chunk.choices[0]` или некорректное событие провайдера

В 0.6.36 и прежних клиентах событие OpenAI-совместимого шлюза с `usage` без `choices` могло завершить запрос ошибкой `undefined is not an object (evaluating 'chunk.choices[0]')`. Завершающий пакет без `delta` вызывал похожий сбой. Исправление вошло в [CLI 0.6.37](https://github.com/TheAsrada/ChiselCode/releases/tag/v0.6.37); обновите клиент. [Проверки выпуска](contributors/reports/release-0.6.37.md). Удалять историю и настройки не требуется.

В исправленном драйвере служебный usage принимается, а повреждённое событие даёт `transport` с названием API и полем. Если ошибка сохраняется, проверьте driver и endpoint профиля: `openai-chat` ожидает Chat Completions, `anthropic-messages` — Messages API. Responses API не поддерживается. Успешный `/models` не проверяет формат генерации. При сообщении об ошибке укажите провайдера, модель, версию клиента и безопасный текст диагностики; ключи и содержимое запросов присылать не нужно. [Почему возникал сбой и как проверяется поток](architecture/provider-streams.md).

## HTTP 400 с `data: [DONE]` или поток без `finish_reason`

HTTP 400 с телом только `data: [DONE]` означает, что шлюз отклонил запрос и не сообщил причину. Маркер SSE в теле HTTP-ошибки не подтверждает успешную генерацию. В CLI 0.6.40 для этого случая есть отдельное объяснение; код остаётся `bad_request`. Проверьте Chat Completions endpoint и поддержку инструментов выбранной моделью. Успешный короткий ответ или `/models` не проверяет продолжение истории с вызовами инструментов. Если отказ повторяется, передайте поддержке сервиса время запроса, модель, HTTP-статус и request ID из его журнала, без ключей и содержимого проекта.

`Provider stream ended without a finish marker` — другая ситуация: HTTP-поток завершился без `finish_reason`. Клиент сохраняет ошибку `transport` и не выполняет незавершённые вызовы. Уже выполненные инструменты предыдущих ответов остаются в истории; повторное «продолжи» использует их результаты. Оно не исправляет неисправный endpoint или постоянный отказ шлюза. [Граница протокола и разбор](architecture/provider-streams.md).

## Git показывает соседние папки или отказывает с `scope=all`

Начиная с 0.6.49, чтения `git_status`/`git_diff` в обычной папке без Git возвращают сообщение об отсутствии репозитория и `details.git.reason: not_repository`. Это не чистый Git diff и не ошибка рабочей копии. Файловые инструменты и shell продолжают действовать по своим разрешениям. Настоящие ошибки Git, включая повреждённый `.git`, не преобразуются в это состояние; `git_commit` без репозитория возвращает `GIT_NOT_REPOSITORY`, не выполняя `git init`.

В CLI 0.6.40 `git_status` и `git_diff` ограничены папкой открытого проекта, включая проект внутри родительского репозитория. `git_diff` с `scope=all` работает до первого коммита: отдельно читает staged и unstaged изменения, не добавляя файлы в индекс. Новые untracked файлы смотрите через `git_status` и `read_file`; отсутствие patch не означает, что файл не создан. Ранее обращение к отсутствующему `HEAD` могло приводить к `WORKTREE_GIT_ERROR`.

## Зависает перезапуск после `/update`

Клиенты до 0.6.35 могли остановиться на ожидании Enter после закрытия интерфейса, пока установщик пытался заменить занятый EXE. Повторный запуск вручную возвращал прежнюю версию. Исправление вошло в [0.6.35](https://github.com/TheAsrada/ChiselCode/releases/tag/v0.6.35); код уже запущенного старого клиента оно не меняет.

Закройте зависшее окно и другие экземпляры ChiselCode. Скачайте новый Windows EXE из [Releases](https://github.com/TheAsrada/ChiselCode/releases/latest) и запустите установщик вручную один раз. После установки проверьте `chisel --version` в новом терминале. Настройки и история сохраняются; удалять пользовательскую папку не требуется.

В исправленном клиенте неуспешная установка появляется в `/update` с причиной. Журнал по умолчанию — `%LOCALAPPDATA%\ChiselCode\update.log`; при установке в другую папку он лежит рядом с `chisel.exe`. Ошибка занятого файла требует закрыть остальные экземпляры и повторить установку. [Как выполняется замена и перезапуск](architecture/self-update.md).

## Linux запускает прежнюю версию после обновления

Выполните `type -a chisel` и `chisel --version`. Если PATH содержит несколько копий, оболочка запускает первую. После изменения PATH откройте новый терминал. `chisel update` показывает канал запущенной копии, когда доступна новая версия.

При установке через `curl` ошибка SHA-256 оставляет действующую ссылку и файлы прежнего выпуска. Загрузите свежий `install.sh` с последнего выпуска и повторите установку. Если скрипт обнаружил чужой `~/.local/bin/chisel`, обновите его исходным способом. [Способы установки и удаления](installation.md).

## Ошибки команд на Windows

`run_shell` работает в CMD. `;` попадает в аргументы команды; для последовательного запуска используйте `&` или `&&`. Вызов `python -m pytest ... | tail -30` может завершиться ошибкой отсутствующего `tail`, поэтому запустите проверку без pipeline и прочитайте сохранённый вывод. При ошибке CMD подсказка учитывает и саму команду, даже если текст диагностики нечитаем. [Запуск команд и чтение вывода](background-tasks.md#запустить-и-перевести-в-фон).

Настройка CMD/Python на UTF-8 и основные подсказки оболочки доступны с [0.6.23](../CHANGELOG.md#0623---2026-10-12). Если установлен более ранний выпуск, обновите ChiselCode. Для программы, которая использует собственную кодировку, включите UTF-8 её параметрами; смена шрифта не восстанавливает уже неверно декодированные байты.

Traceback, `AttributeError`, `AssertionError` и `FAILED` после успешного запуска Python означают падение проверки проекта. ChiselCode передаёт файл, строку, проверяемое условие и настоящий код завершения; разбор приложения и его тестов требует исходников этого проекта.

## Ошибки инструментов в начале задачи

Обычная локальная работа не требует GitHub или управляемой рабочей копии. Инструкции текущих исходников направляют агента сначала к файлам проекта; удалённый поиск, установка навыков и worktree нужны по задаче или правилам проекта. Для shell в открытой папке `targetWorktreeId` и `retryOf` следует опускать. Ошибка Git/worktree сама по себе не запрещает чтение, запись и shell; ограничения Plan и разрешений проверяются отдельно.

Если `.git` нет в открытой папке и её предках, текущие исходники не объявляют модели локальные Git/worktree-инструменты и coding-помощника с Git-копией. Скрытый вызов из старой истории не исполняется. Обычная работа с файлами и shell остаётся доступной; Git не нужно инициализировать ради чтения или правки. После явно запрошенного `git init` каталог обновляется при следующем запросе. Вложенные проекты внутри существующего репозитория сохраняют Git-возможности.

В 0.6.49 добавлено приведение однозначных ошибок представления аргументов: необязательный `null` опускается, а строковые числа и boolean сверяются со схемой. Это не исправляет выдуманный UUID, неверную команду, отсутствующий файл или неподдержанный инструмент. `INVALID_TOOL_INPUT` указывает поля для исправления; `REPEATED_CALL_DETECTED` останавливает повторение одинаковых отказов после возможности скорректировать вызов. Уже выполненные изменения и история сохраняются. Удалять `.git`, проект или сессии для такого восстановления не требуется.

`TOOL_FAILURE_LIMIT` означает восемь последовательных шагов, в которых все инструменты вернули ошибки, даже если их имена различались. Успешный инструмент сбрасывает этот счётчик. Это предел неуспешного цикла, а не подтверждение выполнения задачи.

При ошибке посмотрите название инструмента, его аргументы и первый отказ в «Действиях агента». Передайте версию CLI, провайдера/модель и безопасный текст первого отказа: дальнейшие сообщения могут быть следствием одной неверной цели или команды. [Подробности исправления и реальные проверки](contributors/reports/tool-cycle-reliability.md).

## «Владелец фоновых задач изменился»

В прежней реализации восстановление разговора и следующий запрос могли считать разный регистр Windows или ссылку на тот же каталог сменой проекта. В текущих исходниках путь проверяется по общей идентичности каталога, а одновременные подключения одной сессии выполняются последовательно. Исправление вошло в [CLI 0.6.32](../CHANGELOG.md#0632---2026-10-16).

При действительном конфликте открытых разговоров закройте прежнюю вкладку этой сессии и откройте её через `/resume`. Смена написания пути к той же папке не должна требовать остановки процессов. Сведения о сохранённых задачах и неподтверждённом завершении находятся в [руководстве фоновых задач](background-tasks.md#история-и-восстановление).

## MCP не подключается

Откройте `/mcp` → сервер → **Диагностика**, либо выполните `chisel mcp doctor <ID> --json`. Проверка запускает только включённые доверенные серверы. В `chisel mcp logs <ID>` виден безопасный журнал текущей попытки; он не хранится между отдельными запусками CLI.

«Нужно доверие» означает, что команда или адрес пришли из `.chiselrc`: проверьте их в `/mcp` и выдайте доверие. Изменение конфигурации требует нового подтверждения. «Нужна авторизация» требует токен или доступную env/secret reference; браузерный OAuth пока не реализован. Для локального сервера проверьте executable, PATH, cwd и разделение stdout/stderr; для удалённого — именно MCP endpoint, не REST URL и не устаревший SSE-only endpoint.

После нескольких сбоев автоматическое переподключение останавливается. Исправьте причину и выберите **Переподключить**. После ошибки внешнего изменения проверьте сервис перед повтором: предыдущая операция могла выполниться. Невалидное MCP-поле не отключает локальные инструменты; `doctor` показывает имя проблемного поля без значения секрета. [Подробная инструкция](mcp.md#диагностика-и-сбои).

## Ошибка расшифровки ключей

Если после переноса профиля появляется `Unable to decrypt ChiselCode credentials`, закройте приложение и найдите `credentials.enc` по [таблице путей](configuration.md). Сохраните его резервную копию в защищённом месте, затем переименуйте файл и пройдите `chisel setup` заново. Потребуется повторно ввести ключи; не прикладывайте этот файл к issue.

## Поиск и корпоративная сеть

Поиск Exa и Parallel доступен без отдельного API-ключа. По умолчанию Авто переходит к следующему разрешённому сервису при недоступности или квоте; отмена, deny и общие лимиты такой переход не вызывают. Если выбран Brave без ключа, переключите `/settings` → Web → Сервис поиска на Авто или выполните `chisel web configure --search-provider auto`. Ошибка `WEB_RATE_LIMITED` требует повторить позже или использовать свой поисковый тариф; неизвестные страницы можно открывать через fetch независимо от backend.

Проверьте `chisel web status --json`, затем `chisel web test --url https://react.dev/reference/`: с дефолтным Allow approval не требуется. Сохранённый Ask продолжает действовать; переключите его на Allow в Settings или через `chisel web configure --search allow --fetch allow`, если подтверждения не нужны. `WEB_NETWORK_DENIED` требует проверить также user/project deny и отключение Web; `--allow` и Bypass не переопределяют запреты. Для корпоративной сети настройте proxy, дополнительные CA и mTLS в окружении: [инструкция](network.md). TLS-проверка не отключается, proxy не открывает private network через Web. Не прикладывайте пароли proxy, PEM или закрытые ключи к issue.

Для отдельной страницы HTTP 401/403/451 означает отказ её сервера; ключ Brave и переключение Exa/Parallel не предоставляют доступ к этой странице. Найдите другой открытый источник и отличайте проверенный текст от поискового snippet. HTTP 200 тоже не гарантирует наличие данных: JavaScript не исполняется. В CLI 0.6.39 показывается предупреждение `limited_static_content`, если получены только заголовки или ссылки. [Разбор `web_fetch` и границы исправления](contributors/reports/web-fetch-diagnostics.md).

## Неизвестное окно контекста

Надпись «Размер окна неизвестен» означает, что для выбранного подключения нет известного лимита API или каталога. Сам список `/models` может успешно возвращать ID без размера окна; это не подтверждает ошибку генерации. Например, некоторые шлюзы перечисляют DeepSeek V4.1 Flash/1017 без лимитов. В текущих исходниках эти точные ID есть в каталоге, и панель помечает источник «каталог».

Сверьте точный ID и лимиты в документации вашего шлюза. Собственные суффиксы вроде `-high` или `-free` могут обозначать другое развёртывание; ChiselCode не удаляет их ради подстановки лимита похожей модели. Если лимит известен, задайте его в `.chiselrc` выбранного проекта, сохранив остальные настройки:

```json
{
  "context": { "contextWindow": 128000 }
}
```

Здесь `128000` — пример, замените его подтверждённым лимитом. Настройка применяется при следующем запросе. Она ограничивает рабочий budget и не увеличивает известное окно модели. [Остальные параметры контекста](configuration.md#параметры-core-runtime-v2).

## Проект остаётся занят после прерванной команды

Откройте разговор, в котором запускалась команда, и повторите существующее действие **Восстановить очистку** в её подробностях либо `/tasks recover ID`. Подтверждённое завершение позволяет продолжить работу без повторного запуска команды. Это относится и к обычному `run_shell`, который не переводился в фон.

Если подтверждение потеряно, сначала выполните проверку, затем перезагрузите компьютер и откройте ChiselCode сразу после входа. Историю, логи и блокировки вручную не удаляйте: отсутствие одного процесса не подтверждает завершение его потомков. [Условия восстановления](background-tasks.md#история-и-восстановление).

## Как оформить баг

Откройте [форму сообщения об ошибке](https://github.com/TheAsrada/ChiselCode/issues/new/choose) и укажите:

1. Версию ChiselCode, ОС, архитектуру и терминал.
2. Режим запуска, провайдера и модель (без ключа).
3. Минимальные шаги воспроизведения, ожидаемый и фактический результат.
4. Обезличенное сообщение об ошибке; при проблемах UI — размер окна и скриншот.

Проверьте логи и изображения на секреты. Уязвимости отправляйте по [отдельному каналу](../SECURITY.md).

## Profiles и custom providers

Provider unavailable: проверьте `chisel providers list/validate` и восстановите manifest; history/config остаются читаемыми. Multiple profiles: укажите --profile. Invalid config: исходный файл не reset, путь показан в ошибке; перед ручным исправлением сохраните backup. `config.v1.backup.json` создаётся при первом save v2, а credentials.enc не мигрирует. Подробности — [migration notes](provider-migration.md).

## Действие меню не выполняется по прежнему сочетанию

Локальные сочетания меню заменены именованными действиями. Нажимайте Tab до нужной области, стрелками выберите операцию и подтвердите Enter или Space. В узком окне перебирайте строку «Действия: …». В Settings параметры сохраняются автоматически; при ошибке ввод остаётся в форме для исправления и повтора. Глобальные переходы чата сохранены. [Актуальная таблица управления](keybindings.md#настройки-модели-навыки-и-сессии).

## Подписка ChatGPT

Если не появляется код, проверьте доступность `auth.openai.com` и включение входа по коду в настройках безопасности ChatGPT. Получите новый код через «Аккаунт» в «Подключениях»; Esc отменяет предыдущее ожидание.

После ошибки обновления токенов откройте затронутый профиль и выберите «Аккаунт» или «Войти заново». После входа выберите модель; параметры сохранятся автоматически. Для смены аккаунта беседы отдельно выберите «Использовать подключение». `OPENAI_API_KEY` относится к API и не исправляет вход по подписке. При исчерпании лимита дождитесь указанного времени сброса. «Лимиты недоступны» означает отсутствие свежих данных сервиса; не удаляйте все credentials ради обновления панели. [Подписка и профили](providers.md#подписка-chatgpt).
