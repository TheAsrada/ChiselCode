# Plan / Build

[Документация](README.md) · [Архитектура](architecture.md)

В поле ввода отображаются Plan/Build, метка разрешений Manual / Accept edits / Dont ask / Bypass и следующей строкой выбранная модель. Shift+Tab переключает workflow в редакторе; на метку можно нажать мышью. F4 отдельно переключает доступные режимы разрешений; Bypass включается в Settings. Модель, черновик и история разговора сохраняются. [Семантика разрешений](permissions.md).

| Режим | Работа агента | Доступные действия |
| --- | --- | --- |
| Plan | Изучить проект, уточнить существенные неизвестные, подготовить конкретный план | Чтение файлов, поиск, Git status/diff, загрузка инструкций скилла и чтение сохранённых результатов |
| Build | Выполнить задачу или согласованный план и проверить изменения | Все обычные инструменты с существующими правилами разрешений и подтверждениями |

Новая сессия по умолчанию использует Build. Для анализа переключитесь в Plan, отправьте задачу, ознакомьтесь с результатом, затем переключитесь в Build и попросите выполнить план. Plan остаётся активным до вашего переключения. Запрос «реализуй» в Plan приводит к подготовке плана. Агент не переключает режим самостоятельно.

План сохраняется в разговоре. Специальный файл в проекте не создаётся. Подходящий результат содержит проверенные сведения, затрагиваемые файлы, решения, последовательность изменений, способ проверки и существенные риски. Для простой задачи достаточно короткого плана.

## Переключение и сессии

- `/plan`, `/build` и `/mode plan|build` выбирают режим локально, без запроса к модели и создания вкладки.
- `chisel --mode plan` открывает TUI в Plan; этот флаг также работает для одноразового запроса. JSON-результат содержит `mode`.
- Режим принадлежит вкладке. Новая главная через «+» наследует выбранный режим, существующие вкладки сохраняют свои значения.
- При resume восстанавливается сохранённый выбор; `--mode` явно его заменяет. Старые сессии без этого поля открываются в Build.
- Shift+Tab во время работы меняет выбор для следующего запроса. Режим уже отправленного сообщения, включая очередь, зафиксирован. Если выбор отличается от выполняющегося запроса, подпись показывает `сейчас Plan` или `сейчас Build`.
- В настройках, библиотеке скиллов и других popup сочетание управляет окном; режим агента не меняется. Tab продолжает дополнять команды или переключать фокус, Ctrl+Shift+Tab переключает вкладки в поддерживающих терминалах.

## Как обеспечивается Plan

`AgentMode` отделён от provider/profile/model, оформления и разрешений. Один runtime и один каталог инструментов обслуживают оба режима. Handler объявляет `effect`: `read`, `workspace_write`, `process`, `git_write` или `external`. Это свойство кода инструмента, скилл его не меняет.

В начале запроса runtime захватывает выбранный режим. Для Plan каталог выдаёт модели только `read` definitions. Executor проверяет effect ещё раз до parse, prepare и approval: попытка вызвать write/edit/delete/apply_patch, shell, commit или create_skill возвращает `MODE_RESTRICTION` и запись invocation в состоянии `denied`. Скрытие инструмента дополняется проверкой исполнения.

Правила Plan действуют при `--yes`, `--allow`, разрешениях из frontmatter скилла и явной просьбе об изменении. Скиллы остаются доступными как инструкции через `load_skill`; их команды используют тот же runtime. Generic shell в Plan отключён: название команды и её префикс недостаточны для гарантии чтения. Для исследования есть структурированные инструменты. Git-чтение выполняется без optional index locks, fsmonitor hook, external diff и textconv, включая контекстную панель TUI.

Build передаёт действия существующей PermissionPolicy. Сам переход в Build не включает auto-approval. Pending approval из Build, возобновлённый в Plan, становится отказом без исполнения; выполненные ранее вызовы сохраняются как история и не повторяются. Для выполнения отклонённого действия после перехода в Build модель должна запросить новый вызов.

Инструкции режима входят в system при каждом построении контекста, поэтому compaction не превращает Plan в Build. История, checkpoint и internal artifacts сохраняются приложением; запросы к выбранному провайдеру продолжаются. Plan ограничивает действия зарегистрированных инструментов; ОС-изоляция остаётся отдельной возможностью runtime.
