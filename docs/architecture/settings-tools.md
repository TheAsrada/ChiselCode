# MCP и навыки внутри Settings

[Документация](../README.md) · [Архитектура](../architecture.md) · [Кадры и проверки](../contributors/reports/settings-tools.md)

Статус: принято, 0.6.34.

## Причина и решение

Ранее выбор MCP или навыков в Settings открывал второй modal поверх настроек. Пользователь терял связь между разделом и его управлением, хотя остальные инструменты уже отображались внутри Settings. Размеры, каталог, поиск и навигация общей оболочки сохранены. Меняется размещение содержимого двух разделов.

`OpenTuiMcp` и `OpenTuiSkills` поддерживают встроенное размещение через `OpenTuiToolPane`. Панель использует размер области содержимого без дополнительного backdrop, рамки и отступов modal. При вызове `/mcp` или `/skills` тот же компонент использует `OpenTuiDialog`. Контроллер MCP, каталог навыков, правила, доверие, отмена и хранение данных общие для обоих способов открытия.

## Жизненный цикл и ввод

Settings загружает MCP при первом посещении раздела. Посещённые панели остаются смонтированы: переход сохраняет форму, текущий экран, поиск и выбор. Общий `SettingsPanelControl` находится в отдельном модуле; `flush` завершает автосохранение перед переходом; `back` управляет внутренней навигацией.

`active` разрешает обработку событий только выбранной панели без подтверждения поверх неё; `focused` дополнительно ограничивает клавиатуру и native inputs областью содержимого. Ctrl+F, Tab и Escape координируются Settings. В активном содержимом LSP Ctrl+F передаётся локальному поиску серверов; при фокусе в навигации он ищет разделы. Остальные встроенные панели сохраняют прежний маршрут. MCP сообщает о незавершённой форме, изменённых категориях разрешений и выполняемой операции через `onDirty`. Закрытие ожидает `flush`; ошибка сохраняет форму и причину без диалога несохранённых изменений. Ctrl+C и первый Escape во время MCP-проверки передают отмену контроллеру.

В навыках и MCP локальный `tab(reverse)` обходит области панели и возвращает `false` на границе, чтобы Settings передал фокус следующей области. Полоса навыков переключается ←/→; действия используют общую модель `MenuAction`. Выбор для задачи, создание и изменение выполняются после закрытия Settings. Отложенный переход выполняется только после успешного завершения записей. Закрепление применяется сразу и не считается несохранённой формой.

## Владелец и границы

При открытии Settings приложение захватывает workspace root, контроллер беседы и его generation. MCP создаётся для исходного root; действия навыков проверяют исходную generation. Перед подготовкой сообщения повторно проверяется владелец, затем читается каталог или исходник навыка. Устаревший выбор показывает ошибку и не пишет в другую беседу. Ошибка чтения после закрытия настроек также выводится в чат.

Просмотр не вызывает модель и не выполняет MCP tools. Подключение, диагностика и добавление MCP сервера выполняются явными действиями. Секреты остаются в прежнем защищённом хранилище; поля показывают только маску и не получают ввод при скрытой панели. Незавершённые формы установки MCP действуют до закрытия Settings; установка, доверие и запуск остаются явными действиями. Остальные параметры сохраняются автоматически.

## Атомарная запись на Windows

Native-сценарий обнаружил `EPERM` при замене config, одновременно читаемого проверкой. Общее `replaceAtomicFile` в `utils/atomic-file.ts` повторяет только rename того же временного файла при Windows `EPERM/EACCES/EBUSY`, с прежним пределом session storage в 2 секунды и проверкой владельца перед каждой попыткой. Старый файл не удаляется. Сохранение config и MCP используют этот helper; `replaceSessionFile` остаётся совместимым именем для session callers. Сериализация обновлений, revision и доверие не меняются. Постоянная блокировка возвращает ошибку, а не успех.

## Адаптация размеров

Панель рассчитывает строки из доступной области, учитывая заголовок, состояние, действия и уведомление. На узком экране библиотека показывает список; инструкции, описание и источник доступны через действие «Инструкции». Малый размер не пересоздаёт native input и сохраняет курсор. Для tiny-dialog используется непрозрачный фон, чтобы символы лежащего позади чата не мешали чтению; структура renderables при resize остаётся стабильной.

Публичный SDK и engine protocol не меняются. Расширения, Web, LSP, фоновые задачи и помощники уже имели встроенные панели и сохраняют своё размещение.

## Единое меню LSP

В текущих исходниках LSP использует тот же `OpenTuiLspSettings` при входе через панель, F9 и Settings. Внутренний `lspUiTarget` запрашивает у оболочки маршрут `tools.lsp`; отдельный generic view `analysis` удалён. Переключатели сохраняются узкими patches сразу, валидная ручная форма — автоматически. Черновик остаётся при поиске, возврате к списку, переключении раздела и resize. [Семантика и контракт записи](lsp-menu.md), [проверки и кадры](../contributors/reports/lsp-menu.md).

Общий [контракт фокуса и именованных действий](menu-navigation.md) определяет компактную строку, обработку Enter/Space и сохранение владельца ввода.

[Очередь автосохранения и подключения](settings-autosave.md) описывает актуальный контракт записи.
