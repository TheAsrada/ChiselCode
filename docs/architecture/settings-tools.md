# MCP и навыки внутри Settings

[Документация](../README.md) · [Архитектура](../architecture.md) · [Кадры и проверки](../contributors/reports/settings-tools.md)

Статус: принято, Unreleased после 0.6.33.

## Причина и решение

Ранее выбор MCP или навыков в Settings открывал второй modal поверх настроек. Пользователь терял связь между разделом и его управлением, хотя остальные инструменты уже отображались внутри Settings. Размеры, каталог, поиск и навигация общей оболочки сохранены. Меняется размещение содержимого двух разделов.

`OpenTuiMcp` и `OpenTuiSkills` поддерживают встроенное размещение через `OpenTuiToolPane`. Панель использует размер области содержимого без дополнительного backdrop, рамки и отступов modal. При вызове `/mcp` или `/skills` тот же компонент использует `OpenTuiDialog`. Контроллер MCP, каталог навыков, правила, доверие, отмена и хранение данных общие для обоих способов открытия.

## Жизненный цикл и ввод

Settings загружает MCP при первом посещении раздела. Посещённые панели остаются смонтированы: переход сохраняет форму, текущий экран, поиск и выбор. Общий `SettingsPanelControl` находится в отдельном модуле; `save`, `back` и `discard` используются всеми встроенными панелями.

`active` разрешает обработку событий только выбранной панели без подтверждения поверх неё; `focused` дополнительно ограничивает клавиатуру и native inputs областью содержимого. Ctrl+F, Tab, Escape, Ctrl+S и F2 принадлежат Settings. MCP сообщает о незавершённой форме, изменённых категориях разрешений и выполняемой операции через `onDirty`. Закрытие сохраняет существующий диалог выбора действия. Ctrl+C и первый Escape во время MCP-проверки передают отмену контроллеру.

В навыках Alt+1/2 переключает библиотеку и закрепление, освобождая Tab для навигации Settings. Выбор для задачи, создание и изменение выполняются после закрытия Settings. «Остаться» и возврат к сохранению формы очищают отложенный переход; обычное последующее закрытие не должно неожиданно менять черновик. Закрепление применяется сразу и не считается несохранённой формой.

## Владелец и границы

При открытии Settings приложение захватывает workspace root, контроллер беседы и его generation. MCP создаётся для исходного root; действия навыков проверяют исходную generation. Перед подготовкой сообщения повторно проверяется владелец, затем читается каталог или исходник навыка. Устаревший выбор показывает ошибку и не пишет в другую беседу. Ошибка чтения после закрытия настроек также выводится в чат.

Просмотр не вызывает модель и не выполняет MCP tools. Подключение, диагностика и сохранение выполняются прежними явными действиями. Секреты остаются в прежнем защищённом хранилище; поля показывают только маску и не получают ввод при скрытой панели. Черновики действуют до закрытия Settings и не записываются в конфигурацию автоматически.

## Адаптация размеров

Панель рассчитывает строки из доступной области, учитывая заголовок, состояние, действия и уведомление. На узком экране библиотека показывает список; инструкции, описание и источник доступны через Ctrl+O. Малый размер не пересоздаёт native input и сохраняет курсор. Для tiny-dialog используется непрозрачный фон, чтобы символы лежащего позади чата не мешали чтению; структура renderables при resize остаётся стабильной.

Публичный SDK и engine protocol не меняются. Расширения, Web, LSP, фоновые задачи и помощники уже имели встроенные панели и сохраняют своё размещение.
