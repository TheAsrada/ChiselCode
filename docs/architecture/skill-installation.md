# Установка внешних навыков

[Архитектура](../architecture.md) · [Навыки для пользователя](../skills.md)

Статус: принято, включено в [CLI 0.6.42](../contributors/reports/release-0.6.42.md). Навык является пакетом инструкций и файлов в существующей библиотеке ChiselCode. Установка не создаёт второй runtime плагинов и не исполняет внешний установщик.

## Границы компонентов

| Компонент | Ответственность |
| --- | --- |
| `skills/source.ts` | Разбор URL, `owner/repo` и ограниченного формата `npx skills add` в данные источника; отказ shell-операторам и неизвестным флагам |
| `skills/remote.ts` | Разрешение публичного GitHub snapshot или прямого Markdown; загрузка только выбранного поддерева |
| `skills/package.ts` | Проверка portable paths, состава, размеров и metadata; вычисление SHA-256 пакета |
| `skills/library.ts` | Общий lock библиотеки, проверка конфликтов, скрытый staging и атомарная публикация готовой папки |
| `tools/local/skill-sources.ts` | Тонкие handlers `inspect_skills` и `install_skill` в общем ToolExecutor |
| `skills/references.ts` | Чтение ограниченного UTF-8-файла внутри каталога навыка без выполнения скриптов |

`RemoteSkills` получает общий `SafeWebHttpClient` из composition root. Транспорт учитывает proxy, CA, TLS, проверку URL/DNS/IP, redirects, отмену и пользовательские пределы Web. Все обращения требуют выданный executor сетевой capability; разрешение не создаётся внутри установщика. GitHub commit/tree/blob читаются через один домен `api.github.com`, поэтому подтверждение одного хоста не превращается в разрешение на другие хосты. Credentials GitHub из среды автоматически не подключаются.

## Порядок операции

`prepare` разбирает запрос и формирует конкретное превью источника, выбранного навыка и центральной библиотеки. До разрешения сети и записи HTTP-запросов нет. `inspect_skills` имеет effect `external_read`, `install_skill` — `library_write`: Plan допускает просмотр и блокирует установку, Accept edits не разрешает глобальную запись автоматически. Инструменты имеют source `skill`; действующая политика помощников не выдаёт им доступ к глобальной библиотеке.

Для GitHub сначала определяется SHA коммита, затем дерево и пути `SKILL.md`. Явная папка разрешается через shallow trees, после чего рекурсивно читается только её поддерево. Неоднозначность возвращает список без установки. `revision` позволяет установить тот же коммит, который был просмотрен. Содержимое каждого файла сверяется с Git blob SHA из дерева; до четырёх загрузок идут параллельно, при ошибке остальные отменяются и завершаются перед возвратом результата. GitHub API quotas продолжают действовать, массового автоматического повтора нет.

Проверка пакета завершается до публикации. Lock `.library.lock` общий с `create_skill` и удерживается только на время локального изменения библиотеки. Сетевые native handlers узнаются по идентичности в WeakSet и не удерживают проектную write lease во время скачивания; поддельное имя инструмента эту льготу не даёт. Собственный скрытый staging удаляется при ошибке или отмене. Межпроцессный lock координирует штатных писателей ChiselCode; перед rename повторно проверяется отсутствие назначения. Это не системная песочница против другого процесса, произвольно меняющего файловую систему.

Установщик сохраняет receipt с источником, revision, путём `SKILL.md`, digest и составом пакета. Идемпотентность проверяется по фактическим файлам, а не только receipt. Правки, ссылки, лишние файлы или конфликт имени сохраняют существующую папку и останавливают установку. Автообновление, перезапись и garbage collection пользовательских навыков в этот контракт не входят.

## Видимость и инструкции

В production `load_skill` получает функцию чтения актуального каталога. Результат установки содержит фактическое имя из frontmatter, так что следующий вызов в том же AgentRuntime может загрузить инструкции и относительную справку. Новый запрос заново собирает каталог системного промпта. Открытая библиотека поддерживает штатный Ctrl+R; установка не меняет закрепление.

External metadata и файлы не дают разрешений. Frontmatter `allowed-tools` не становится allowlist установки; сохраняются `user-invocable` и `disable-model-invocation`. Установка сама по себе не загружает инструкции в контекст модели. Системное правило требует штатный установщик и запрещает обход неподдерживаемого источника или сетевого отказа через shell. Дополнительный источник в будущем должен реализовать такое же разрешение snapshot и подготовку `SkillPackage`, сохраняя общий validator, publisher и permission flow.

## Проверки

`skill-source.test.ts` входит в быстрый профиль и проверяет разбор недоверенного ввода и границы пакета. `skill-install-runtime.test.ts` проверяет настоящий executor с локальным HTTP fixture: разрешения до сети, snapshot, выбор, конфликты, бинарные данные, отмену, SSRF redirect и последовательность install → load → reference в AgentRuntime. Файл выполняется также в platform subset Windows/macOS. `skill-install-cli.ts` проверяет установленную и compiled-поставку через обычные HTTPS, TLS и proxy с изолированной библиотекой; это короткий smoke, без повторения всего source-набора.
