# Web без внутренних квот

[Документация](../README.md) · [Архитектура](../architecture.md#native-web) · [Пользовательская справка](../web.md) · [Проверки](../contributors/reports/web-search.md)

Статус: принято, текущие исходники после 0.6.35.

## Причина и решение

Ранее Web учитывал вызовы инструментов и HTTP-запросы двумя независимыми счётчиками. В предел 24 запроса за ход попадали также MCP handshake, discovery и redirects. Несколько поисков могли исчерпать бюджет до завершения задачи. Общий limiter добавлял предел 120 HTTP-запросов в минуту, задержку между стартами и отдельную очередь параллельности.

Эти механизмы удалены из provider и HTTP transport, включая process maps и ожидание токенов limiter. Web использует общий планировщик инструментов; подключения ограничены сроком жизни запроса и отменяются через AbortSignal. Старые `maxRequestsPerTurn` и `maxConcurrent` удаляются preprocess-миграцией при чтении user/project config и не записываются обратно. Остальные поля проходят прежнюю строгую валидацию; разрешения, credentials и неизвестные глобальные настройки сохраняются.

## Поиск из коробки

Стандартный Auto использует фиксированные официальные сервисы Exa и Parallel без регистрации; настроенный ключ Brave добавляет его первым. Пустой успешный ответ завершает поиск. При ошибке сервиса роутер может обратиться к следующему разрешённому кандидату, не более одного раза к каждому и в пределах общего timeout. Последний успешно ответивший backend получает приоритет до пересоздания provider. При его отказе остальные кандидаты снова доступны. Это не постоянный blacklist и не повтор неудачной операции по таймеру.

Eligibility заново рассчитывается по выданной executor capability. Изменение приоритета не выдаёт новых полномочий: deny, SSRF, HTTP 403 и отмена останавливают выполнение. Routing и фактический provider сохраняются в результате. Явный выбор сервиса остаётся явным: Auto не включается вместо пользовательского Brave/Exa/Parallel и не заменяет Ask/Deny.

Фиксированные публичные endpoints используют поддерживаемый `initialize` через официальный SDK в режиме legacy negotiation. Спекулятивный `server/discover`, на который оба сервиса отвечали HTTP 400, больше не отправляется. Общий менеджер пользовательских MCP-серверов сохраняет собственное согласование протокола. Search client по-прежнему закрывается после вызова; протокол и сервисные ответы не становятся инструментами модели.

## Сохранённые границы

Квоты внешнего сервиса определяются его владельцем. Auto переключает разрешённый сервис при соответствующем отказе, но не гарантирует безлимитный внешний доступ. Нет ротации IP, ключей или обхода отказов доступа.

Сохранены TLS, публичные DNS/IP, проверка каждого redirect, scoped credentials, permissions, конечные connection/request deadlines и пределы размера ответа/DOM. Эти проверки защищают чтение и cleanup; число запросов за ход они не считают. Большой вывод и источники сохраняются прежним механизмом artifacts и истории.

## Чтение страниц и диагностика — 0.6.39

`SafeWebHttpClient` сохраняет прежние HTTP error codes, `retryable` и Retry-After, добавляя hostname и понятное объяснение отказа. Raw error body не включается в сообщение. Fetch не делает автоматических повторов 401/403/451, не меняет credentials или transport и не блокирует весь hostname после отказа одного пути: другая публичная страница того же сайта остаётся доступна.

Extractor различает ограничение размера и ограниченное статическое содержимое. После удаления scripts/navigation он проверяет наличие текста вне заголовков и ссылок. Если исходный HTML содержит scripts, а в выбранном теле остались только заголовки или ссылки, optional `WebDocument.warnings` получает `limited_static_content`. Короткие содержательные страницы не отклоняются. Provider сохраняет warning в source metadata, кеше и durable result и добавляет объяснение перед текстом. Это консервативная диагностика, не распознавание любой JS-страницы или paywall.

Общая нормализация результатов использует `utf8Prefix` из `utils/text`, а сокращение краткой причины ошибки — `clipText`; byte/token budgets не режут кодовую точку. Прежний экспорт helper из `models/context` сохранён. Raw результат, trust metadata и `read_tool_result` не изменены. [Воспроизведение и проверки](../contributors/reports/web-fetch-diagnostics.md).

## Рассмотренные варианты

Увеличение лимита оставило бы тот же отказ после большего числа запросов и неоднозначность двух счётчиков. Отключение всех защит вместе с квотами открыло бы приватную сеть и неограниченную загрузку данных. Собственный scraping поисковых страниц добавил бы зависимость от HTML, CAPTCHA и пользовательских cookies. Выбраны удаление внутренних квот и официальные публичные API с проверяемым failover.
