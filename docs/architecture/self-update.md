# Перезапуск при обновлении Windows

[Документация](../README.md) · [Архитектура](../architecture.md) · [Установка](../installation.md) · [Проверки](../contributors/reports/windows-update.md)

Статус: принято, исходники 0.6.35.

## Причина и решение

Ранее `/update` запускал NSIS до завершения приложения. После cleanup общий CLI-путь мог ожидать Enter: явно заданный `--pause` или запуск через Explorer. Исполняемый файл оставался занят, установщик исчерпывал 20 попыток по 500 мс и переходил к удалению при перезагрузке. Пауза на стороне клиента и повтор замены файла не образовывали согласованный протокол.

`runOpenTuiAgent` возвращает `InteractiveExitReason`. Значение `update` появляется только после успешной передачи установщику и завершения всех application/extension/terminal cleanup. CLI вызывает `completeInteractiveExit`: для обновления завершает процесс с кодом 0, освобождая EXE и оставшиеся handles; для обычного выхода сохраняет прежнюю политику паузы. При ошибке launch причина `update` не выдаётся: проверенный файл остаётся для повторной попытки. Ошибка cleanup также не маскируется успешным выходом.

## Контракт установщика

Клиент передаёт `/S`, проект, необязательный ID сохранённой сессии, PID текущего процесса и фактический каталог установленного EXE. `spawn` выполняется без shell. Значения NSIS имеют вид `key="value"`; `/D=` идёт последним без кавычек, как требует NSIS. Метасимволы пути не становятся командами оболочки.

Общий `installer/update.nsh` используется основным установщиком и изолированным Windows regression. Установщик открывает один process handle и ждёт выхода до 60 секунд. Уже завершившийся процесс допустим; ошибка доступа и таймаут останавливают установку. Убийство других экземпляров и удаление EXE при перезагрузке не используются.

Новый EXE сначала извлекается в файл рядом с целевым. `ReplaceFileW` заменяет прежний файл с резервной копией; при sharing violation сохраняется прежний EXE. Прежний предел повторов замены — 20 попыток с 500 мс между ними. При отказе временный файл удаляется, исчезнувший target восстанавливается из backup. Завершение с ошибкой возвращает ненулевой exit code и не запускает старую копию как результат обновления.

После успешной установки `ExecShell` открывает консольное приложение через Windows Shell. Новый процесс получает собственный терминал вместо ignored stdio установщика. Проект и сессия передаются отдельно; `\.` в конце пути сохраняет Windows root и trailing backslash при разборе argv.

## Диагностика и границы

`update.log` рядом с установленным EXE хранит версию и этапы `waiting`, `installed`, `success` либо короткую причину `failed`. Формат — UTF-16LE, размер чтения ограничен 64 КиБ. При следующем запуске установленного Windows CLI прежний сбой виден в уведомлении и `/update`, независимо от успеха проверки GitHub. Секреты, текст сессии и API-запросы в журнал не записываются.

Проверка release metadata, SHA-256, streaming download, отмена и запрет перезапуска при активном запросе/очереди сохраняются. macOS/Linux используют прежнюю ручную установку. Клиент, уже установленный до исправления, продолжает исполнять старую логику паузы; для перехода с зависающего выпуска нужен однократный запуск нового установщика вручную.
