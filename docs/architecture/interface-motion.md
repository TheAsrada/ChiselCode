# Визуальная система и анимации OpenTUI

[Архитектура](../architecture.md) · [Темы и анимации](../themes.md) · [Исследование и кадры](../contributors/reports/interface-design.md)

Решение принято 24 октября 2026 года для текущих исходников после CLI 0.6.40. Опубликованный tag 0.6.40 сохраняет прежний интерфейс. Реализация использует установленный OpenTUI 0.5.12 и React; backend инструментов, разрешений и SDK не заменяется визуальными компонентами.

## Поверхности и иерархия

Существующая `Palette` остаётся контрактом цветов, включая темы расширений. Фон отделён от поверхности формы и поднятой поверхности выделения. Акцент показывает фокус и активное действие; предупреждения и ошибки сохраняют собственные цвета. Цветовые переходы вычисляются из выбранной палитры.

Главная сохраняет Coder Mini, центрированный ввод и горячие клавиши. На достаточной площади рядом с вводом доступны переходы в модель, историю и настройки. Композер использует верхнюю и левую границы, явный черновик, режим, разрешения и заметную отправку. На узком экране приоритет получают текст и режим доступа. Вкладки бесед используют активную нижнюю линию и отдельный индикатор работы; закрытие имеет увеличенную область попадания.

Ширина обычных сообщений ограничена 104 клетками. Diff, таблицы действий и панели сохраняют свои viewport. Markdown продолжает строиться по source offsets: готовые блоки сохраняются во время streaming.

## Владелец времени

Один `MotionClock` принадлежит `OpenTuiMotion` в корне приложения. Список tasks содержит только текущие цветовые переходы и индикаторы. Таймер с шагом 32 мс создаётся при первой задаче и удаляется после последней; unmount корня очищает все задачи и запрещает позднюю регистрацию. Завершившаяся или отменённая задача удаляется в том же кадре.

Локальные hooks обновляют небольшой control либо индикатор. Потоковый текст, редактор и весь экран не подписаны на animation clock. Собственный clock выбран для React 0.5.12: актуальные custom renderables OpenCode используют другой native API, переносить их напрямую в этот runtime нельзя.

| Элемент | Поведение |
| --- | --- |
| Вторичное действие | 140 мс, cubic ease-out между цветами поверхности |
| Диалог | 160 мс, появление затемнения и тени на неизменной позиции |
| Индикатор вкладки / узкого статуса | Braille-кадр раз в 80 мс |
| Широкая строка запроса | Световая полоса с циклом 1400 мс; это неопределённая активность, а не процент выполнения |
| Ожидание разрешения | Статический жёлтый маркер; сообщение и elapsed остаются доступны |
| Завершение / закрытие | Сразу передаёт управление следующему состоянию |

Основные и заблокированные кнопки меняют цвет сразу, сохраняя читаемость. Нажатие доступно с первого кадра появления окна. Entrance выполняется один раз: изменение настройки движения не запускает повторное затемнение уже открытого окна. Геометрия и hit areas сохраняются при переходах.

## Настройка пользователя

Глобальный `ui.motion` принимает `full` и `reduced`; отсутствие поля выбирает `full`. **Настройки → Внешний вид → Тема**, кнопка «Анимации» и M переключают значение. Настройка сохраняется сразу через ту же последовательную запись глобальной конфигурации, что тема; merge сохраняет остальные UI-поля и профили. При отказе записи предыдущий режим остаётся активным и показывается ошибка.

В `reduced` исчезают цветовые переходы и периодическое движение, animation tasks освобождаются. Остаются текстовые статусы, elapsed, управление мышью и клавиатурой. Для колеса используется штатное ускорение `MacOSScrollAccel` с ограничением multiplier; reduced выбирает линейную прокрутку. Drag, selection, sticky scroll и keyboard scrolling принадлежат native ScrollBox.

## Поиск и исполнение меню

`SidebarMenu` фильтрует зарегистрированные действия по словам названия, описания, раздела и shortcut. `/` или мышь фокусируют native input. Цифры и скобки в поиске вводят текст; вне поиска они сохраняют навигационные сочетания панели. Enter и Space открывают выбранный пункт через существующий callback. Нажатие не передаётся новому диалогу или композеру.

Выбор хранится по ID. Исчезнувший пункт расширения не подменяется другой командой; пользователь выбирает новый. Ввод и overlay по-прежнему захватывают owner/revision. Строки используют `DialogAction` с проверкой press/release, resize, drag и selection. Поиск и переходы не вызывают модель.

## Проверки

`motion.test.ts` проверяет освобождение clock, отмену задачи в текущем кадре, запрет работы после dispose и совместимость config. `opentui-motion.test.tsx` проверяет native renderer, переключение full/reduced, unmount, отказ сохранения, владение поиском и Enter.

Production fixture `tui-ui-design.ts` запускает обычный `runOpenTuiAgent` с настоящим SDK и локальным endpoint. Проверяет запись настройки, Unicode draft/cursor и identity редактора при resize, реальные изменения цветов полосы и кадров индикатора, получение ответа, поиск и отсутствие генераций от меню. Source wrapper выполняется один раз в Linux full suite; compiled fixture проверяет native поставку на трёх ОС. Результаты конкретного source и ограничения физического терминала находятся в [отчёте](../contributors/reports/interface-design.md).
