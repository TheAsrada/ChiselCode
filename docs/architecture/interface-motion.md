# Визуальная система и анимации OpenTUI

[Архитектура](../architecture.md) · [Темы и анимации](../themes.md) · [Исследование и кадры](../contributors/reports/interface-design.md)

Визуальная система впервые выпущена в [CLI 0.6.41](../contributors/reports/release-0.6.41.md). Ниже описаны текущие исходники. Интерфейс использует OpenTUI 0.5.12 и React. Выполнение инструментов и разрешения принадлежат runtime.

## Поверхности и иерархия

Существующая `Palette` остаётся контрактом цветов, включая темы расширений. Фон отделён от поверхности формы и поднятой поверхности выделения. Акцент показывает фокус и активное действие; предупреждения и ошибки сохраняют собственные цвета. Цветовые переходы вычисляются из выбранной палитры.

Главная показывает Coder Mini, центрированный ввод и горячие клавиши. Исходная сетка 76×5 задаёт изображение 76×10, в котором каждая половина ячейки соответствует одному пикселю. OpenTUI выбирает протокол по возможностям терминала. В узком окне используется текстовая подпись. На достаточной площади рядом с вводом доступны переходы в модель, историю и настройки. Композер использует верхнюю и левую границы, явный черновик, режим, разрешения и заметную отправку. На узком экране приоритет получают текст и режим доступа. Вкладки бесед используют активную нижнюю линию и отдельный индикатор работы; закрытие имеет увеличенную область попадания.

Ширина обычных сообщений ограничена 104 клетками. Diff, таблицы действий и панели сохраняют свои viewport. Markdown продолжает строиться по source offsets: готовые блоки сохраняются во время streaming. Отступ между ответами задаётся лентой; самостоятельный `FormattedMessage` по умолчанию не добавляет пустую строку.

## Владелец времени

Один `MotionClock` принадлежит `OpenTuiMotion` в корне приложения. Список tasks содержит только текущие цветовые переходы и индикаторы. Таймер с шагом 32 мс создаётся при первой задаче и удаляется после последней; unmount корня очищает все задачи и запрещает позднюю регистрацию. Завершившаяся или отменённая задача удаляется в том же кадре.

Локальные hooks обновляют небольшой control; периодические индикаторы пишут кадр непосредственно в native `TextRenderable.content`, без React state на каждый tick. Потоковый текст, редактор и весь экран не подписаны на animation clock. Собственный clock выбран для `@opentui/react` 0.5.12: актуальные custom renderables OpenCode используют другой native API, переносить их напрямую в этот runtime нельзя.

| Элемент | Поведение |
| --- | --- |
| Вторичное действие | 140 мс, cubic ease-out между цветами поверхности |
| Диалог | 160 мс, появление затемнения и тени на неизменной позиции |
| Индикатор вкладки | Braille-кадр раз в 80 мс |
| Строка запроса | Пять фиксированных клеток. Волна ожидания, орбита рассуждения, сборка вызова, сканирование при чтении, штрих при записи, пульс курсора при команде и ответе |
| Смена действия | Подпись обновляется сразу. Переход между значками занимает 180 мс на той же позиции |
| Ожидание разрешения | Статический жёлтый маркер; сообщение и elapsed остаются доступны |
| Завершение / закрытие | Сразу передаёт управление следующему состоянию |

Основные и заблокированные кнопки меняют цвет сразу, сохраняя читаемость. Нажатие доступно с первого кадра появления окна. Entrance выполняется один раз: изменение настройки движения не запускает повторное затемнение уже открытого окна. Геометрия и hit areas сохраняются при переходах.

## Первый запуск

`StartupIntro` раскрывает Coder Mini переливом акцентов пяти встроенных тем и возвращает надпись к цвету выбранной палитры. Боковые волны идут с небольшим сдвигом и дают мягкий повторный импульс на спаде. Частицы стартуют в штрихах букв и расходятся во все стороны. После 3200 мс на том же `TextRenderable` появляется пульсирующая подсказка «Press any key», а частицы продолжают движение. При resize координаты пересчитываются, фаза сохраняется. Первый ввод после подсказки открывает «Подключения» и освобождает задачу интро. Акцент рамки затихает за 300 мс. Настройки загружаются во время интро, редакторы и действия принимают ввод с первого видимого кадра формы. В `reduced` сразу рисуется статичный кадр, задача анимации не создаётся. При переходе между обычными разделами и на главную меняется цвет поверхности при неизменной геометрии. Предпросмотр темы применяет новую палитру сразу.

## Состояния активного запроса

`RequestActivityTracker` принадлежит контроллеру беседы и хранит текущий запрос. `provider_request_started` выбирает «Запрашиваю модель» или «Жду продолжения» по последнему сообщению, отправляемому в API. Второй статус требует результата инструмента в этом сообщении. Сигнал рассуждения, текст ответа и начало сборки вызова меняют статус на «Думаю», «Пишу ответ» и «Собираю вызов».

ChatGPT сообщает начало рассуждения через `response.output_item.added` для элемента `reasoning`, Anthropic через `content_block_start` для блока `thinking`. Драйверы проецируют их в `thinking_start`, runtime передаёт событие `provider_thinking_delta` без текста. Уже поддерживаемые текстовые фрагменты тоже переключают статус. OpenTUI отображает подпись состояния, а поток текста рассуждения в ленту не добавляется.

Сжатие показывает «Готовлю контекст». Вид выполняемого инструмента определяется доверенным именем и `ToolSource`. `run_shell` показывает «Выполняю команду», диагностика встроенного LSP — «Проверяю код». Сторонние инструменты получают общую подпись.

Вызовы хранятся по `invocationId`, отдельно от проекции карточек в ленте. В счётчик исполнения входят только начавшиеся вызовы. Завершение удаляет только свой вызов; одинаковые виды сохраняют значок, смешанные показывают число действий. Подтверждение имеет приоритет над работающими инструментами; ошибка запроса и остановка — над обычной активностью. Новая операция сбрасывает проекцию, завершение убирает строку, поздние события после отмены не оживляют её. Переключение вкладки сохраняет состояние её контроллера; история сообщений модели не меняется.

`OpenTuiRequestStatus` слушает события контроллера, а кадры пишет только в свой `TextRenderable`. Переход начинается с текущего видимого значка. Подпись остаётся однотонной в течение анимации. Ширина ограничена 44 клетками, таймер занимает фиксированную правую область. На узком экране используются три клетки и короткая подпись. Подтверждение, ошибка, остановка и `reduced` освобождают задачу анимации, локальный таймер обновляет время раз в секунду. Unmount освобождает оба источника обновлений.

## Настройка пользователя

Глобальный `ui.motion` принимает `full` и `reduced`; отсутствие поля выбирает `full`. **Настройки → Внешний вид → Тема**, кнопка «Анимации» и M переключают значение. Настройка сохраняется сразу через ту же последовательную запись глобальной конфигурации, что тема; merge сохраняет остальные UI-поля и профили. При отказе записи предыдущий режим остаётся активным и показывается ошибка.

В `reduced` исчезают цветовые переходы и периодическое движение, animation tasks освобождаются. Остаются текстовые статусы, elapsed, управление мышью и клавиатурой. Для колеса используется штатное ускорение `MacOSScrollAccel` с ограничением multiplier; reduced выбирает линейную прокрутку. Drag, selection, sticky scroll и keyboard scrolling принадлежат native ScrollBox.

## Поиск и исполнение меню

`SidebarMenu` фильтрует зарегистрированные действия по словам названия, описания, раздела и shortcut. `/` или мышь фокусируют native input. Цифры и скобки в поиске вводят текст; вне поиска они сохраняют навигационные сочетания панели. Enter и Space открывают выбранный пункт через существующий callback. Нажатие не передаётся новому диалогу или композеру.

Выбор хранится по ID. Исчезнувший пункт расширения не подменяется другой командой; пользователь выбирает новый. Ввод и overlay по-прежнему захватывают owner/revision. Строки используют `DialogAction` с проверкой press/release, resize, drag и selection. Поиск и переходы не вызывают модель.

## Команды на главной

Главная не рендерит transcript и не содержит область feedback под вводом. Её контроллер направляет ошибки и предупреждения из `append` и `appendNotice` в отдельное состояние `commandFeedback`, а успешные служебные уведомления отбрасывает; контроллеры разговоров сохраняют прежнюю ленту. Это единая граница для неизвестных команд, ошибок аргументов, путей и расширений. `/status` и `/doctor` удалены из slash registry и application dispatch, их дашборд удалён. `/cwd` без аргументов готовит путь в редакторе с курсором после пробела.

Сообщение открывается в общем Dialog с прокруткой и закрытием, затем освобождается. Ownership включает conversation, generation и ID результата: старое закрытие не стирает новый вывод. Ввод и paste за окном заблокированы; Ctrl+C закрывает сообщение без отмены чужой работы. Approval и уже открытый диалог имеют приоритет, смена проекта очищает feedback. `/worktree` сохраняет свой графический менеджер; ошибки парсинга на главной используют ту же общую границу. Реальные операции и их проверки разрешений остаются в backend.

## Проверки

`motion.test.ts` проверяет освобождение clock, отмену задачи в текущем кадре, запрет работы после dispose и совместимость config. `opentui-motion.test.tsx` проверяет native renderer, переключение full/reduced, unmount, отказ сохранения, владение поиском и Enter.

Production fixture `tui-ui-design.ts` запускает обычный `runOpenTuiAgent` с реальным SDK и локальным endpoint. Проверяет запись настройки, черновик и курсор при resize, рассуждение, сборку вызова, параллельное чтение и поиск, подтверждённую запись лендинга и shell-команду, ожидание продолжения, потоковый ответ и отсутствие генераций от меню. Source wrapper выполняется один раз в Linux full suite. Compiled fixture проверяет поставку на трёх ОС. Чистая проекция входит в быстрый профиль, native unit tests проверяют состояния и освобождение таймеров.
