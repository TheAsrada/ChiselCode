# Потоковые ответы провайдеров

[Документация](../README.md) · [Архитектура](../architecture.md#provider-architecture) · [Подключение модели](../providers.md) · [Решение проблем](../troubleshooting.md#ошибка-chunkchoices0-или-некорректное-событие-провайдера)

Исправление вошло в [CLI 0.6.37](https://github.com/TheAsrada/ChiselCode/releases/tag/v0.6.37). [Проверки выпуска и опубликованных файлов](../contributors/reports/release-0.6.37.md).

## Причина сбоя

`OpenAIProtocolAdapter` получал из SDK тип `ChatCompletionChunk` и без проверки читал `chunk.choices[0]`. SDK разбирает SSE и JSON, но не проверяет соответствие объекта TypeScript-типу. Совместимый сервис может прислать отдельный usage без `choices`. Даже после корректного ответа и `finish_reason` такой пакет вызывал дословно `undefined is not an object (evaluating 'chunk.choices[0]')` и превращал весь запрос в ошибку `unknown`.

Минимальный поток, воспроизведённый через настоящий SDK до исправления:

```text
data: {"choices":[{"index":0,"delta":{"content":"Привет"}}]}

data: {"choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}

data: {"usage":{"prompt_tokens":19,"completion_tokens":7}}

data: [DONE]
```

Второй воспроизведённый сбой — `choice.delta.refusal` при завершающем событии без `delta`. В Anthropic-драйвере аналогичные предположения существовали для `message`, `usage`, `content_block` и `delta`. Проверка только наличия `choices` не защищала остальные обращения и могла бы скрыть ответ другого API.

## Граница протокола

`src/providers/stream-validation.ts` принимает `unknown` и проверяет потребляемую структуру через Zod. Схемы создаются один раз при загрузке модуля. SDK сохраняет ответственность за HTTP, SSE, UTF-8, отмену и API-ошибки; драйвер отвечает за форму и последовательность событий, сборку текста, счётчиков и инструментов. `TurnRunner`, история, интерфейс и разрешения используют прежний контракт.

| Входящий пакет | Обработка |
| --- | --- |
| OpenAI usage с отсутствующими/null `choices` | Обновить счётчики, продолжить поток |
| OpenAI `choices: []`, в том числе `usage: null` | Служебный пакет, без обращения к элементу массива |
| OpenAI `finish_reason` без/null `delta` | Пустая terminal delta; сохранить накопленный текст и инструменты |
| JSON heartbeat `{ "type": "ping" }` или `{ "type": "heartbeat" }` | Продолжить без изменения ответа; дополнительные содержательные поля не игнорируются |
| Частичный usage | Дополнить предыдущие числовые счётчики; не обнулять отсутствующие поля |
| Anthropic `message_delta` без usage | Сохранить предыдущий usage и принять stop reason |
| Дополнительные поля метаданных | Сохранить совместимость; не проецировать их в core |
| Неизвестные Anthropic block/delta types | Оставить непрозрачными; не превращать в текст или tool call |
| Неверные типы `choices`, `delta`, текста, аргументов или счётчиков | Ошибка `transport` до завершения ответа |
| Содержательное событие другого API без ожидаемой структуры | Ошибка совместимости; не пропускать его как heartbeat |

Диагностика структуры содержит название протокола и путь к полю. Исходные значения ответа в неё не подставляются. Невалидный JSON также нормализуется в `transport`. API-ошибки сохраняют сообщение и существующую классификацию сервиса; проверка формы не объявляет их успешным ответом и не создаёт дополнительных запросов.

## Завершение и инструменты

Драйвер собирает tool calls во временном состоянии. Он выдаёт их только после окончания потока, проверки terminal marker, имён/ID и полного JSON аргументов. Повреждение любого последующего события отменяет весь незавершённый ответ; подготовленный ранее фрагмент не достигает scheduler.

OpenAI требует `finish_reason`; `[DONE]` сам по себе его не заменяет. После finish допускаются служебные usage/heartbeat, но новые текст, reasoning, refusal и tool fragments отклоняются. Anthropic требует `message_start` и `message_stop`, запрещает повторный start, данные после terminal и delta для неизвестного или явно закрытого блока. Эти проверки действуют для обычного агента и запросов расширений.

После завершения итерации повторно проверяется AbortSignal: SDK может закончить итератор при отмене без исключения. Такая ситуация остаётся `cancelled`; она не становится успешным ответом или ошибкой отсутствующего marker. Последний корректный usage сохраняется и при неудачном запросе.

## Исходящие запросы и непрозрачные HTTP-ошибки

В текущих исходниках `openai-chat` не отправляет пустые `tools` и `tool_calls`: строгий Chat Completions endpoint может отвергать пустой массив. Сообщение ассистента без инструментов передаётся только с текстом. В смешанном пользовательском сообщении результаты инструментов сериализуются перед текстом пользователя, чтобы между вызовами ассистента и всеми соответствующими `role: tool` не появлялась другая роль. Исходная история и ошибки инструментов сохраняются.

HTTP 400 с телом только `data: [DONE]` распознаётся в диагностике отдельно. Он остаётся `bad_request` со статусом 400; SDK не передаёт такое тело в успешный SSE-парсер. Клиент не знает скрытую причину отказа и не угадывает параметры для повтора. Совместимые повторы для `stream_options` или лимита токенов по-прежнему требуют указания соответствующего параметра в ошибке. `[DONE]` в HTTP-ошибке и отсутствие `finish_reason` в успешном HTTP-потоке — разные сбои.

Эти изменения вошли в [CLI 0.6.40](../contributors/reports/release-0.6.40.md). [Разбор разговора](../contributors/reports/provider-client-diagnostics.md) содержит воспроизведение клиентских ошибок и ограничения выводов о шлюзе.

## Проверки

`tests/unit/provider-stream-events.test.ts` использует настоящие OpenAI/Anthropic SDK с SSE Response, разбитым на семибайтные фрагменты, включая UTF-8. Проверяются оба исходных сбоя, служебные пакеты, повреждённые вложенные поля, tool fragments, частичный usage, неизвестные метаданные, API-ошибки, JSON, terminal и отмена на EOF. Файл входит в быстрый профиль без серверов и дочерних процессов.

Там же строгий тестовый endpoint отвергает пустые массивы и нарушенный порядок tool results. `tests/unit/provider-tool-recovery.test.ts` дополнительно выполняет настоящий цикл runtime → OpenAI SDK → `write_file` → HTTP 400 → продолжение: файл сохраняется, завершённый инструмент не запускается повторно. Реальные Git-проверки вложенной папки и репозитория без коммитов находятся в `tests/unit/tools.test.ts` и не добавлены в быстрый профиль.

`tests/fixtures/manifest-cli.ts` использует настоящий локальный HTTP endpoint и обычный CLI. Успешный сценарий проходит через heartbeat, finish без delta и usage без choices до выполнения штатного инструмента и сохранения checkpoint. `--malformed-stream` подтверждает одну HTTP-попытку, отсутствие выполненных инструментов и сохранённую причину `transport`. Fixture используется для source, установленного npm-пакета и compiled CLI; его source assertions находятся в `tests/integration/extension-tools-cli.test.ts`.

```bash
bun test tests/unit/provider-stream-events.test.ts tests/integration/extension-tools-cli.test.ts
bun tests/fixtures/manifest-cli.ts bun dist/cli.js
bun tests/fixtures/manifest-cli.ts bun dist/cli.js --malformed-stream
```

Локально на Linux, Bun 1.4.3: быстрый профиль — 415 pass в 41 файле, без ошибок; 111 проверок runtime/протокола/recovery в пяти файлах и 34 проверки совместимости, HTTP и побочных вопросов в шести файлах также прошли. Typecheck, lint и CLI/SDK build успешны; существующие предупреждения lint не отключались. Оба сценария fixture прошли в source CLI, установленном локальном npm-пакете и compiled CLI. Числа разных наборов не суммируются: их покрытие пересекается.

[Quick CI](https://github.com/TheAsrada/ChiselCode/actions/runs/39358289282) прошла на точном source `17fc326f91c8b29451fce728c7cf21c70ebbf363`: 415 pass, typecheck, lint, CLI/SDK build и запуск собранного CLI под Bun 1.4.2. До исправления два регрессионных теста воспроизвели дословные ошибки `chunk.choices[0]` и `choice.delta.refusal`; после исправления прошли.

При подготовке исправления отдельно проверялся Linux. Проверки Native validation для выпуска и результаты публикации приведены в [отчёте CLI 0.6.37](../contributors/reports/release-0.6.37.md). Изменение не требует обновления схемы сессий, пользовательских настроек или SDK расширений.
