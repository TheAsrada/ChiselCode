# Структурированная лента действий

[Архитектура](../architecture.md) · [Справка](../agent-actions.md)

## Решение

OpenTUI хранит одну `TranscriptEntry.toolAction` на invocation ID. Core callbacks передают тот же `invocationId`, что `RuntimeEvent` и `session.runtime.invocations`; queued/approval/progress дополняют состояние, start/result обновляют запись. Строки прежнего renderer не разбираются. Сообщения, контекстные записи и отдельные карточки остаются границами.

`groupToolActions` — общая проекция последовательных записей в группы действий или навыков. Порядок определяется началом вызова; поздний результат обновляет эту запись, включая параллельное выполнение через границу сообщения. При разделении раскрытой группы самостоятельной карточкой раскрытие переносится на оставшиеся действия по invocation ID. Неизвестные инструменты используют общее представление с именем и результатом.

`actionIsSeparate` оставляет вне групп изменения файлов, содержательные presentations, subagent/background results и скачанные файлы. На месте вызова сохраняется невидимая граница `toolBoundary`: поздний самостоятельный результат не склеивает чтения по обе стороны параллельного вызова. Вызов, ожидающий подтверждения, показывает самостоятельную строку. Ordinary foreground shell остаётся в группе по `foregroundTaskId`; background events прикрепляют кнопки процесса. Перевод в фон переносит управление в прежнюю самостоятельную карточку без повторного запуска.

## Восстановление и данные

Replay читает `tool_use`, `tool_result`, invocation results, diff и presentations. Он вызывает тот же upsert и строит ту же проекцию, включая source, errorCode и artifact. Для старого результата остаются имя и сохранённый текст; сведения навыка не угадываются из инструкций или текущей библиотеки.

`load_skill` сохраняет в `details.skill` имя, описание и источник прочитанного snapshot. Provider-facing output содержит прежние инструкции. Строка навыков показывает метаданные и результат чтения, не заявляет применение и не меняет разрешения.

Перед offload большого неуспешного вывода normalizer сохраняет ограниченный `details.failureReason` из санитизированного результата. Artifact остаётся полным. UI читает страницы через `ToolResultStore`, проверяя принадлежность invocation/URI открытой беседе и generation/signal. Модель и executor при раскрытии не вызываются.

## Состояние и пределы

Раскрытие, страницы и предел видимых действий находятся в `TuiController.presentation.actions`. Ключ группы включает kind и ID первого вызова; ключ вывода — invocation ID. Обновления результата не заменяют ключи. Вкладки сохраняют состояние, смена/закрытие владельца отменяет позднее чтение; начальная история свёрнута.

Сначала выполняется группировка, затем окно из 240 строк ленты. Раскрытая группа монтирует 40 операций с явным продолжением. Вывод делится на части по 6000 символов; artifact читается по 100 строк. Большая строка доступна последовательными частями той же страницы. Исходные results и artifacts не удаляются.

Мышь использует `DialogAction` с защитой от drag/selection. Клавиатурные targets имеют стабильные строковые ID; прокрутка к target меняется по явному переходу пользователя. При раскрытии sticky follow отключён. Split-footer коммитит завершённые группы компактно, оставляя интерактивную ленту в footer при фокусе Tab.
