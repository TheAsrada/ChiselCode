# Отображение расширений в чате

[Оглавление](../README.md) · [Обзор архитектуры](../architecture.md) · [Пользовательская справка](../subagents.md)

Расширение описывает представление данных, а OpenTUI рисует его в выбранной теме. Интерфейс не проверяет ID конкретного расширения и не знает имён его инструментов. Это часть существующего API связанных расширений; отдельный загрузчик плагинов не добавляется.

Основной контракт доступен начиная с **0.6.22**. Target `background_task` и управляемые действия входят в **0.6.23**; статус публикации — на [странице выпуска](https://github.com/TheAsrada/ChiselCode/releases/tag/v0.6.23).

## Регистрация

`ctx.chat.register({ id, render })` регистрирует синхронный форматтер в текущем workspace. ID принадлежит расширению: два расширения могут использовать одинаковый `id`. Регистрация участвует в staging, rollback и dispose вместе с инструментами и командами. После activation новые регистрации закрыты; метаданные и ссылки на функции фиксируются при регистрации.

Инструмент указывает `spec.chat`, команда — `chat`:

```ts
ctx.chat.register({
  id: "inspection",
  render(data) {
    const result = data as ToolExecutionResult;
    return {
      cards: [{
        id: "inspection-result",
        revision: 1,
        title: "Проверка проекта",
        subtitle: "Локальный анализ",
        description: result.output,
        status: { label: "Готово", tone: "success" },
      }],
    };
  },
});

ctx.tools.register(defineTool(
  {
    name: "inspect",
    description: "Проверить проект",
    effect: "read",
    permission: "read",
    parallelSafe: true,
    chat: { title: "Проверка проекта", inputField: "label", view: "inspection" },
  },
  z.object({ label: z.string() }),
  prepareInspection,
  executeInspection,
));
```

`title` задаёт подпись вызова, `inputField` добавляет строковое значение аргумента, а `view` выбирает форматтер результата. Для команды используется тот же контракт; данные её результата поступают в форматтер после выполнения callback. Отсутствующее оформление сохраняет существующее отображение расширений. Типы `ChatStyle`, `ChatPresentation`, `ChatCard` и `ExtensionChatView` экспортируются из `src/extensions/index.ts`.

## Данные и обновления

`ChatPresentation` содержит `summary` и/или `cards`. Карточка задаёт `title`, необязательные `subtitle`, `description`, `detail`, а также статус `{ label, tone }`. Тона `muted`, `accent`, `success`, `warning`, `error` получают цвета из темы. Размеры, переносы, терминальные символы и управляющие последовательности обрабатывает общий renderer.

`id` и `revision` позволяют обновлять одну карточку. Ключ включает владельца расширения, поэтому чужая карточка с тем же ID не заменяется. Старые и повторные ревизии игнорируются. Обновление оставляет основной поток ответа, черновик и фокус на месте. Данные ограничены схемой: максимум 32 карточки в представлении, заголовок до 240 символов, описание до 8192 символов.

Для живого источника приложение вызывает `scope.chat.render(extensionId, view, data)` и передаёт полученное представление вместе с событием. Расширение получает замороженную копию данных и возвращает DTO. `builtin.subagents` использует представление `task` для событий задачи и отдельные представления для запуска, списка, ожидания, результата и остановки. Русские подписи и правила статусов находятся в самом расширении. `target: { type: "subagent", id }` открывает принадлежащую текущему разговору задачу через существующий порт просмотра; карточка не исполняет инструменты.

## Хранение и ошибки

`ToolSource.chat` сохраняет подпись вызова; `ToolExecutionResult.presentation` содержит проверенные данные и владельца, назначенного host. Инструмент не может подменить владельца через возвращённый DTO. Основной `output` и provider messages сохраняют исходное значение. Метаданные оформления не включаются в определения инструментов для модели.

Результаты инструментов сохраняются в `runtime.invocations`, оформление команд — в `Session.chatPresentations` с позицией в истории. Последняя карточка AI-помощника сохраняется в `ChildReceipt.presentation`; карточки локальных фоновых команд — в `Session.backgroundTasks` как узкие revision receipts. При replay новая ревизия заменяет снимок запуска. Для старой истории доступный форматтер можно применить к сохранённым данным; это не повторяет инструменты и не вызывает модель. Сохранённые представления читаются и после удаления расширения.

Ошибка или некорректный DTO форматтера возвращают существующее отображение; выполненный инструмент сохраняет свой результат. Ошибки инструментов и запросы разрешения проходят обычный путь и не превращаются в успешные карточки.

Проверки: `extension-chat.test.ts`, `opentui-chat-card.test.tsx`, настоящий `tui-command-contributions.ts` с отдельным расширением отчёта и `tui-subagents.ts` с живыми задачами и `/resume`. Эти же сценарии выполняются для установленного пакета и compiled-сборок.

## Цели фоновых команд

`target: { type: "background_task", id }` адресует core task UUID, не child ID/PID. Карточка может содержать до трёх действий `open`, `promote`, `stop`, `wait` с typed target; dispatcher проверяет live root owner/child scope через core port перед async действием. Сохранённый DTO не выдаёт права на запуск/kill. После promotion исходная карточка обновляется тем же ID; busy resource card содержит действия просмотра/остановки/ожидания. Ошибка форматтера не меняет errorCode или результат инструмента.

Связанные темы: [Архитектура фоновых задач](background-tasks.md), [Помощники](subagents.md), [Справка](../background-tasks.md).

Карточки и typed targets используют общий owned dispatcher: [UI contributions](ui-contributions.md).
