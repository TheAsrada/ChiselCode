# Автосохранение настроек и подключения

[Документация](../README.md) · [Архитектура](../architecture.md) · [Пользовательский сценарий](../interactive.md)

Статус: принято, текущие исходники (Unreleased).

## Решение

`SettingsAutosave` сериализует записи каждой формы, объединяет ожидающий ввод и предоставляет общий `flush`. Переключатели записываются сразу; текст ожидает 350 мс и проходит штатную валидацию. `SettingsPanelControl.flush` возвращает результат записи: Settings завершает все панели до перехода или закрытия. Ошибка блокирует переход, сохраняет ввод и позволяет повторить запись. Подтверждение старого snapshot обновляет baseline/revision, но не получает право заменять более новый ввод. Возврат к исходному значению во время записи также проходит через очередь.

Загрузка, поиск и фокус не создают операцию записи. Панели остаются смонтированы; переход области global/project сначала завершает запись и затем загружает значения новой области. Сервисы сохраняют прежние atomic updates, проверки revisions и защищённое хранение секретов. Профиль записывает только изменённые поля относительно подтверждённого snapshot; конфликт того же поля сохраняет внешнее значение и сообщает причину. Чужие поля конфигурации остаются на месте.

## Подключения

`settingsDraft()` больше не генерирует ID профиля из определения провайдера. Пустой config и миграция пустого v1 дают пустой словарь профилей. Создание начинается явным добавлением и вводом ID. Просмотр загружает значения и обновляет baseline без выбора модели беседы. Параметры записываются с `activate: false`; отдельное действие выбора обновляет default, последнее выбранное подключение и runtime исходного владельца. Редактирование уже выбранного профиля обновляет его runtime; изменение другого профиля не выбирает его.

Ответ `setup_required` означает успешную запись с незавершённой авторизацией. UI подтверждает snapshot и показывает этот статус отдельно от ошибки записи. Готовность credentials не заменяет явную сетевую проверку. Секреты передаются существующему CredentialStore, открытый ключ в config не появляется.

## Явные операции

Автосохранение не вызывает вход, проверку сети или путей, установку, доверие, запуск и удаление. В частности, добавление проверенного MCP сервера выдаёт доверие и подключает его, поэтому имеет отдельное именованное действие; незавершённая установочная форма остаётся в памяти. Параметры существующих расширений и категории MCP сохраняются автоматически.

## Проверки

`settings-autosave.test.ts` проверяет порядок записей, объединение ввода, возврат к baseline во время записи, ошибку и повтор. `provider-settings.test.ts` проверяет пустую установку, сохранение без ключа, удаление последнего профиля и сохранение внешних полей/конфликты. `settings-autosave-runtime.test.tsx` использует настоящий OpenTUI и файловое хранилище: клавиатуру, мышь, resize, ошибку записи, повтор, задержанные ответы и закрытие.
