# Провайдеры, профили и подписки

[Документация](README.md) · [Выбор модели](model-picker.md) · [Пользовательские провайдеры](custom-providers.md)

**Провайдер** — сервис, которому отправляются запросы. **Профиль** — аккаунт и настройки подключения к этому сервису. **Модель** — выбранная модель этого подключения. Один сервис может иметь несколько профилей, например рабочий и личный.

<a id="каталог-и-выбор"></a>

## Подключить сервис

1. Запустите `chisel setup` либо откройте `/settings` → «Подключения» и выберите «Добавить подключение».
2. Найдите сервис по названию или ID, задайте ID нового профиля и подтвердите ввод. Для совместимого API укажите «Адрес API».
3. Введите «API-ключ» и выберите «Модель». Параметры сохраняются автоматически; для подписки используйте [вход в ChatGPT](#подписка-chatgpt).
4. Вернитесь к параметрам профиля и выберите «Проверить подключение», затем «Использовать подключение», чтобы выбрать его для беседы. Отправьте короткую задачу: успешное получение списка моделей ещё не подтверждает работу генерации и инструментов.

Ключи создаются в [консоли Anthropic](https://console.anthropic.com), [кабинете OpenAI](https://platform.openai.com/api-keys) или [кабинете AgentRouter](https://agentrouter.org/console/token). Совместимый сервис выдаёт собственные параметры.

## Встроенные сервисы

| ID | Сервис | Переменная ключа | Модель по умолчанию | Базовый адрес |
| --- | --- | --- | --- | --- |
| `anthropic` | Anthropic | `ANTHROPIC_API_KEY` | `claude-opus-5` | `https://api.anthropic.com` |
| `anthropic-compatible` | Anthropic-совместимый API | `ANTHROPIC_AUTH_TOKEN` | выбрать вручную | указать при настройке |
| `openai` | OpenAI | `OPENAI_API_KEY` | `gpt-5` | `https://api.openai.com/v1` |
| `openai-compatible` | OpenAI-совместимый API | `OPENAI_API_KEY` | выбрать вручную | указать при настройке |
| `agentrouter` | AgentRouter | `AGENTROUTER_API_KEY` | `claude-opus-5` | `https://agentrouter.org/v1` |

Текущий каталог показывает `chisel providers list`. Модель по умолчанию не гарантирует доступ на вашем аккаунте: используйте точный ID из кабинета сервиса или окна `/model`.

Сервисы из таблицы требуют непустой ключ. [Подписка ChatGPT](#подписка-chatgpt) подключается отдельно через вход по коду. Для локального сервера без авторизации используйте [пользовательский manifest](custom-providers.md#локальный-сервер-без-ключа) с `auth.required: false`. Совместимый сервер также может принимать служебный непустой ключ, если это предусмотрено самим сервером.

## Подписка ChatGPT

1. Откройте `/settings` → «Подключения» → «Добавить подключение».
2. Выберите **ChatGPT** и задайте ID профиля, например `chatgpt-personal`.
3. Откройте «Аккаунт» или действие «Войти в ChatGPT». В браузере перейдите по показанному адресу `https://auth.openai.com/codex/device` и введите код.
4. После входа откроется каталог подписки. Выберите модель: параметры сохранятся автоматически.
5. В параметрах профиля выберите «Использовать подключение», чтобы использовать этот аккаунт и модель в беседе. Сам вход и просмотр профиля не переключают беседу на него. [Управление подключениями](#управление-подключениями).

Нужен аккаунт с доступом к Codex через ChatGPT. Если вход по коду отключён, включите его в настройках безопасности аккаунта ChatGPT. Esc отменяет ожидание. API-ключ OpenAI для этого подключения не нужен; лимиты и доступные модели определяет подписка.

В беседе с выбранным подключением ChatGPT в боковой панели на вкладке «Контекст» появится блок **ChatGPT**: остаток лимитов и время сброса. Значения обновляются примерно раз в минуту и из доступных заголовков ответов. «Лимиты недоступны» или «Данные устарели» не означают полный остаток. Панель показывает лимиты Codex-доступа, а не всех сообщений на сайте ChatGPT.

Для второго аккаунта создайте другой профиль. Для повторного входа в существующий откройте его параметры и выберите «Аккаунт» или «Войти заново». «Отключить аккаунт» требует подтверждения и удаляет локальный вход только этого профиля; подписка в OpenAI сохраняется. Данные входа зашифрованы в `credentials.enc`, обновление токенов происходит автоматически. Адрес подключения подписки фиксирован.

```bash
chisel --profile chatgpt-personal "Объясни проект"
```

<a id="profiles-и-models"></a>

## Рабочий и личный аккаунты

Создайте отдельные профили:

```bash
chisel setup --provider openai --profile openai-work
chisel setup --provider openai --profile openai-personal
chisel --profile openai-work "Объясни проект"
```

В `/settings` → «Подключения» список объединяет сохранённые профили всех сервисов. «Добавить подключение» сначала предлагает сервис, затем ID; «Название» меняет отображаемую подпись. Откройте нужный профиль и выберите «Использовать подключение», чтобы переключить беседу на этот аккаунт. Переход к другому профилю сначала завершает автосохранение; при ошибке ввод остаётся в форме, а переход блокируется до успешной записи. [Управление подключениями](#управление-подключениями).

«Удалить профиль» требует подтверждения. Ключ, адрес API и модель каждого профиля независимы. Если у сервиса несколько профилей, CLI требует точный `--profile`; `--provider` не выбирает аккаунт случайно.

Модель запроса выбирается в порядке `--model` → модель профиля → модель сервиса. При продолжении сессии без явных переопределений сохраняются её профиль и модель. [Смена модели в чате](model-picker.md).

<a id="authentication"></a>

## Откуда берётся ключ

Для обычного запуска приоритет имеет первая непустая переменная окружения сервиса, затем сохранённый ключ профиля. Ключ, введённый для текущей проверки в настройках, используется раньше них. Если вы заменили сохранённый ключ, а ошибка авторизации осталась, проверьте переменные окружения.

Мастер скрывает ввод и сохраняет ключ локально в `credentials.enc`. Manifest и конфигурация содержат ссылки на ключи, а не сами секреты. Низкоуровневый `chisel auth set` передаёт ключ в аргументах процесса; для ручной настройки используйте мастер. [Ключи в автоматизации](cli.md#ключи-в-автоматизации).

<a id="endpoints"></a>

## Адрес API

Для API-ключей адрес профиля или `--base-url` заменяет стандартный адрес сервиса, включая официальные API. Для подписки ChatGPT подмена адреса запрещена. Укажите HTTP(S)-адрес без логина, пароля, query и fragment. Не добавляйте конечный `/chat/completions` или `/messages`.

| Настройка адреса | Поведение |
| --- | --- |
| `none` | Удаляет конечные `/`, сохраняет путь; используется официальными Anthropic и OpenAI |
| `openai-v1` | К голому хосту добавляет `/v1`, существующий путь сохраняет; используется OpenAI-compatible и AgentRouter |
| `anthropic-root` | Удаляет конечный `/v1`; драйвер сам добавляет `/v1/messages` |

Переменная `ANTHROPIC_BASE_URL` автоматически не читается: задайте адрес в профиле или `--base-url`. HTTP для локального сервера разрешён; удалённый HTTP передаёт ключ и запросы без TLS, о чём проверка manifest предупреждает. [Proxy, сертификаты и корпоративная сеть](network.md).

<a id="capabilities-и-health"></a>

## Если подключение не работает

- `chisel doctor` проверяет локальные настройки без запроса к API.
- «Проверить подключение» проверяет соединение или список моделей, если сервис умеет их перечислять.
- Если список недоступен, введите точный ID вручную через `/model` → «Ввести ID».
- При 401 проверьте ключ и выбранный профиль; при 404 — базовый адрес и тип API.
- HTTP 400 с телом только `data: [DONE]` означает отказ сервиса без объяснения. Клиент сохраняет ошибку и не повторяет принятый запрос с произвольно изменёнными параметрами.

[Диагностика провайдеров](troubleshooting.md#проверка-подключения) описывает дальнейшие проверки. Состояние «проверка не поддерживается» само по себе не означает отказ подключения.

## Возможности и стоимость

Поддерживаются OpenAI Chat Completions и Anthropic Messages. Расширение ChatGPT использует Responses backend подписки; отдельного Responses driver для произвольных API нет. Совместимость инструментов и рассуждений зависит от сервиса. Известное окно контекста берётся из API модели, затем из каталога точных ID; неизвестное окно не выдумывается. Каталог включает DeepSeek V4.1 Flash и `deepseek-v4.1-flash-1017`, а также известные ID Gemini, Grok и GLM. Лимиты конкретного развёртывания сервиса могут отличаться; метаданные его API имеют приоритет над каталогом. Если шлюз возвращает только ID или использует собственный алиас без известных лимитов, см. [диагностику неизвестного окна](troubleshooting.md#неизвестное-окно-контекста).

Стоимость — оценка по известному тарифу, а не выписка биллинга. Неизвестная цена показывается как неизвестная, а известная часть расхода не объявляется полной стоимостью. Проверяйте итоговый счёт в кабинете провайдера.

## Управление подключениями

В `/settings` → «Подключения» показаны только сохранённые пользовательские профили. На чистой установке и после удаления последнего профиля список пуст, активного профиля нет. Создавайте запись через «Добавить подключение». Просмотр профиля не выбирает его для беседы. «Использовать подключение» отдельно выбирает профиль и модель для беседы, из которой открыты настройки, делает профиль подключением по умолчанию и запоминает выбор для следующих запусков. Остальные открытые беседы сохраняют свои профили.

Параметры профиля сохраняются автоматически, в том числе без ключа. Отдельной кнопки «Сохранить» нет. Редактирование уже выбранного подключения обновляет его параметры в беседе; редактирование другого профиля не переключает беседу на него. Статус «Сохранено · требуется настройка / авторизация» отличается от ошибки записи: параметры уже сохранены, но нужно добавить ключ или выполнить явный вход. Сам выбор подключения не заменяет авторизацию.

В разделе «Модель» действие «Ввести вручную...» позволяет задать ID без ожидания каталога. Вход, проверка подключения, отключение и удаление выполняются только явными действиями. Ошибка записи сохраняет введённое значение; исправьте причину и повторите выход из поля или выберите «Повторить». [Навигация и автосохранение](interactive.md#окно-настроек).
