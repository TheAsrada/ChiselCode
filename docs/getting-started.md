# Первая задача за несколько шагов

[Документация](README.md) · [Главная](../README.md)

## 1. Установите и запустите

Выберите [установщик для своей платформы](installation.md), затем откройте новый терминал:

```bash
chisel
```

Первый запуск открывает мастер. Найдите провайдера в каталоге, вставьте API-ключ и укажите доступную модель. Для совместимого API укажите endpoint, если его нет в definition. Подробности — в [справке провайдеров](providers.md).

Повторно открыть мастер можно командой `chisel setup` или через `/settings`. Ключ в мастере скрыт и сохраняется локально в зашифрованном файле.

## 2. Выберите проект

В текущих исходниках запуск с `--launcher` открывает главную без проекта. Нажмите «Открыть папку» или выполните `/cwd`. При запуске `chisel` из обычного терминала выбирается папка терминала; Git не обязателен. Служебные данные ChiselCode проектом не становятся. Эти изменения относятся к `Unreleased`, а не к опубликованной 0.6.43.

Чтобы сразу указать путь, выполните:

```text
/cwd "C:\path\to\project"
```

На macOS/Linux:

```text
/cwd /home/user/project
```

Путь должен существовать. `/cwd` принимает папку или файл (тогда выбирается его папка); относительный путь отсчитывается от текущего проекта, а без него — от показанной папки навигации. `/cwd` без аргументов открывает окно выбора с полным путём, каталогами и недавними проектами. Выбор папки сохраняет набранный текст и не отправляет его: отправьте задачу следующим Enter. Esc или Ctrl+C отменяет выбор. Модель и подключение проверьте в `/settings`.

## 3. Начните с изучения

```text
Объясни структуру проекта. Найди точку входа и команды для запуска тестов.
```

Затем уточните задачу:

```text
Найди причину ошибки валидации email. Сначала предложи план исправления.
```

Чем точнее ожидаемый результат и способ проверки, тем проще оценить работу помощника.

## 4. Проверьте изменение

При запросе на запись появится diff; для команды — её текст и рабочая папка. **y** разрешает действие, **n / Esc** отклоняет. Попросите запустить нужный тест и показать итоговый diff.

Разрешённый shell не изолирован от системы. Перед подтверждением прочитайте команду; детали — в [модели безопасности](security.md).

## 5. Вернитесь к разговору

`/sessions` открывает разговоры текущего проекта. `/clear` сохраняет текущий и начинает новый, а `/exit` закрывает приложение. При следующем запуске выберите тот же проект и откройте `/resume`.

Далее: [команды и клавиши](interactive.md) · [если что-то не работает](troubleshooting.md).

Для второго аккаунта используйте «Новый профиль» в /settings или `chisel setup --provider openai --profile openai-personal`. Выбирайте через --profile; собственный manifest автоматически добавляется в поиск провайдеров.
