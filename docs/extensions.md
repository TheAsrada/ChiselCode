# Внешние расширения

[Документация](README.md) · [Для разработчика](extensions/README.md) · [Безопасность](security.md)

Внешний пакет добавляет инструменты, команды, статусы и представления. Сначала подготовьте готовый пакет в каталоге, который показывает `chisel extensions path`. ChiselCode не ищет расширения в проекте и не устанавливает зависимости.

## Проверка и доверие

Пакет содержит `chisel-extension.json` и готовый `index.mjs`. Укажите его папку явно:

```sh
chisel extensions inspect /путь/из/extensions/пакет --json
```

Проверка читает manifest и все файлы, но не выполняет JavaScript. Сверьте имя, id, версию, путь, совместимость и полный SHA-256. Затем подтвердите конкретное содержимое:

```sh
chisel extensions approve /путь/из/extensions/пакет --id author.feature --digest SHA256_ИЗ_INSPECT --enable
```

В терминале появится адресованное подтверждение. Без интерактивного терминала добавьте `--ack-process-access`. Для сохранения доверия без включения используйте `--disabled` вместо `--enable`.

Доверенный JavaScript исполняется внутри процесса приложения и может обращаться к файлам, сети и запускать программы напрямую. Это **не OS sandbox**. SHA-256 определяет содержимое, а не честность автора. Разрешения штатных инструментов отдельно проверяются при каждом действии.

Изменение любого файла, включая assets, отменяет совпадение с подтверждённым digest. Выполните inspect заново и отдельно подтвердите новое содержимое. Старое подтверждение не распространяется на новую версию или другой путь.

## Запуск, статусы и восстановление

Перезапустите ChiselCode после изменения code/trust/enabled. Проверить user записи без исполнения кода:

```sh
chisel extensions status
chisel extensions status --json
```

Включённый пакет не обязательно активен. `status` отдельного CLI-процесса проверяет файлы и доверие; он не импортирует пакет и не изображает workspace activation успешной. Ошибка optional расширения показывается кратким notice; исправные встроенные возможности продолжают работать.

Если внешний код мешает запуску, откройте новый процесс:

```sh
chisel --no-external-extensions
```

Флаг оставляет встроенные инструменты и отключает все внешние импорты. Help, version, doctor, inspect, approve и status также не импортируют пользовательский код. Проверка пакета не требует API-ключа.

Проект может только сузить user выбор в `.chiselrc`:

```json
{"externalExtensions":{"disabledIds":["author.feature"]}}
```

`disabled: true` отключает все внешние пакеты для проекта. Проект не может выдать доверие или выбрать executable path.

## Доступность и границы

Загрузчик и SDK доступны в [**0.6.25**](https://github.com/TheAsrada/ChiselCode/releases/tag/v0.6.25). Релиз содержит четыре установщика и `chiselcode-0.6.25.tgz` с CLI и публичными типами SDK; npm registry upload не выполнялся. Установку из архива, обновление, удаление и Settings → Extensions добавят отдельно. Нет поиска по npm/GitHub, install scripts, runtime TypeScript/JSX, native modules, hot reload или sandbox изолированного JS.
