# Навыки

[Документация](README.md) · [Главная](../README.md)

Скилл — это папка с `SKILL.md` (формат Agent Skills): YAML-шапка с `name`/`description` и markdown-инструкции. Агент получает только имена и описания доступных ему навыков и по задаче загружает инструкции через `load_skill({name})`. Команда `/имя` вызывает навык вручную, если это разрешено:

```markdown
---
name: explain-api
description: Объясни API проекта, когда пользователь просит описать его контракты.
---

Объясни API по коду проекта. Учти запрос пользователя:

$ARGUMENTS
```

Навыки хранятся в ChiselCode Home: встроенные — в `skills/bundled/`, пользовательские — в `skills/user/`. На Windows ChiselCode Home равен `%LOCALAPPDATA%\ChiselCode`; на macOS/Linux — `$XDG_DATA_HOME/chiselcode` или `~/.local/share/chiselcode`. При обновлении приложение заменяет только встроенные навыки и не трогает `skills/user/`. Проектные каталоги больше не являются источниками навыков. Старые пользовательские навыки безопасно копируются в `skills/user/` при первом обнаружении; исходные файлы сохраняются. Имена встроенных навыков зарезервированы: конфликтующий пользовательский навык игнорируется с диагностикой.

Встроенные команды (`/settings` и др.) перекрыть нельзя. `user-invocable: false` отдельно отключает вызов `/имя`, но оставляет автоматическую загрузку агентом; `disable-model-invocation: true` отдельно скрывает навык от агента, но оставляет ручную команду. Начиная с 0.6.33 встроенные `/skill-creator`, `/code-review` и `/extension-creator` доступны вручную и по подходящей задаче. Последний создаёт готовые отключённые [расширения интерфейса](ui-mods.md) через `create_extension`. Для создания достаточно попросить агента создать навык или отправить `/skill-creator <задача>`. Изменения встроенных навыков перечислены в [истории 0.6.33](../CHANGELOG.md#0633---2026-10-16).

Инструкции самого `skill-creator` написаны на английском. Новые навыки он должен создавать на языке пользователя: `description`, текст инструкций, примеры и пояснения. Явное указание другого языка имеет приоритет; при изменении существующего навыка сохраняется его язык, если перевод не запрошен. Имена папок остаются латинскими slug, YAML-поля, команды и API не переводятся.

[Кадр настоящего OpenTUI: автоматическая загрузка и `/skill-creator`](assets/skill-creator/skill-creator.png).

`/skill-creator` создаёт и изменяет пользовательские навыки через `create_skill`, который сам ограничивает запись каталогом `skills/user/` и не принимает абсолютные пути. В CLI 0.6.42 агент читает текстовые файлы внутри навыка через `load_skill({name, path})`; чтение ограничено UTF-8-файлами до 64 KiB и не выполняет скрипты. Обычный `read_file` по-прежнему ограничен проектом.

## Библиотека `/skills`

Чат показывает загрузку `load_skill` отдельной строкой **«Навыки»**: названия в порядке чтения, успех или ошибку. Раскрытие показывает описание и источник snapshot; полный текст инструкций остаётся в истории инструмента, а чтение не помечается как применение. Эти вызовы не входят в счётчики [«Действий агента»](agent-actions.md#навыки).

Агент сам выбирает подходящий навык по описанию. Для явного выбора откройте `/skills` или нажмите Ctrl+S, чтобы сохранить текущий черновик задачи: popup показывает поиск, список и подробности выбранного навыка. На небольшом терминале используется компактный список. `Enter` добавляет `/имя` к сообщению и возвращает фокус в редактор, сохраняя черновик задачи. Отправьте сообщение, чтобы применить навык один раз. Сам выбор ничего не запускает и не закрепляет. Навыки с `user-invocable: false` доступны для просмотра, но не для ручного вызова.

- `↑/↓`, `PageUp/PageDown` — выбрать навык; название и описание участвуют в поиске, поддерживается вставка текста.
- `Ctrl+O` — открыть полные инструкции; `Esc` — вернуться к списку или закрыть окно. Можно выбирать мышью и закрывать окно нажатием вне него.
- `Ctrl+N` — подготовить создание через `/skill-creator`; `Ctrl+E` — подготовить изменение пользовательского навыка с его текущим `SKILL.md`, включая настройки вызова. Изменения выполняются после отправки сообщения и обычного подтверждения записи.
- `Tab` — отдельная вкладка «Закрепление». Здесь `Enter` закрепляет или открепляет инструкции для каждого следующего сообщения текущей открытой вкладки (`●` — закреплён). Это дополнительный режим для постоянных правил. Закрепление не восстанавливается после закрытия вкладки или перезапуска приложения; ранее отправленные инструкции остаются в истории.

## Настройки → Инструменты → Навыки

В 0.6.34 библиотека встроена в настройки. Поиск, список, описание и источник выбранного навыка находятся в том же разделе. На узком экране подробности доступны через Ctrl+O вместе с инструкциями. Отдельного окна поверх Settings нет; `/skills` и Ctrl+S из чата сохраняют привычный popup.

**Alt+1 / Alt+2** переключают библиотеку и закрепление; Tab переводит фокус между областями Settings. Ctrl+R или «Обновить» перечитывает каталог. Стрелки, Enter, Ctrl+O, Ctrl+N и Ctrl+E работают при фокусе в содержимом раздела. Esc сначала закрывает инструкции; следующий Esc закрывает Settings на широком экране или возвращает к разделам на узком. Закрепление применяется сразу к беседе, из которой открыли настройки, без отправки сообщения. Выбор навыка для задачи, создание и изменение закрывают Settings и подготавливают черновик; несохранённые формы сначала требуют выбора действия. «Остаться» отменяет переход в черновик.

[Кадры библиотеки и закрепления](contributors/reports/settings-tools.md#кадры-opentui).

## Добавить пользовательский навык

### Установить по ссылке или команде

В [CLI 0.6.42](contributors/reports/release-0.6.42.md) можно попросить агента установить навык прямо в разговоре:

```text
Установи навык: npx skills add https://github.com/msmps/opentui-skill --skill opentui
```

Агент передаёт строку встроенному `install_skill` как описание источника. ChiselCode не запускает `npx`, npm-пакеты, скрипты навыка или установку его зависимостей. Поддерживаются публичные GitHub-репозитории (`owner/repo`, HTTPS-ссылка, `tree` на папку, `blob`/raw на `SKILL.md`) и прямые HTTPS-ссылки на отдельный `SKILL.md`. Для GitHub скачивается весь выбранный навык: инструкции, справочные файлы, скрипты и assets; отдельная ссылка на Markdown сохраняет только сам `SKILL.md`.

Если навыков несколько, `inspect_skills` показывает пути и коммит источника. Агент выбирает указанный пользователем навык; при неясном выборе уточняет его. Отсутствующее имя не заменяется похожим. В опубликованной 0.6.42 одинаковые имена в разных папках требуют полного пути. В текущих исходниках после 0.6.42 обычный выбор по имени отдаёт приоритет стандартному `skills/<имя>` перед упаковкой для плагинов; полный путь выбирает конкретный вариант. Если стандартного варианта нет и совпадений несколько, агент получает только подходящие пути с коммитом и уточняет выбор. Каталог установки всегда `skills/user/` в ChiselCode Home, в том числе при `-g`; `--agent` допускает только `chiselcode`. Произвольные shell-команды, архивы, локальные папки, другие Git-хостинги, приватные репозитории и неизвестные параметры сейчас не поддерживаются. Для ветки со слешем используйте `owner/repo`, полный путь навыка в `skill` и SHA коммита в `revision`.

В текущих исходниках необязательный `revision` пропускается или передаётся как `null`, пока пользователь не указал конкретный SHA или `inspect_skills` не вернул его. Клиент определяет коммит сам и возвращает настоящий `revision` в результате. Заглушка из 40 нулей отклоняется до обращения к GitHub с подсказкой исправить поле. Агент должен исправить аргументы; смена формы ссылки или инструмента с тем же неверным SHA не помогает. Если пользователь явно закрепил версию, клиент не заменяет её другой.

Установка доступна в Build и требует обычного разрешения на изменение библиотеки; Accept edits самостоятельно его не выдаёт. Сетевые запреты Web продолжают действовать. Загрузка GitHub идёт через `api.github.com` без автоматического использования credentials. Отказ не обходится запуском другого установщика. Если GitHub вернул 403/429, учитывайте ограничение сервиса, а не повторяйте установку без изменения условий. В текущих исходниках ошибка дополнена короткой причиной из JSON GitHub API; для неподходящего `revision` указано поле, которое нужно исправить.

После успеха навык доступен в `/skills` и через `load_skill` сразу, без перезапуска. Если библиотека уже открыта, нажмите Ctrl+R. Установка не закрепляет навык в беседе и не запускает его инструкции. При следующей подходящей задаче агент сам загрузит их; справочные файлы он читает через `load_skill({name, path: "references/guide.md"})`. Бинарные файлы сохраняются, но этот инструмент читает только UTF-8-текст до 64 KiB.

Существующий навык сохраняется. Повторная установка идентичного пакета подтверждает его наличие; изменённый пакет или локальные правки вызывают конфликт. Автоматического обновления и перезаписи нет. GitHub-пакет привязан к коммиту и проверенным blob SHA; источник, коммит и SHA-256 пакета записываются в служебный `.chisel-source.json`. Имя библиотеки берётся из `SKILL.md`, поэтому оно может отличаться от папки в репозитории. Зарезервированные имена, ссылки, опасные пути, вложенные навыки и конфликты регистра отклоняются. Пределы: 128 файлов, 1 MiB на файл, 8 MiB на пакет и 64 KiB для `SKILL.md`; более строгие сетевые пределы пользователя также сохраняются.

### Создать вручную

1. Создайте папку `skills/user/explain-api/` внутри ChiselCode Home.
2. Сохраните пример выше в `SKILL.md` этой папки.
3. Откройте `/skills` и проверьте, что навык обнаружен; в уже открытой библиотеке нажмите Ctrl+R.
4. Вызовите `/explain-api опиши публичные endpoints` или выберите навык в библиотеке `/skills` и допишите задачу.

Для создания через помощника используйте `/skill-creator`. Перед сохранением проверьте предложенные инструкции. Навык добавляет инструкции, но не отменяет подтверждения инструментов и проверки путей.

| Поле YAML | Назначение |
| --- | --- |
| `name` | Имя навыка и ручной команды |
| `description` | Когда агенту следует использовать навык |
| `user-invocable: false` | Отключить ручной вызов |
| `disable-model-invocation: true` | Отключить автоматический выбор агентом |

См. также: [расположение данных](configuration.md), [безопасность](security.md).
