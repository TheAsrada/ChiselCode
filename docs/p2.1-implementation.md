# P2.1: WorktreeService

База: main `c5c94ec7b5311b2c75e08925990a4b684e69fe7a`, v0.6.19. Реализация и commits выполняются прямо в main; development branches/worktrees/PR не создаются. Managed detached worktrees в Home и временных Git fixtures — сама функция этого этапа. Версия результата — 0.6.20, по отдельному поручению владельца.

## Изменение поведения

Ранее parallel tabs использовали обычные roots без managed isolation. Теперь default `builtin.worktrees` даёт шесть production tools и `/worktree`: create/list/status/diff/open/apply/remove. Команда foreground, local операции не требуют model chat/API key. Open проверяет descriptor, удерживает admission lease и создаёт настоящую TUI conversation по новому root. В обычном CLI показывает тот же проверенный root для штатного запуска агента.

WorktreeService использует canonical Git common-dir, отдельные workspace git-dir/root, Home registry schema 1, immutable ownership marker, intents и cross-process use heartbeats. Core planner поддерживает mixed read/write resources без nested acquire. File operations разных worktrees параллельны, Git common mutations и shell одного repo сериализованы. Registry writer проверяет token и revision перед mutation/atomic rename: resumed former writer не перезаписывает нового владельца. Pending approval не отменяется чтением списка; отказ помечает неисполненный create без materialization.

Result включает committed, staged, unstaged и допустимые новые файлы относительно immutable base. Apply сохраняет bytes выбранного UTF-8 результата через существующий EditingService batch/commit, fresh observations, обычные approvals/guards/checkpoints/artifacts. Before-write validation повторяет source, target Git identity и policy. Conflicts/stale/unsupported selection блокируются целиком. Ordinary failure использует штатный rollback, concurrent bytes защищены; crash требует hash reconciliation, без replay.

Remove не имеет force/discard, блокируется пользователями/dirty/staged/untracked/ignored/conflicts/locks/unfinished state. Clean commit-result удерживается в internal ref до удаления и переживает restart/GC. Ошибка retention сохраняет tree. Закрытие вкладки/prompt не удаляет файлы; scope/LSP завершаются перед освобождением use lease. `.git` directory/file, local Git resources и canonical-root capture поддерживаются. Session schema 3 получила optional display-only worktree metadata, credentials/history в registry не копируются.

## Реальные проверки

Linux: Bun 1.4.2, Node 24.19.0, Git 2.52.0 и отдельно собранный официальный Git 2.39.5. Real TypeScript backend: typescript-language-server 6.0.1 / TypeScript 6.0.3 с внешним Node; dev TypeScript приложения не используется вместо backend.

Git integration использует actual repositories/files, production host/catalog/executor/policy/store, две detached копии и обычные local tools. Проверены CRLF/Unicode/newline filenames, branches/HEAD/index без изменений, committed/staged/unstaged/new/delete transfers, identical no-op, conflicting task, source/target approval races, Plan/deny/Dont Ask, rollback и concurrent rollback failure, hooks/filters, unknown owners/tamper/symlink, retained refs после GC, реальные shared-ref tools и cancellation. SIGKILL fixtures проверяют create/remove/apply checkpoints; abandoned lock expiry продвигается только после child exit. Отдельное interleaving показывает, что новый reconciliation не стирается resumed старым writer.

TUI harness запускает обычный application/default composition через real OpenTUI renderer. Пользователь создаёт два trees с approval, открывает отдельные tabs, агент через настоящий driver выполняет read, real LSP diagnostics, write, manifest и Git. Проверены разные Session IDs/observations/bytes, origin без изменений, apply из другой вкладки, conflict/refusal, close dirty tab, Settings, /btw и shutdown descendants. Model/network изолированы controlled endpoint; Worktree/Git/LSP executor не mocked.

Обязательные quality, ordinary installed npm package и compiled CLI/TUI checks перечислены в developer workflow. `command-packaging.ts` сохраняет P1.2/P1.3/P1.4 scenarios и добавляет installed/compiled worktree acceptance; CI выполняет полный набор Windows/macOS/Linux. Release workflow строит verified Windows, macOS arm64/x64 и Linux installers. Результаты конкретного выпуска доступны в Actions/Release и отчёте coding agent; source-only fixture flags в production отсутствуют.

## Пределы первого API

Regular non-bare committed repository, Git >=2.39; bare/unborn, submodules, sparse checkout, external filter attributes/LFS, binary/symlink/executable/mode-only apply и unsafe/case-colliding paths unsupported. Transfer: 512000 bytes/file, 8 MiB total base+result, 200 selected files; metadata 20000 paths, 1000 registry records. Git output 8 MiB, subprocess deadline 30 s, tool timeout 120 s, use heartbeat 5 s, storage abandoned lease 30 s. Нет автоматического fetch/install/merge/commit/discard/prune/repair/replay и удаления retained refs по timeout.

Это файловая изоляция, не OS security sandbox. Shared Git metadata и произвольные внешние shell/editor processes требуют state rechecks; неизвестный живой app owner блокирует remove. Windows/macOS PID liveness консервативна при неизвестной identity; Linux дополнительно проверяет process start. Worktrees сохраняются до явного удаления. Subagents, child agent loop, JobManager и внешний SDK не реализованы. [Пользовательский сценарий и recovery](worktrees.md), [core API](architecture.md#worktreeservice-p21).
