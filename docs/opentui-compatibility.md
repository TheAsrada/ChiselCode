# Проверка терминального интерфейса

[Разработка](development.md) · [Проверка в реальных терминалах](opentui-terminal-matrix.md)

OpenTUI используется в интерактивном `chisel` и `chisel setup`. Отдельный
`opentui-spike` проверяет renderer без API-ключа: историю, многострочный ввод,
diff, изменение размера, фокус, прокрутку и восстановление терминала.
В 0.6.34 используется только графическое оформление: ASCII-ветки и переключатель удалены; старое поле конфигурации игнорируется. [Решение и кадры](contributors/reports/opentui-graphics.md).

## Запуск диагностического приложения

Нужны Bun 1.3+ и зависимости проекта. CI использует Bun 1.4.2.

```sh
npm ci
bun run opentui:spike
bun run opentui:compile
./dist/opentui-spike --smoke
```

Для интерактивной проверки запустите `./dist/opentui-spike`.
Ctrl+B открывает контекст, Ctrl+D раскрывает diff, Tab переключает фокус,
Esc закрывает панель или возвращает фокус вводу. Ctrl+C останавливает запрос
текущей вкладки; `/exit` завершает приложение.
Переменные `CHISEL_ALT_SCREEN=0` или `CHISEL_NO_ALT_SCREEN=1` включают split-footer.

## Что проверяет CI

CI на Linux, macOS и Windows устанавливает npm-пакет, компилирует CLI и probe,
проверяет `--version`, инструменты, SDK и нативный `--smoke`. Smoke создаёт кадры
в памяти, изменяет размер, воспроизводит 10 000 записей истории и завершает renderer.
Release собирает оба macOS target: arm64 и x64; запуск на Intel не проверяется.

Эти проверки подтверждают загрузку нативных зависимостей и работу renderer;
ввод, копирование и восстановление конкретного физического терминала проверяются
[вручную](opentui-terminal-matrix.md). Готовые бинарники доступны в артефактах CI
`native-<runner>`.
