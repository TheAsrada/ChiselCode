## Независимые проверки запуска

Обе CLI получили в отдельных пустых Git-каталогах одинаковый контрольный запрос с просьбой вернуть строку `BENCH_PREFLIGHT_OK` без инструментов. Набор задач, его спецификация и оценщик в эти каталоги не передавались. Повтор Codex и итоговая проверка ChiselCode прошли с отдельным пространством монтирования и PID. Проверка монтирования подтвердила, что в пространстве дочернего процесса не видны облачные каталоги исходного архива и подготовленных заданий. Для ChiselCode использованы отдельные каталоги XDG, для повтора Codex — временный записываемый слой поверх штатного каталога Codex. Учётные данные между CLI не передавались.

| CLI | Запрошенная модель и effort | Время до завершения | Код | Наблюдение |
| --- | --- | ---: | ---: | --- |
| Codex | `gpt-6.2-sol`, `high` через `model_reasoning_effort` | 1,823 с | 1 | `codex login status` сообщил о входе через ChatGPT. Запрос каталога вернул HTTP 401, JSONL завершился событием `turn.failed` с сообщением о невозможности обновить токен. |
| Codex, повтор с `--ignore-user-config` | `gpt-6.2-sol`, `high` | 1,615 с | 1 | При повторе получены HTTP 401 и то же событие `turn.failed`. |

У Codex использованы `exec --ephemeral --sandbox read-only --json -m gpt-6.2-sol -c 'model_reasoning_effort="high"'` и отключён запрос подтверждений. У ChiselCode использованы `--profile chatgpt-bench --model gpt-6.2-sol --mode plan --approval dontAsk --json` с минимальным конфигом профиля без ключей. Ограничения чтения и Plan использовались для контрольного сообщения, которое не требовало изменений. Текущая сессия организатора в прогонах не участвовала. [Штатные флаги ChiselCode](../cli.md) · [Репозиторий Codex CLI](https://github.com/openai/codex)

На момент первичной проверки у облачной среды не было настроенных секретов для провайдера. Переменные `OPENAI_API_KEY` и `CODEX_API_KEY` отсутствовали. На этом этапе отдельные профили ещё не были подключены и контрольный ответ отсутствовал у обеих CLI. Причина отказа токена Codex известна только на уровне ответа сервиса и клиентской ошибки обновления. ## Методика и результаты

`prepare.py` создал две побайтно совпадающие группы по шесть чистых проектов для независимого прогона. Для проверки исходного состояния созданы отдельные копии, на которых выполнен `grade.py` из исходного архива. Обе исходные группы дали одинаковый результат по каждому заданию. Сумма объявленных закрытых тестов и знаменатель оценщика совпали и составили 65 на группу. Все шесть публичных `npm test` в неисправленных проектах также завершились успешно. Полный проход `grade.py` по двум группам занял 6,486 с.

Протокол предусматривал один свежий сеанс на задачу, одинаковый текст с ссылкой на `TASK.md`, последовательный запуск с чередующимся порядком CLI и лимит 20 минут на задачу вне времени установки. Для допуска обе CLI должны были подтвердить модель и effort, а их рабочие процессы — получить одинаковые права и сетевые ограничения. Эксперимент остановился на допуске. ### Ограничения

- Шесть синтетических задач охватывают отдельные контракты. 65 проверок начисляют баллы за поведение и дают больший вес задачам с большим числом проверок. Для оценки вариативности нужны повторения. Выводов о сравнительном качестве, скорости или стоимости по этому запуску сделать нельзя.
- Задание 06 проверяет поиск нужной реализации среди 90 посторонних модулей. Общий объём `src/` в этом задании — 14 703 байта. Оно не показывает, как агент работает у границы окна модели или после компактизации.
- В общем файловом пространстве отдельный рабочий каталог сам по себе оставляет доступ к закрытым тестам через shell. Проверка монтирования относится к контрольному запуску. Перед реальным прогоном требуется повторить проверку доступности файлов и сетевых ограничений для обоих рабочих процессов.
- В разделе протокола архивного `README.md` встречается строка про «6.1 Sol». Запрос владельца, спецификация `CODEX_CLOUD_PROMPT.md` и примеры запуска задают `gpt-6.2-sol`. Это значение использовано в обеих командах.

## Архитектурные наблюдения

Измеренное различие относится к автоматизации запуска. У Codex CLI доступны явная настройка effort, одноразовый `exec` и события JSONL. ChiselCode умеет выполнять headless-запросы, однако наружу отдаёт один итоговый JSON, а выбор effort в свежем разговоре вынесен в интерактивную команду `/effort`. В реализации выбор передаётся в агентное ядро и затем в `reasoning.effort` для ChatGPT, если запрошенный уровень входит в каталог возможностей модели. Свежий CLI-запрос не передаёт такой выбор через аргументы. [Парсер ChiselCode CLI](../../src/cli.ts) · [Выбор уровня в runtime](../../src/app/model-runtime.ts) · [Адаптер ChatGPT](../../src/extensions/builtins/chatgpt/adapter.ts)

| Категория | Наблюдение и граница вывода |
| --- | --- |
| Модель и провайдер | После отдельного входа Codex завершил контрольный запрос, а ChiselCode подтвердил доступность модели и уровня по каталогу. Замеры задач отсутствуют. Явный выбор effort в одноразовой CLI ChiselCode по-прежнему недоступен. |
| Цикл агента | ChiselCode уже ограничивает повторяющиеся сбои инструментов и один раз запрашивает текст при пустом финале. Итоговый JSON не показывает последовательность этих событий. В сравниваемых задачах цикл не исполнялся. [Контракты runtime](../architecture/runtime.md) |
| Маршрутизация инструментов | ChiselCode использует каталог со сведениями об источнике, эффектах и wire aliases. Без потока событий внешнему наблюдателю трудно установить, где возник отказ — при выборе схемы, проверке разрешения, выполнении или обработке результата. Ошибок маршрутизации в эксперименте не наблюдали. [Каталог инструментов](../../src/tools/catalog.ts) · [Контракты runtime](../architecture/runtime.md) |
| Shell | ChiselCode формирует exit code, сигнал, состояние захвата вывода и подтверждение cleanup внутри результата shell. Эти поля не представлены отдельными событиями одноразовой CLI. Статистика shell-вызовов в эксперименте отсутствует. [Структура результата shell](../../src/tools/shell-result.ts) |
| Разрешения | Встроенные ограничения путей и approvals ChiselCode полезны для структурированных инструментов. Разрешённый shell работает с правами процесса. У Codex заданный режим sandbox является частью штатного CLI. Для равных прав в A/B оба процесса требуют общего внешнего ограничения. [Модель безопасности ChiselCode](../security.md) |
| Контекст | ChiselCode уже публикует внутренние события компактизации. Публичный headless-вывод не позволяет связать эпизод компактизации с потерей нужного контекста. Испытание на такой эффект отсутствовало. [Менеджер контекста](../../src/context/context-manager.ts) |
