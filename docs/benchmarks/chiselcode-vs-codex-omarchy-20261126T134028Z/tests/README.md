# ChiselCode и Codex CLI на Omarchy

Парное сравнение двух установленных клиентов на `gpt-6.2-sol` с reasoning effort `high` через подписку ChatGPT. Основной набор включает восемь задач, по три независимых попытки каждого клиента на задачу. Всего 48 измеряемых запусков и два контрольных запроса перед ними.

## Запуск

Распакуй архив в отдельную папку, например в `~/bench`, и передай агенту [PROMPT_LOCAL_AGENT.md](PROMPT_LOCAL_AGENT.md). Для ручного прогона:

```bash
python3 run.py selftest
python3 run.py run --out runs/omarchy-01
```

Команда `run` автоматически проверяет запуск обеих CLI, офлайн-оценщик, выбранную модель, effort, правку файла и выполнение команды. Если нужно запустить только эту проверку, используй `python3 run.py preflight`. При нескольких ChatGPT-профилях ChiselCode укажи `--profile <id>`. Для альтернативных путей предусмотрены `--chisel`, `--codex`, `--chisel-config`, `--codex-home` и `--runtime-dir`. Последний нужен только для нестандартной установки, если CLI ищет ресурсы вне каталога пакета.

Требуются Omarchy или другой Linux с поддержкой непривилегированных namespaces, `bubblewrap`, `git`, Python 3.11+ с `sqlite3`, а также `node` или `bun`. Измерения запускай обычным пользователем. Нужны действующие входы ChiselCode и Codex CLI через ChatGPT одного аккаунта или workspace с доступом к Sol High. Codex должен хранить вход в `auth.json`. Если выбран другой credential store, войди через штатный интерфейс Codex с `cli_auth_credentials_store = "file"` в локальном профиле перед прогоном. Пакеты Python и контейнерные образы не требуются.

`run.py` использует локальный профиль ChiselCode и токены действующих входов. В отдельный временный дом каждой CLI попадает только её выбранный вход с короткоживущим доступом, без исходного refresh-токена. Родительские профили открываются на чтение. По окончании попытки временный дом и рабочая копия удаляются. При истёкшем входе обнови его штатным способом и повтори команду. Ошибка модели или effort останавливает контрольный запуск. Эквивалентный backend snapshot подписка не раскрывает.

Нормальная команда сохраняет прогресс после каждого запуска в `runs/omarchy-01`. После прерывания возобнови тем же вызовом и параметрами. Раннер пропускает уже записанные попытки, включая зарегистрированную инфраструктурную ошибку. Новый независимый замер использует новый `--out`. `python3 run.py report --out runs/omarchy-01` пересобирает отчёт из сохранённых строк с завершившегося или приостановленного прогона. Для быстрой разведки допустим другой каталог с `--repeats 1`. В основной отчёт такую разведку не включай.

## Задачи

| ID | Что проверяется |
| --- | --- |
| `layers` | Рекурсивные конфигурации, удаления, приоритет env, неизменяемость входных данных |
| `jobs` | Исполнение графа по слоям, циклы, неизвестные зависимости, глубокая цепочка |
| `batches` | Атомарная обработка остатков, повторные операции, откат и повтор |
| `cursor` | Фильтрация, устойчивое ранжирование и курсор без записи-якоря |
| `replay` | Валидация JSONL, порядок событий, дедупликация и watermark |
| `occupancy` | Агрегация событий на границах, отрицательные значения, разреженные интервалы |
| `ledger` | Согласованные переводы, повторяемость, SQLite и интеграция с helper |
| `alerts` | Маршрутизация, стабильный порядок при равном времени и cooldown |

Каждая задача получает отдельный Git-репозиторий из одного исходного снимка, открытый контракт и один публичный пример. Обе CLI получают один пользовательский промпт и своё системное окружение. Порядок задач перемешан по фиксированному seed. В половине пар каждой серии первой идёт одна CLI, в половине другая. Порядок внутри задачи меняется от серии к серии. Дефолтный дедлайн в 720 секунд включает запуск клиента. Глобальные пользовательские расширения, MCP, веб-инструменты и делегирование выключены. Внутренние инструменты и системные промпты клиентов входят в предмет сравнения.

Используется внешняя файловая изоляция bubblewrap. Внутри неё клиент видит рабочую копию, собственный временный профиль и нужный runtime. У клиентов есть сеть для ChatGPT, а доступ shell к сети не фильтруется по URL. У задачи нет сетевых зависимостей. Оценщик работает в отдельной песочнице с отключённой сетью и входом только на чтение. Ожидаемые ответы и функции-эталоны находятся у оркестратора. Для оценки запускаются 80 закрытых случаев и исходные публичные тесты. Оценщик проверяет наблюдаемое поведение. Он рассчитан на добросовестные исправления, его не следует использовать для запуска умышленно вредного кода.

Задача считается решённой только при завершённом клиентском запросе с подтверждёнными model/effort, 10/10 закрытых проверок и сохранённых проходящих публичных тестах. Частичный балл считается отдельно. Таймаут задачи остаётся в итогах. Несопоставимые пары из-за инфраструктуры явно помечаются. Время охватывает рабочий цикл CLI от её старта до обнаружения результата и освобождения процесса, включая подготовку TUI и `/effort` ChiselCode. Время оценщика вынесено за пределы метрики. Usage берётся из клиентских журналов, поэтому сравнение токенов и инструментов описательное.

Набор синтетический и ограничен Python. Три попытки на задачу показывают вариативность конкретных клиентов и настроек.

## Публикация прогона

После прогона собери отдельную папку отчёта в локальной копии ChiselCode:

```bash
python3 run.py export --out runs/omarchy-01 \
  --dest /path/to/ChiselCode/docs/benchmarks/chiselcode-vs-codex-omarchy-01
```

| Файл или папка | Содержимое |
| --- | --- |
| `README.md` | Отчёт с методикой, результатами и ссылками на журналы |
| `RESULTS.json` | Результаты по попыткам, параметры запуска, версии и SHA-256 набора |
| `tests/` | Точный набор задач, исходных фикстур, публичных и закрытых проверок, оценщик и раннер |
| `logs/preflight/` | Контрольные запуски |
| `logs/rNN/<задача>/<агент>/` | Выгрузки сессий, сырой stdout/stderr Codex или PTY ChiselCode и статус попытки |

Журналы сохраняются после каждой попытки, в том числе при ошибках. Раннер маскирует значения авторизации, личные данные и защищённые поля в публичной копии. Большие журналы сжимаются без обрезки и получают суффикс `.gz`. В отчёте отмечаются недоступные выгрузки. Перед публикацией просмотрите артефакты на наличие чувствительных данных. Файлы авторизации и конфигурация пользовательских профилей в экспорт не входят. После публикации закрытые случаи доступны читателям, поэтому для следующего независимого сравнения желательно обновить их до начала прогона.

## Источники методики

- Формат «инструкция, изолированное окружение, независимые проверки» и понятие попытки описаны в [Harbor](https://docs.harborframework.com/tasks/overview) и применяются в [Terminal-Bench](https://www.tbench.ai/).
- Рекомендации по конкретным критериям, детерминированным проверкам и повторяемому сравнению изложены в [OpenAI Evaluation Best Practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices). Разбор несовпадений условия и проверок есть в [SWE-bench Verified](https://openai.com/index/introducing-swe-bench-verified/).
- Повторные измерения на разных задачах и осторожная интерпретация надёжности описаны в [METR Time Horizon](https://metr.org/blog/2025-03-19-measuring-ai-ability-to-complete-long-tasks/). В этом архиве bootstrap повторно выбирает задачи с сохранением пар и всех повторов каждой задачи.
- Для настроек запуска см. [Codex CLI](https://developers.openai.com/codex/cli/reference) и [ChiselCode CLI и effort](https://github.com/TheAsrada/ChiselCode/blob/main/docs/model-picker.md#глубина-рассуждений). Синтаксис ChiselCode сверялся с релизом 0.6.58 и [актуальными исходниками на момент сборки](https://github.com/TheAsrada/ChiselCode/tree/9880c38facd1fcaba9a036128e4906d6ffac5ee4).
- Для промпта оркестратора использованы рекомендации GPT‑6.2 по явному результату, границам самостоятельных решений и проверке завершения. [OpenAI Using GPT‑6.2](https://developers.openai.com/api/docs/guides/latest-model#prompting-best-practices)
