## Подтверждение действий

По умолчанию запись, редактирование, удаление файлов, запуск shell, Git commit и создание навыков требуют разрешения. Чтение, поиск и просмотр состояния Git проходят без такого вопроса.

| Действие | Проверки и поведение |
| --- | --- |
| `read_file`, `list_dir`, `glob`, `grep` | Проверки путей и исключений проекта |
| `write_file`, `edit_file`, `delete_file`, `apply_patch` | Проверки путей, предпросмотр diff и разрешение |
| `run_shell` | Проверка рабочей папки, правил команды и разрешения |
| `git_commit` | Разрешение на коммит |
| `create_skill` | Разрешение; запись ограничена `skills/user/` |

Manual / Accept edits / Dont ask / Bypass, `--approval` и `--allow` задают поведение подтверждений. Совместимые `--yes` и `autoApprove` выбирают Accept edits и не разрешают shell или Bypass. Доступ к Bypass включается только в пользовательских Settings; выбранный режим и возможность его использовать проверяются раздельно. Для shell сначала проверяется `deniedCommands`, затем `allowedCommands`, затем режим. Все режимы сохраняют deny rules, path/revision checks и ограничения Plan. Без доступного подтверждения требующее его действие не выполняется. [Режимы и приоритеты разрешений](permissions.md).

## Границы файловых инструментов

Пути проверяются относительно корня проекта, в том числе переходы через `..` и существующие симлинки. Учитываются `ignorePatterns`. Перед перезаписью существующий файл должен быть прочитан, а SHA-256 текущего содержимого должен совпадать с observed revision; `edit_file` требует единственного совпадения заменяемого фрагмента. Diff строится до подтверждения и сохраняется после успешного изменения.

Эти проверки не означают, что всё приложение работает в системной песочнице. Настройки, история и навыки штатно хранятся вне проекта.

## Shell работает с вашими правами

После разрешения `run_shell` запускает команду через системный shell. Проверка её рабочей папки **не запрещает** самой команде читать или изменять файлы вне проекта, обращаться к сети или запускать другие процессы.

Консервативный shell analyzer разрешает prefix rules только для простых команд без operators, redirects и expansions. Составные команды требуют отдельного approval; явный `--yes` или `--allow run_shell` остаётся широким разрешением. HostSandboxExecutor сообщает `sandboxed=false`. Не считайте их изоляцией недоверенного кода. Для такой работы используйте отдельное ограниченное окружение и не включайте автоматическое подтверждение без необходимости.

## Ключи, история и внешний API

Plan ограничивает инструменты чтением на уровне ToolExecutor до подготовки и подтверждений. `--yes`, разрешения скилла и текст запроса не включают запись или shell в Plan. Git-чтение отключает optional index locks, fsmonitor hooks, external diff и textconv. Сохранение истории и запросы к выбранному API продолжают работать. Build использует обычные permissions, workspace boundary и approval. [Семантика режимов](agent-modes.md).

- API-ключи сохраняются в `credentials.enc` с AES-256-GCM. Ключ шифрования выводится из локальных параметров пользователя; это не системное хранилище секретов и не защита от атакующего с доступом к вашей учётной записи.
- Сессии сохраняются в JSON и могут содержать сообщения, код, вывод инструментов и diff.
- Содержимое, попавшее в контекст модели, отправляется выбранному провайдеру или вашему совместимому серверу.
- `.env` не входит в стандартный список `ignorePatterns`; добавьте нужные исключения явно. Эти исключения не ограничивают разрешённый shell.

Пути данных и пример конфигурации — в [справке настроек](configuration.md).

## MCP

MCP-инструменты разделяют внешнее чтение, запись и разрушительные действия. Plan допускает только консервативно классифицированное чтение; MCP annotations — подсказки, а не доказательство безопасности. Неизвестный tool и произвольный SQL/RPC требуют подтверждения и не доступны в Plan. Подтверждение и «Всегда разрешать» относятся к конкретному tool; явные запреты проверяются повторно перед исполнением.

Проектные stdio и HTTP-конфигурации не подключаются до явного доверия, привязанного к отпечатку команды, аргументов, endpoint, окружения и остальных настроек. Bypass и repository `allow` не выдают такое доверие. Локальный MCP-процесс запускается без shell с правами пользователя; это доверенный код, не OS sandbox. Его потенциальные записи синхронизируются с локальными изменениями workspace в процессе ChiselCode.

MCP config содержит `secretRef`/`envRef`, а введённые токены используют существующий шифрованный CredentialStorage. Разрешение ссылок находится на границе транспорта. Известные секреты и чувствительные поля редактируются до событий, ошибок, transcript, checkpoints и artifacts. Перенаправления HTTP запрещены. Запросы sampling/elicitation автоматически не исполняются; неподдержанный `input_required` возвращает ошибку, а не фиктивный успех.

При сетевом сбое соединение может переподключиться, но изменяющий вызов не воспроизводится. Если результат изменения неизвестен, он помечается `executionUnknown` и требует проверки внешнего ресурса перед повтором. Ctrl+C передаёт отмену; сервер может уже завершить побочный эффект. [Настройка, доверие и границы MCP](mcp.md).

## Custom Providers

Manifest — данные, а не executable code. Discovery не читает credentials, не создаёт SDK clients, не обращается к сети и не импортирует JS. Secret fields запрещены; используйте env var names и profile.apiKeyRef. Читаются только immediate child directories с regular provider.json до 256 KiB; package/manifest symlinks и junctions отклоняются. Namespaced ID не используется как filesystem path. Duplicate IDs отключают все конфликтующие packages; custom не заменяет built-ins. Remote HTTP может раскрыть ключи и prompts; localhost HTTP разрешён для локальных моделей. Executable custom drivers пока не поддерживаются; в будущем такой driver потребует отдельного trust design и будет trusted user code, даже в child process.

## Публичный Web

`web_search` и `web_fetch` — `external_read` с отдельной network policy. Plan разрешает чтение, но не выдаёт сетевой доступ. По умолчанию нужен approval; Dont Ask отклоняет неподтверждённое, Accept edits не разрешает сеть автоматически. Bypass соблюдает явные deny и отключение Web. Разрешение «на сессию» относится к поиску либо точному hostname и хранится только в памяти; сохранённая история его не восстанавливает.

SSRF protection действует отдельно от permissions. Даже Bypass не разрешает localhost, private/reserved IPv4/IPv6, link-local, metadata, `.local`, credentials в URL, нестандартные protocols или порты. Все DNS answers проверяются; socket открывается к проверенному IP с исходной TLS identity. Redirect проверяется заново; переход на другой домен требует действующего разрешения. Опции отключения SSRF или доступа к localhost в native Web нет. Shell и MCP имеют свои полномочия; Web policy не является OS firewall.

Поиск отправляет выбранному Exa/Brave текст запроса и domain filters; fetch отправляет URL владельцу страницы. Exa работает без отдельного ключа, имеет лимиты и не получает session ID/имя модели. Cookies, login credentials и контекст проекта в fetch автоматически не передаются. URL/query могут содержать данные задачи: не включайте конфиденциальный код в запросы. Optional API-ключ Brave берётся из CredentialStore или environment reference и редактируется до transcript/events/artifacts.

Корпоративная сеть настраивается только пользователем через environment. Proxy-авторизация не передаётся целевому сайту. Дополнительные CA сохраняют проверку цепочки/hostname, mTLS identity ограничивается явно указанными адресами, а сертификаты proxy и origin разделены. В Web proxy CONNECT получает проверенный публичный IP; DNS/redirect/SSRF-защита действует и через proxy. [Настройка и ограничения](network.md).

Веб-страницы и snippets — недоверенные данные. Короткая метка сохраняется в tool result и во всех диапазонах web artifact; model instructions запрещают исполнять внедрённые команды или раскрывать секреты. Это снижает риск prompt injection, но не доказывает безошибочность модели; обычные approvals и workspace policy остаются обязательными. [Настройка и ограничения](web.md).
