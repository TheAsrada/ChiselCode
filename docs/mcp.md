# MCP: внешние инструменты

[Документация](README.md) · [Разрешения](permissions.md) · [CLI](cli.md)

MCP подключает к агенту инструменты других сервисов: поиск в GitHub, запросы к базе данных, работу с мониторингом или браузером. Инструменты проходят через обычные режимы, подтверждения, отмену и историю ChiselCode. Подключать их удобнее в `/mcp`; редактировать JSON для обычной настройки не нужно.

## Добавить удалённый сервер

1. Откройте `/mcp` → **Добавить MCP** → **Вставить URL**.
2. Задайте короткий ID, например `github`, и полный MCP endpoint сервиса. Обычно это HTTPS-адрес с `/mcp`; адрес REST API вместо MCP не подойдёт.
3. Если сервер использует bearer token, откройте поле токена. Ввод скрыт; значение сохранится отдельно от конфигурации.
4. Нажмите **Проверить подключение**. ChiselCode проверит инициализацию, согласует протокол и обнаружит инструменты.
5. В предпросмотре откройте **Обнаруженные инструменты**, посмотрите назначение и классификацию. Выберите правила для чтения, записи, разрушительных и неизвестных действий, затем **Сохранить**.

Для удалённых серверов используется Streamable HTTP. HTTP без TLS разрешён только на loopback (`localhost`, `127.0.0.1`, `::1`). URL с логином, паролем или секретными query-параметрами отклоняется. Перенаправления endpoint запрещены, чтобы учётные данные не уходили на другой адрес.

При ответе сервера «Нужна авторизация» можно сохранить подключение и добавить токен через **Учётные данные**. OAuth-вход через браузер пока не реализован: серверу, поддерживающему только OAuth, потребуется этот будущий способ входа. Попап не выдаёт отсутствие авторизации за успешное подключение.

## Добавить локальный сервер

Выберите **Локальная команда**, введите отдельный исполняемый файл и аргументы в одну строку. Например, официальный filesystem-сервер:

```text
npx -y @modelcontextprotocol/server-filesystem@2026.8.31 /home/me/project
```

На Windows путь с пробелами заключите в кавычки. Для постоянного подключения выбирайте известную версию пакета. ChiselCode сохраняет ваши аргументы и не меняет версии автоматически.

При необходимости укажите рабочую папку. В **Окружении** можно добавить:

| Тип значения | Когда использовать |
| --- | --- |
| Секрет | Ввести API key, пароль или строку подключения; в config остаётся `secretRef` |
| Переменная среды | Прочитать существующую переменную, например `API_TOKEN`; в config остаётся `envRef` |
| Обычное значение | Регион, имя проекта и другие несекретные настройки |

Команда запускается напрямую, без shell-операторов и подстановок. Перед **Проверить подключение** отображается команда; тест действительно запускает её с вашими правами. Stdio-сервер должен писать MCP-сообщения в stdout, а обычные сообщения — в stderr. SDK может запускать кратковременный процесс проверки протокола перед основным процессом.

Проверка черновика не сохраняет конфигурацию или секреты. Закрытие окна завершает тестовое подключение. **Расширенная настройка** принимает строгий объект сервера для раздельных `command`/`args`, HTTP headers, ссылок на секреты и таймаутов.

## Все проекты или один проект

**Для всех проектов** сохраняет сервер в пользовательском `config.json`. **Этот проект** сохраняет его в `.chiselrc`. Пользовательский сервер с тем же ID имеет приоритет: репозиторий не может подменить его endpoint, команду или разрешения.

Сервер из клонированного проекта никогда не запускается автоматически. Откройте его в `/mcp` → **Проверить и доверить**: окно покажет точную команду, рабочую папку, ссылки окружения либо удалённый адрес. Источники окружения, HTTP headers и токена показаны как ссылки, без чтения секретных значений. **Доверить и запустить** разрешает именно эту конфигурацию. Это требуется и для проектного HTTP-сервера, который может запросить ваши секреты.

Доверие хранится в пользовательском `mcp-trust.json`, привязано к SHA-256 конфигурации и корню проекта. Изменение команды, аргументов, папки, окружения, авторизации, правил или других настроек отменяет прежнее доверие. Репозиторий не может назначить себе разрешения `allow`; его явные запреты сохраняются. Bypass не заменяет доверие.

## Разрешения и Plan

Начальные правила мастера и `mcp add`: чтение — **Разрешать**, запись, разрушительные и неизвестные операции — **Спрашивать**. Ручная конфигурация без правил использует **Спрашивать** для всех MCP-категорий.

| Категория | Примеры | Plan |
| --- | --- | --- |
| Внешнее чтение | `github.search_code`, `github.get_issue` | Доступно с разрешением |
| Внешняя запись | `github.create_issue`, `github.comment_issue` | Заблокировано |
| Разрушительные действия | `github.merge_pull_request`, удаление данных | Заблокировано |
| Неизвестные действия | Произвольный SQL, RPC или неоднозначный tool | Заблокировано |

Чтение определяется консервативно по имени, описанию, схеме и MCP annotations. `readOnlyHint` не делает `delete`, `merge` или выполнение произвольного кода безопасным. Неоднозначный `query` считается потенциальной записью. Инструменты выполнения локального кода также запрещены в Plan.

В разделе **Разрешения** задаются категории, а в **Инструменты** → выбранный tool — индивидуальное правило. Любой применимый **Запретить** имеет приоритет. Затем выбирается правило tool, категории, сервера (`permissions.default`) и наконец `ask` по умолчанию.

Подтверждение показывает сервер, действие, ресурс и последствия. **Всегда разрешать этот tool** разрешает только его, сохраняя правила остальных инструментов. Для разрушительных действий этой кнопки нет. Accept edits не разрешает внешнюю запись; Dont ask отклоняет операции, требующие подтверждения. Включённый пользователем Bypass пропускает такие вопросы, сохраняя явные запреты, Plan и доверие проекта.

Локальный MCP-процесс работает с правами пользователя и не является системной песочницей. Разрешения контролируют вызовы агента, но не могут проверить реализацию недоверенного сервера или запретить ему действия во время запуска. Подключайте проверенные серверы; для недоверенного кода используйте отдельное ограниченное окружение.

## Работа в разговоре

Агент видит имена вида `github.search_code`, а исходное имя передаётся соответствующему серверу. MCP-вызов отображается компактно как **GitHub · Search issues**, без JSON-RPC-пакетов. Прогресс появляется в текущей активности, сохраняя ленту без промежуточных уведомлений.

Большие ответы сокращаются в контексте и сохраняются в обычный `tool-result://` artifact. Агент читает нужные строки через `read_tool_result`. Структурированные ответы сохраняются вместе с текстом; изображения и другие бинарные вложения пока представлены описанием типа, без загрузки в контекст.

При большом количестве tools каталог выбирает до 32 MCP-схем по запросу, закреплениям и недавним вызовам, с общим бюджетом 96 KiB на turn. Явный выбор имеет приоритет над закреплениями; локальные инструменты сохраняются. Отдельные MCP-схемы свыше 64 KiB не импортируются и получают запись в диагностике. `discover_mcp_tools` позволяет найти и включить нужные инструменты. Изменения списка на сервере обновляются без перезапуска приложения; изменившееся после подготовки действие требует нового вызова.

Ctrl+C отменяет текущий запрос и передаёт отмену MCP. Другие вкладки и их вызовы продолжают работу. Сервер должен соблюдать отмену протокола; уже совершённые внешние действия не откатываются. Локальные MCP-операции с возможной записью синхронизируются с изменениями общего workspace; удалённая запись не блокирует независимые локальные правки.

## Диагностика и сбои

В `/mcp` откройте сервер → **Диагностика** или **Журнал соединения**. Проверяются конфигурация, executable для локальной команды, запуск, инициализация, протокол, авторизация, tools и время подключения. Ошибка одного сервера оставляет локальные инструменты и остальные подключения доступными.

Переподключение выполняется с ограничением до трёх автоматических попыток и растущей задержкой. Инструмент при этом не вызывается повторно. Если связь оборвалась во время внешнего изменения, сначала проверьте внешний ресурс: действие могло завершиться. **Переподключить** запускает новую явную попытку. **Разорвать соединение** удерживает сервер отключённым до явного подключения; **Отключить** сохраняет этот выбор для следующих запусков.

| Состояние / ошибка | Что сделать |
| --- | --- |
| Нужно доверие | Проверить команду или адрес проекта и выдать доверие в `/mcp` |
| Нужна авторизация | Добавить токен / переменную среды; OAuth-only сервер пока не поддерживается |
| Исполняемый файл не найден | Проверить Node/npx, абсолютный путь, PATH и рабочую папку |
| Ошибка протокола | Указать MCP endpoint; убрать посторонний stdout у локального сервера |
| Сервер завершился | Посмотреть безопасный stderr в диагностике; проверить зависимости сервера |
| Изменился tool | Повторно обнаружить инструменты и отправить новый вызов |
| Невалидная конфигурация | Исправить указанное поле; остальные валидные серверы сохраняют работоспособность |

Журнал ограничен текущим запуском и последними 80 записями. Для защиты от чрезмерных ответов каталог ограничен 1000 tools и 4 MiB, stdio-сообщение — 10 MiB, HTTP-ответ или SSE-поток — 16 MiB. После превышения лимита используйте более узкий запрос; большой корректный результат в пределах лимита сохраняется как artifact. SDK не предоставляет код завершения stdio-процесса через публичный API; диагностика показывает закрытие соединения и доступный stderr. Учётные данные и известные секретные значения редактируются до попадания в ошибки, события, результаты, artifacts и сессии. Для передачи сторонних логов всё равно проверяйте их на чувствительные данные.

## CLI

```bash
chisel mcp
chisel mcp list --json
chisel mcp add github --url https://example.com/mcp --token-ref mcp/github/token
chisel mcp add filesystem --command 'npx -y @modelcontextprotocol/server-filesystem@2026.8.31 /home/me/project' --test
chisel mcp add database --config ./database-server.json --project
chisel mcp info database --json
chisel mcp trust database --fingerprint <проверенный-sha256-из-info>
chisel mcp tools github
chisel mcp doctor
chisel mcp doctor github --json
chisel mcp logs github
chisel mcp disable github
chisel mcp enable github
chisel mcp remove github
```

`--cwd` выбирает проект. `list` и `info` не запускают команды; `tools`, `doctor` и `logs` подключаются только к включённым доверенным серверам. CLI `add` сохраняет конфигурацию; `--test` дополнительно подключается. `--env-ref NAME=ENV_NAME` и `--secret-ref NAME=reference` добавляют ссылки окружения. В CI используйте `envRef`; обычный пользователь вводит секрет в `/mcp`.

В JSON-режиме выводится один объект. Код 0 означает успех, 1 — ошибку команды, 2 у `doctor` — провал проверки или необходимое доверие/авторизацию. Все команды закрывают свои подключения перед завершением.

## Конфигурация и текущие границы

MCP использует версию `mcp.schemaVersion: 1` внутри существующего config v2 или `.chiselrc`. Пример со ссылками и индивидуальными разрешениями: [конфигурация](configuration.md#mcp).

Credentials используют существующее `credentials.enc` и абстракцию `CredentialStorage`; raw tokens не записываются в MCP config. Файл шифруется AES-256-GCM, но пока не заменяет native OS keychain и не защищает от доступа под вашей учётной записью.

Сейчас поддерживаются tools, notifications списка, прогресс и отмена через stdio и Streamable HTTP. Capabilities resources, prompts и tasks обнаруживаются для будущего расширения; их выбор/исполнение, OAuth browser flow, elicitation и MCP Apps ещё не доступны. Legacy SSE-only endpoint не поддерживается. Основа использует официальный [TypeScript SDK](https://github.com/modelcontextprotocol/typescript-sdk), без отдельного JSON-RPC executor.
