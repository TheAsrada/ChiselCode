# Изолированные рабочие копии

[Документация](README.md) · [Интерактивный режим](interactive.md)

Рабочая копия Git позволяет вести задачу в отдельной папке проекта. Можно открыть две копии в разных вкладках и независимо менять один и тот же файл. Исходный проект меняется только после явного применения выбранного результата. Закрытие вкладки, отмена задачи и выход из приложения сохраняют папку и её изменения.

Возможность доступна начиная с [опубликованной версии 0.6.20](https://github.com/TheAsrada/ChiselCode/releases/tag/v0.6.20). Нужны Git 2.39 или новее и обычный репозиторий хотя бы с одним коммитом.

## Создать и открыть

В интерактивном режиме отправьте:

```text
/worktree create Первая задача
/worktree create Вторая задача
/worktree list
/worktree open <ID первой копии>
```

Создание проходит обычное подтверждение изменения Git. Копия начинается с текущего сохранённого коммита исходного проекта; его незакоммиченные изменения не копируются и не изменяются. Для другого локального коммита или ссылки используйте `/worktree create --ref <ссылка> <название>`. Загрузка удалённых коммитов не выполняется.

Команда показывает название, ID, исходный коммит и путь. `open` проверяет копию и открывает новый разговор по её папке. В боковой панели видны название, ID и `Detached HEAD`: копия не создаёт новую ветку. В CLI `open` выводит проверенный путь для обычного запуска:

```bash
chisel --cwd <путь-копии> "Выполни задачу в этой копии"
```

В новой вкладке доступны обычные чтение и правка файлов, Git, shell, анализ кода, настройки и `/btw`. Разговоры и результаты анализа разделены по папкам. Ключи API и глобальные настройки не копируются в репозиторий. Зависимости не устанавливаются автоматически.

## Посмотреть результат и перенести в исходный проект

```text
/worktree status <ID>
/worktree diff <ID>
/worktree apply <ID>
```

Результат сравнивается с исходным коммитом копии. В него входят изменения в новых коммитах, подготовленные к коммиту и незакоммиченные правки, а также допустимые новые файлы. `diff` показывает карточки изменений. `apply` предлагает проверить их и разрешить перенос в записанный исходный проект; выбрать произвольную папку назначения нельзя.

Для одного файла: `/worktree diff <ID> <путь>` и `/worktree apply <ID> <путь>`. Путь после ID передаётся буквально и может содержать пробелы; кавычки не работают как shell-экранирование.

Перенос разрешён, если затронутый файл исходного проекта всё ещё совпадает с исходной версией копии. Если он уже совпадает с результатом, запись не требуется. Если отличается от обеих версий, возникает конфликт **до любых записей**. Подготовленные к коммиту или конфликтующие файлы назначения также блокируют перенос. Остальные изменения проекта сохраняются; его HEAD, ветка и индекс Git не меняются.

После подтверждения файлы и состояние Git проверяются снова. Если они изменились после просмотра, операция останавливается: обновите diff и отправьте команду заново. Исходная рабочая копия после успешного переноса сохраняется.

## Закрыть, вернуться и удалить

Ctrl+W закрывает вкладку, сохраняя копию. Позже откройте её командой `/worktree open <ID>`; после повторного запуска список доступен через `/worktree list`. Неактивная открытая вкладка тоже считается пользователем папки.

Удаление — отдельное действие:

```text
/worktree remove <ID>
```

Изменённые, подготовленные к коммиту, конфликтующие, новые **и игнорируемые** файлы блокируют удаление. Это относится и к `node_modules` или кэшу. Применение результата не делает такую копию автоматически безопасной для удаления. Сначала завершите использующие её вкладки и процессы; лишние файлы удаляйте отдельно, проверив, что они больше не нужны. Команда не имеет режима принудительного удаления или сброса изменений.

Если чистая копия содержит новый коммит, перед удалением он сохраняется во внутренней ссылке `refs/chiselcode/worktrees/<ID>/<OID>`. Это не новая ветка. Ссылка и коммит показаны в результате; они сохраняются после перезапуска и сборки мусора Git. `git show <ссылка>` позволяет прочитать результат, а обычный `git worktree add --detach <новый-путь> <ссылка>` — восстановить папку. Ошибка сохранения коммита блокирует удаление. Чужие рабочие копии и исходный проект показываются только для просмотра.

## Ограничения и восстановление

Перенос поддерживает создание, изменение и удаление обычных текстовых файлов UTF-8 с сохранением байтов и переводов строк. Двоичные файлы, символические ссылки, изменения права исполнения или только режима файла, подмодули и неподдерживаемая кодировка отклоняются. Переименование рассматривается как удаление и добавление; небезопасные или конфликтующие по регистру пути не переносятся. Игнорируемые и запрещённые правилами проекта файлы не читаются ради предпросмотра.

До записи проверяется весь выбранный набор. Неподдерживаемый файл блокирует его целиком; можно явно выбрать поддерживаемый файл отдельно. Пределы: 512000 байтов на файл, 8 МиБ суммарных исходных и результирующих данных, до 200 выбранных файлов. Большой или неизвестный результат не выдаётся за успешно перенесённый.

Пока не поддержаны bare-репозитории, репозитории без коммитов, подмодули, sparse checkout и внешние checkout-фильтры, включая Git LFS. Автоматического merge, stash, reset, commit, установки зависимостей и применения результатов нет. Plan разрешает просмотр, а создание, перенос и удаление требуют Build и действующих разрешений.

Папки и сведения о копиях хранятся в `ChiselCode Home/worktrees`, вне исходного проекта. После аварийного завершения приложение сверяет фактические файлы и Git, но не повторяет создание, перенос или удаление автоматически. Состояние «Нужна проверка» требует ручного изучения результата. При обычной ошибке переноса выполняется попытка отката уже записанных файлов; если появились чужие изменения, они не перезаписываются ради отката, а неполный результат показывается явно. Внезапное выключение между записями не гарантирует атомарный перенос всех файлов.

Рабочая копия даёт файловую изоляцию, а не системную песочницу. Служебные данные Git общие для репозитория; shell работает с правами пользователя, а внешние процессы не подчиняются блокировкам ChiselCode. Shell-вызовы одного репозитория выполняются последовательно, обычные файловые инструменты разных копий могут работать параллельно. Автоматическое делегирование агентам и фоновые задания пока не реализованы.

См. также: [режимы агента](agent-modes.md), [разрешения](permissions.md), [расположение данных](configuration.md).

## Помощники

Помощник с изменениями получает отдельную рабочую копию. Применение доступно после завершения и подтверждённого cleanup; активный writer блокирует перенос. См. [Помощники и делегирование задач](subagents.md).
