# Рабочие копии

[Документация](README.md) · [Интерактивный режим](interactive.md) · [Устройство менеджера](architecture/worktree-manager.md)

Отдельная копия Git позволяет вести независимую задачу в другой папке. Основной проект изменится только после явного переноса результата. Закрытие вкладки сохраняет папку и файлы.

Графический менеджер доступен в [CLI 0.6.40](https://github.com/TheAsrada/ChiselCode/releases/tag/v0.6.40). Версию установленного приложения показывает `chisel --version`. Текстовые команды доступны с [CLI 0.6.20](https://github.com/TheAsrada/ChiselCode/releases/tag/v0.6.20). Для создания копии нужны Git 2.39+ и репозиторий хотя бы с одним коммитом.

## Открыть менеджер и понять текущую папку

Отправьте `/worktree` без аргументов или откройте **Меню → Проект → Рабочие копии**. Название копии в панели контекста ведёт в тот же менеджер. Эти действия не запрашивают ответ модели.

В списке три группы:

| Группа | Что означает |
| --- | --- |
| Основной проект | Исходная папка репозитория; для обычной работы в ней отдельная копия не нужна |
| Копии ChiselCode | Отдельные папки, созданные сервисом; доступны проверенные действия открытия, переноса и удаления |
| Другие копии Git | Папки, созданные вне ChiselCode; менеджер показывает сведения и не управляет их удалением |

Ограничения управления копией не являются общим запретом работы с файлами. В основном проекте действуют обычные разрешения, Plan/Build и проверки путей. Прежняя метка «Внешняя (только просмотр)» больше не используется для объявления исходного проекта запрещённым.

На широком экране сведения выбранной папки видны справа. На узком Enter открывает карточку. Полный путь и ID доступны через «Полный путь и сведения», путь можно скопировать. Неизвестные счётчики не выдаются за чистое состояние. После ошибки обновления прежний снимок отмечается как устаревший; R повторяет чтение.

## Создать и открыть

1. Нажмите **Новая копия** или N в списке.
2. Введите название задачи. Необязательная локальная ссылка по умолчанию — текущий `HEAD` исходного проекта.
3. Перейдите к проверке. Форма показывает исходный проект и выбранную базу; сервис выбирает отдельную папку в `ChiselCode Home/worktrees`.
4. Нажмите **Создать копию** и пройдите обычное подтверждение Git-изменения.
5. Откройте созданную копию. Если разговор по этой папке уже открыт, приложение выбирает его; иначе создаёт отдельную вкладку и сессию.

Копия начинается с сохранённого коммита. Незакоммиченные правки, новые/игнорируемые файлы и установленные зависимости origin не переносятся и не меняются. Создание не скачивает свежую версию GitHub, не делает commit и не устанавливает пакеты. Используется detached HEAD, новая ветка не создаётся.

В открытой копии доступны обычные файловые инструменты, shell, Git, анализ кода, настройки и `/btw`. Разговоры, черновики и LSP разделены по папкам. Для возврата используйте строку основного проекта или действие **Вернуться в основной проект**. Управляемая копия при этом сохраняется.

## Посмотреть и перенести результат

В карточке копии выберите **Посмотреть изменения**. В результат входят новые коммиты относительно базы, staged/unstaged правки и допустимые новые файлы. Штатные карточки diff позволяют раскрыть текст и выбрать переносимые файлы.

Перед переносом явно показаны источник и назначение. Нажмите **Перенести выбранные**, проверьте список и подтвердите действие. Назначение — записанный основной проект; произвольную папку подставить нельзя. Менеджер передаёт отпечатки просмотренных файлов: если результат изменился после просмотра, перенос останавливается с `WORKTREE_STALE`. Обновите сравнение и проверьте его заново.

Backend дополнительно проверяет весь набор, владение, активных writers, допустимость путей и свежесть содержимого перед записью и после подтверждения. Конфликт возникает до любых записей, если файл origin отличается и от базы, и от результата. Staged/conflicted файлы назначения также блокируют перенос. HEAD, ветка и индекс origin не меняются, посторонние файлы сохраняются.

После успеха копия остаётся на диске. Применение результата не делает её автоматически чистой или безопасной для удаления.

## Закрыть вкладку и удалить копию

**Закрыть менеджер** возвращает в текущий чат. **Закрыть вкладку** сохраняет папку, файлы и историю беседы. **Удалить копию** — отдельное действие только для управляемой папки.

В карточке **Вкладки этой папки** показаны связанные разговоры. Выполняющийся запрос нужно сначала остановить или дождаться его завершения. Закрытие вкладки останавливает принадлежащие ей фоновые процессы по действующему lifecycle. Неактивная открытая вкладка тоже удерживает папку.

Удаление блокируют изменения, staged, конфликты, новые и игнорируемые файлы, включая `node_modules` и кэш. Причина показана в карточке. Сначала завершите использующие папку вкладки/задачи и разберите ненужные файлы отдельно. Автоматической очистки, discard или force нет. При настоящей ошибке владения или регистрации требуется проверка, а не обход ограничений.

Финальное подтверждение показывает удаляемую папку; по умолчанию выбрана отмена. Перед удалением сервис снова проверяет состояние. Основной проект менеджер не удаляет.

Если чистая копия содержит новый коммит, перед удалением он сохраняется во внутренней ссылке `refs/chiselcode/worktrees/<ID>/<OID>`. Это не новая ветка. Ссылка и сведения восстановления показаны в результате; они сохраняются после перезапуска и сборки мусора Git. `git show <ссылка>` читает результат, а `git worktree add --detach <новый-путь> <ссылка>` восстанавливает папку. Ошибка сохранения коммита блокирует удаление.

## Клавиатура и узкое окно

- ↑/↓ выбирают копию или действие, Enter открывает карточку/выполняет выбранное действие; Tab переключает зоны и поля.
- N открывает создание, `/` — поиск по названию и пути, R обновляет список или сравнение. Эти буквы не перехватываются при вводе в поле.
- В сравнении ↑/↓ выбирают файл, Space меняет выбор, Enter раскрывает diff. PgUp/PgDn прокручивают сведения.
- Esc возвращает из вложенного экрана, затем закрывает менеджер. Если операция выполняется, Ctrl+C останавливает текущий запрос.
- На слишком маленьком экране mutation не подтверждается: увеличьте окно или вернитесь через Esc.

Черновик чата не заменяется действиями меню. Форма и выбор сохраняются при resize. Refresh не добавляет одинаковые списки в историю модели или ленту чата.

## Текстовые команды и CLI

В одноразовом CLI `/worktree` остаётся текстовым/JSON-списком. Явные subcommands доступны и в интерактивном режиме:

```text
/worktree list
/worktree create Название задачи
/worktree create --ref <локальная-ссылка> Название задачи
/worktree open <ID>
/worktree origin
/worktree status <ID>
/worktree diff <ID>
/worktree apply <ID>
/worktree remove <ID>
```

Для одного файла: `/worktree diff <ID> <путь>` и `/worktree apply <ID> <путь>`. Путь после ID передаётся буквально; кавычки не являются shell-экранированием. CLI `open`/`origin` возвращает проверенный путь для обычного запуска `chisel --cwd <путь>`.

Для новой shell-команды в текущей папке модель должна опускать `targetWorktreeId` и `retryOf`. Нулевой UUID — ошибка аргумента; он не означает текущий проект. Неизвестный ID отличается от настоящего mismatch реестра и не доказывает общий запрет записи.

## Ограничения и восстановление

Перенос поддерживает обычные текстовые файлы UTF-8 с сохранением байтов и переводов строк. Двоичные файлы, symlink, изменения executable/mode, submodules и неподдерживаемая кодировка отклоняются. Переименование — удаление и добавление. Небезопасные или конфликтующие по регистру пути не переносятся; ignored/запрещённые файлы не читаются ради preview.

Проверяется весь выбранный набор; неподдерживаемый файл блокирует его целиком. Пределы: 512000 байтов на файл, 8 МиБ суммарных исходных и результирующих данных, до 200 выбранных файлов. Можно явно выбрать поддерживаемый файл отдельно.

Не поддержаны bare-репозитории, создание копии без первого коммита, submodules, sparse checkout и внешние checkout-фильтры, включая Git LFS. Нет автоматических merge, stash, reset, commit, установки зависимостей и переноса. Plan допускает просмотр, изменения требуют Build и действующих разрешений.

После аварии приложение сверяет Git и сохранённые данные, но не повторяет mutation автоматически. «Нужна проверка» требует изучения состояния. При обычной ошибке переноса выполняется попытка отката своих записей; чужие последующие изменения не перезаписываются ради отката. Внезапное выключение между записями не гарантирует атомарность всех файлов.

Копия изолирует файлы, а не систему. Git metadata общие; shell работает с правами пользователя. Внешние процессы не подчиняются блокировкам ChiselCode. Shell одного репозитория выполняется последовательно, независимые файловые инструменты разных копий могут идти параллельно.

Помощники и фоновые задачи могут использовать отдельные копии. Активный writer или неподтверждённый cleanup блокирует apply/remove. См. [помощники](subagents.md), [фоновые задачи](background-tasks.md#выбрать-папку), [разрешения](permissions.md), [расположение данных](configuration.md).
